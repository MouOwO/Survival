# 决策

1. 采用共享紫色弹窗 chrome，在各业务窗口复用；不跨 Panorama XML context 强移面板。
2. 最新紧凑单元要求优先于参考图的大圆形奖章：图标、可选数量/进度、名称，详情放 tooltip。
3. 存档试用 1280×800；内容从 y=132 开始，真实全部分类保留并滚动。称号使用独立宽度适配。
4. 生存商店试用 1040×760、4 列图标；商城试用 1280×800、紧凑产品单元。尺寸需截图证据确认。
5. 现有 ModalShell / UILayers 负责输入屏障、缩放、ESC 与生命周期；新共享壳负责外观、导航与货币。
6. 生存商店显示本局金币/木材，商城显示实际账户货币，抽奖券来自真实快照；参考图的示例数字不进入游戏。
7. 排行榜无实际业务，保留未开放提示，不拿塔品阶冒充榜单。
8. 内容自适应不改变已确认结构：生存商店不足一行不保留多余空槽；存档7列、宝物8列、商城5列，称号字艺单元独立宽度。
9. 仅名称/数量进入紧凑单元，条件、成本、效果完整保留在测量 tooltip，购买与领取仍沿用真实服务端验证。商城使用窗口内浮层，其他组件沿各自真实结构适配。
10. 样例浏览器组装和真实游戏图分别标记；同一案例出现在多个QA报告时不重复累加为独立覆盖。
11. 共享API用子面板生命周期标记判断原生layout是否失效，保留同一有效context中的复用；不是每次include都重置ESC/输入状态。
12. 热重载已完成难度的对局仍可能留下旧弹窗的native visible值，渲染时镜像真实状态清除可见性；不代替玩家选择模式或难度。
13. 原生nowrap标签不能只依靠固定宽度的text-align；商品名称使用受max-width约束的自身文本盒并水平居中，C11实际坐标确认。
14. 普通菜单导航逐层调用既有CloseTop，收起详情和父页；遇拒绝关闭或游戏选择层立即停止，不改mandatory/pending原有逻辑。
15. 原生样式有旧min-height/transform约束时逐项清除，browser边界检查不能代替实际字号与裁切核对。冷缓存空白单独留证，不作为页面完成。
16. 生存商店四/五/六列使用同状态真实组件比较。六列在720p把两件熔火商品的关键等级截成相同名称；五列没有降低实际六件其他商品的行数。保留四列，提高密度仍需保留名称辨识度。
17. 商城详情采用窗口内独立浮层，避免原生商品单元裁切；其生命周期仍归原商品，保留原操作和重开单元身份。原生窗口也会裁切浮层，屏幕内几何正确不代表窗口内正确，必须另验最右列和最下行。
18. 抽奖品质、已有数量、时长和重复转化只使用已知真实字段，移入悬停详情；未知字段不伪造永久、零库存或兑换比例。积分单位与数字连写，避免共用效果formatter拆行。
19. 可滚正文必须接收真实鼠标滚轮；直接调用ScrollToBottom和浏览器viewport几何通过都不足以证明原生输入通过。商城A18仅开启正文命中，实际滚轮前后图证实末行可读。
20. 精简不会删除原记录范围、更新日期或奖励说明。保留原history/update脚注，Purple上下文沿共享窗口底部位置；没有日期时使用原controller提示。未获真实奖励的单件详情只标组件样例验证。
21. 最终检查点须同时匹配当前源码、Content输入及编译产物。best_final_compact_purple_c19是最终70份配对；早期混版、失败组或C18历史版不能仅凭时间较新替代它。

## C25最新独立生存商店取舍

最新用户要求覆盖旧公共外框和图标下名称设计：本店只显示图标，原生标题恒定生存商店，三等宽页签、红色选中与购买按钮按第二张参考保留；底材改紫。商品少时留白保留固定比例，不捏造商品。双币/长效果/知识书自动购买按原功能延展详情。

原生父范围外的负坐标尖角会裁切，padding也改变装饰原点；采用透明370外层+左22空间+348不透明内框，动作属于内框，尖角和角装饰属于无padding外层。这是实际引擎兼容修正，不能以浏览器通过代替原生通过。公共商城不改此定位策略。最终选C25，C22失败与C24标题偏差保留。
