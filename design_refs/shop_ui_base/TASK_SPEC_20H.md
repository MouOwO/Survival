# 全项目UI视觉迭代任务：20小时预算

## 一、目标与边界

在现有Dota 2游廊项目中，持续优化主界面、建造/训练队列、存档及其他已接入窗口，使整体呈现清爽、细腻、低饱和、易读的视觉效果。窗口的留白、浅底、层次与操作反馈借鉴原神的舒适感；单位、装备、伐木工头像和技能的视觉识别更贴近Dota 2。沿用项目云海青玉风格，不照搬原神角色、徽章或图标。

20小时是工作预算，不是运行时长保证。直接实施可逆的UI调整，每轮无需等待用户回复“继续”。围绕证据迭代，达到目标并完成检查可以提前整理交付；不能空等或反复改同一个参数凑时间。遇到阻塞先记录原因，继续其他独立任务；全部完成后统一汇报。

不改变地图地貌、模型、战斗数值、存档效果、工人生产与成本、解锁条件、取消队列退款规则、商品和支付逻辑。允许为视觉结构调整UI节点，但复用现有数据与事件。缺少真实数据时使用明确标记的预览样例，不把样例写进生产配置。

## 三、先完成基线与公共视觉规范

1. 定位主界面、训练队列、存档、抽奖、奖池详情/记录、商城、每日奖励、难度选择、tooltip与提示层的文件和资源引用。
2. 保存当前工作区状态，保护用户未提交改动。检查游戏启动、UI重载、截图及预览能力。
3. 每个实际存在的界面先保存默认、悬停、选中/禁用等基线；缺少入口或参考的界面记录缺口，避免自行构造新业务。
4. 建立UI_TOKEN表：背景透明度、青玉色、象牙色、金色选中、边缘厚度、文字色/字号、阴影、内边距、按钮尺寸与动效时间。
5. 区分两个场景：战斗HUD需要透明、紧凑、让出战场；弹窗需要浅底、明确层级与舒适留白。不能给整个战斗画面铺商城的大块背景。
6. 同一角色的按钮、tab、tooltip、关闭叉号共享组件；物品卡、记录行与工人选项按内容需要采用不同尺寸，不能为了复用挤压信息。

## 四、主界面视觉任务

- 左上入口组：保持已有入口及官方返回/退出行为。图标尺寸、光学重量、间距与反馈统一；保留已有必要的小文字标签，不突然改成一排难辨认图标。
- 背景：避免突兀的不透明黑底。必要时仅在控件后添加局部透明渐变衬底，边缘渐淡。
- 右上资源：金币、木材、人口使用图标+数字；人口保留当前/上限。金币等不挪到装备栏上方，不烘焙进贴图。
- 波次和倒计时：层次清楚，不能与资源、导航或战场主体重叠。
- 底部HUD：允许细化底图、边缘、字体、图标和反馈，保留既定结构。人物/建筑面板位置稳定；名字在scene panel上方；六属性竖排图标+数字，不增加属性文字标签。技能槽与物品槽保持正方形，技能与血蓝条区域支持扩展；不再挤窄技能、不移动人物面板。英雄和建筑两种选择状态都要测试。
- 小地图、怪物数量、选中单位与各入口衔接紧凑，不盖住战场重要内容。

## 五、重点重做建造/伐木工训练队列

### 当前问题

最新截图中，HUD上方“伐木工训练”是一个高而密集的深色面板，标题、说明、空闲状态、独立长进度条、空队列格子、4个等级块和底部说明同时显示。信息被切成许多小框，等级、名额、木材成本和操作文字重复堆叠，观感笨重。

### 目标结构

提供至少2个可运行候选：A为紧凑双行面板，B为横向训练工具条+独立紧凑队列。两者用同一数据与事件；对照实际战场截图选择更好方案，不把两套同时加入主界面。

- 面板锚定现有底部HUD附近，训练面板打开不会推挤HUD。选中建筑与英雄切换时按现有显示规则工作。
- 训练选项：每种可生产单位是一个小方形头像按钮。图标优先用项目可用的Dota 2单位头像/高质量资源。不要用emoji、统一斧头替代全部单位，也不要拉伸低清缩略图充当高质量素材。
- 图标下保持成本可见，用金币/木材图标+数字表示；多种成本时按现有配置排列。等级/类型小标记与名额计数保持清楚；名字、产出效果、解锁条件和不足原因放tooltip。
- 沿用配置支持多种伐木工和等级，不能硬编码只有截图中的LV1–LV4。增加类型时可按项目现有方式滚动或折行，保持最小点击面积与成本可读，不无止境缩小头像。
- 正在建造项：突出一个头像，进度用头像上的克制覆盖/底部细进度表示，可加现有剩余时间。删除截图中与头像脱离的粗长空进度条。
- 等待项：一排更小头像，按真实顺序显示；当前正在建造与等待项有明显但低调区别。数量超过空间时按已有上限显示滚动或“+N”并能访问具体项目，不能悄悄截掉等待项。
- 队列为空时收起无用空槽，显示轻量空闲状态；不要一直显示6个点状占位格。队列上限和计数含义读取现有逻辑，不能凭截图认定上限为6或重新定义计数。
- 取消：鼠标悬停到具体队列项时显示小叉号和轻微红色反馈，tooltip说明“取消此项”。叉号具有足够点击区域且不遮住进度/数量。取消按钮命中后不能同时触发加入队列、选中或其他父节点事件。
- 正在建造项能否取消、排队项能否取消、退款和队列顺序完全复用原逻辑；没有取消全部功能就不新加“一键取消全部”。已有“满额后显示后续等级”等行为继续保留。
- 锁定、资源不足、人口不足、数量上限、队列已满应有统一的禁用表现与具体tooltip，不依赖一段永久底部小字解释所有状态。

### 尺寸与信息约束

以完整战斗画面判断大小。普通4个选项且队列空闲的状态，目标高度约为当前面板的55%–70%；宽度先接近当前宽度，小幅调整以保证清晰可点。此比例是候选目标，不是硬性压缩要求。测试1280×720时，如果成本、名额或取消区挤在一起，先重新排信息而非继续缩小文字。

至少提供：空队列；单项建造；多项等待；满队列；不同单位类型；锁定/资源或人口不足；取消中间项；取消当前项（仅已有逻辑允许时）；生产完成更新；英雄/建筑切换。检查状态同步，不改生产规则。

## 六、存档及其他窗口

存档优先级仅次于主界面/队列：保留弹窗、外部透明遮罩、右上叉号、左侧分类toggle、右侧多单元、筛选按钮和滚动。左侧底图上下连续，选中光晕独立且金线下对齐。条目有真实图标、名称、右上当前/目标进度、已解锁/未解锁状态；效果与解锁条件继续放tooltip，不增设巨大的详情列。长名称、进度变化与空分类也要测试。

将确认后的窗口边缘、标题区、导航、tab、按钮、tooltip、奖励单元逐步复用到已存在的奖池详情/抽奖记录、每日奖励等。大小按各窗口需求，层次与材质保持一致；背景题材可以不同。每日奖励继续保留通行证每周最后一天的高级装备规则。

难度选择按已确认结构处理：无关闭按钮，保留需要的滑动条，不加第二个类似进度条的装饰条，长而低的难度按钮。BOSS提示保持渐淡透明黑底。商城保留已有布局、悬停效果描述和购买流程，主要用于公共组件回归，而非重新开发支付。

## 七、20小时预算分配与候选实验

| 阶段预算 | 工作 | 主要证据 |
|---|---|---|
| 0–2小时 | 项目盘点、实际截图、偏差清单、公共视觉规范 | 文件路径表、基线、token表 |
| 2–5小时 | 主界面入口、资源、HUD表面与图标 | 英雄/建筑全图与局部、候选对比 |
| 5–9小时 | 建造/训练队列两种结构及细化 | 两种候选、队列全状态、操作检查 |
| 9–13小时 | 存档窗口、条目、筛选与tooltip | 默认/选中/锁定、长文本与滚动 |
| 13–16小时 | 抽奖窗口、详情/记录、每日奖励公共组件 | 真实存在的页面与状态截图 |
| 16–18小时 | 图标一体化、窗口与商城复用回归 | 资源映射表、共享样式和回归截图 |
| 18–20小时 | 分辨率、完整组装、最佳版与交付整理 | 最终对比、接入说明、未完成项 |

计划24–36个有明确目的的候选实验，按证据调整数量。这是实验覆盖计划，不是重复保存图片的硬指标。结构关键处至少比较2种方案；细节每轮改1–3个变量。主界面、队列和存档优先，其他界面缺少入口或参考时继续能做的独立任务。

## 八、每轮证据与选优

每轮必须查看实际截图并写明：哪个位置不舒服、假设原因、准备改什么、结果是否更好、是否引入代价。不能只说“更精致”“更高级”。比较原基线、当前最佳与本轮候选；版本保存为v001A、v001B等，BEST_VERSION记录保留版本。

比较依据：整体风格一致、信息可读、图标辨识、衔接自然、战场可见、状态反馈、组件复用。主观评分只用于辅助选择，不能自评95分就宣称用户满意。未改善则回退候选，不能叠加更多阴影和金边掩盖问题。连续3个候选无明显收益时，冻结该区域，转到下一独立问题。

每组至少保存默认/悬停等同状态截图与100%局部。截图比较应使用同分辨率、相同数据、相同选中单位/建筑与队列状态；动态战场比较只看UI裁切区，不拿英雄移动或场景光照差异评判UI颜色。

维护Plan.md、Progress.md、Decisions.md、BEST_VERSION.json和资源引用表。文件名/版本/尺寸可追踪，优先在真实UI实现中改公共样式。每组留可恢复检查点，避免中断后从头来一遍。

## 九、验证与最终交付

验证1280×720、1920×1080、2560×1440、2560×1080；检查主界面与队列可见、HUD扩展、窗口边界、长文本、tab/tooltip、按钮点击、取消事件、滚动、透明边缘和光晕裁切。新增纯装饰层不接收鼠标事件；不使用无限闪烁、连续大范围动画或高频网络轮询维持装饰。

Panorama不是浏览器CSS引擎。使用项目已有支持的布局/样式，必要时将可复用阴影/渐变做成独立贴图；不要照搬未验证的filter/backdrop-filter等。能运行游戏时用实际游戏截图验收；无法进入游戏时继续组件和替代预览，但明确标记“尚未游戏验证”，不能编造通过构建、截图或交互的结果。

最终交付最佳版本：主要界面实际全图、关键局部与前后对比、队列状态图/可获取录屏、透明组件和源文件、尺寸/锚点/层级/缩放表、项目资源引用、修改文件列表与回滚/验证步骤。保留已尝试候选及选择原因，并列出仍需用户审美确认或游戏验证的内容。预览必须来自真实组件组装，不能用一张生成效果图冒充导入完成。

如果预算或会话中断，保存当前最佳、剩余问题与下一条实际命令。开始时直接读图并落实第一轮，不停在分析和计划上。
