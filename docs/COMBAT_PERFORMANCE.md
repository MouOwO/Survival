服务器侧计算停顿已被日志证实。第 15 波之后开波时仍有上一波怪物存活；第 17 波起原生 NPC 也出现 10 ms 以上的 Think 警告。游戏模式 Think 与原生 NPC Think 都应继续测量。该表只统计引擎输出的慢调用，不能当作全部回调的平均耗时、完整服务器 tick 或 FPS；33.33 ms 是对比阈值，没有据此断言实测服务器 tickrate。第 21 波观察时长更短，不直接比较警告总数。

代码审计另外确认：`combat/damage_transaction_repository.lua` 在 `create` 时保留记录，`consume_pending` 只移除待消费队列项；`remove` 没有生产调用，记录仅在初始化时整体清空。对真实模块的离线模拟中，已成功消费的 10,000 / 30,000 / 60,000 条记录仍全部保留；垃圾回收后相对初始 Lua 堆增加 5,792.0 / 17,146.0 / 34,304.9 KiB（Lua 5.4.5）。这是确定的无界记录保留路径；未测量该局真实记录数及 GC 耗时，不能把它直接定为第十五波卡顿的主因。此轮保留伤害事务行为，只添加检测。

日志没有 Lua 堆栈错误，也没有 `[CombatDamage]` 每次伤害刷屏。两条粒子/材质资源缺失发生在地图加载时，日志未记录攻击期间的粒子数量、GPU 时间或客户端帧时间。`visuals=0` 只代表 `monster_visual_service` 的状态表，不能解释为没有模型、饰品或塔特效。日志中的 Lua 堆会下降，单凭其波次快照也不能证明整局内存单调泄漏。

下次在同一镜头、同样的塔和怪物数量下，分别在战前、Boss 被集火时、战后执行：

```text
survival_perf_capture 15
script_reload_code tests/manual_boss_performance
```

第一个命令使用已有调度器分析器输出各任务时钟耗时。第二个工具只在 Workshop Tools 的服务器中显式执行，记录 15 秒，结束后恢复包装的函数；不生成/移动/攻击单位，不改属性、档案或特效。需要提前结束时执行 `require("tests/manual_boss_performance").stop()`（通过项目 Lua 控制台工具）。不要同时运行旧的 `manual_combat_performance`。新工具没有加入游戏启动链。

`[BOSS_PERF]` 输出包含开始/结束时的波次、难度、调度任务数、保留伤害记录数、Lua 堆，以及攻击/技能/索敌/怪物 AI/血条回调和事件总线的时钟耗时。粒子方法可写时还输出创建路径及创建/销毁/释放调用数；引擎拒绝包装的方法会明确出现在 `unavailable_hooks`。事件和粒子路径各最多保留 64 项加一个溢出桶，输出只列最多 20 项。采样有观测开销，嵌套回调的时间互相包含，不能相加；`os_clock` 或 `engine_Time` 不代表 GPU 时间，也不保证覆盖引擎全部计算。释放粒子句柄后原生特效仍可能存活，API 计数不能当作在渲染粒子数。

要排除特效，还需在实际卡顿场景同时采集客户端帧时间与 GPU 时间，并核实当前引擎的粒子显示开关后做短时开/关/恢复对照。保留服务器计算和镜头，检查关闭粒子时客户端是否明显改善、服务器 Think 是否仍超时。当前未执行该对照，也未确认用户所说的“撕裂”属于显示同步撕裂还是运动跳帧。

## 2026-09-24：已确认的开销与修改

用户反馈约 7 个以上伐木工、4 个以上防御塔时出现卡顿，尚未对照全部停止采木后的表现。以下结论来自代码审计和确定性测试；不能据此声称已测得 FPS 提升或排除 GPU、内存、地图资源开销。

| 路径 | 已确认的问题 | 修改 |
| --- | --- | --- |
| 树攻击记录 | 每棵树收到全局攻击记录销毁事件，原清理遍历全部待处理攻击 | 仅观察过该攻击者的树处理；按攻击者/目标索引定位队列，销毁用队列 token 清理，校验对象身份防止 entindex 复用 |
| 防御塔选敌 | 稳定状态仍反复写入原生索敌设置；攻击练功目标时重复范围扫描 | 设置按状态变化写入；目标优先级在原有 0.25 秒巡检更新，目标死亡仍立即换敌 |
| 和平采木收益 | 每次命中分别找城墙并枚举场上所有 creature | 同一模拟帧复用攻击目标快照，每位玩家分别缓存其城墙；下一帧重新读取 |
| 血条 | 每个单位每 0.1 秒重复投影和发布相同数值 | 保留采样响应速度，数值未变直接返回；隐藏/移除通知只发一次，传输未就绪可重试 |
| 技能/研究 UI | 每次资源改变立即遍历同队单位/玩家并重建完整视图 | 按资源所有者合并到首条事件后 0.1 秒；持续采木不会把截止时间不断推后 |
| 商店 | 每次资源改变重设 0.05 秒期限，密集事件可能始终不能发布 | 首条事件固定期限，后续只记最新原因；资源变化仅更新已打开的对应玩家商店 |
| HUD 快照 | 每 0.25 秒空闲轮询 dirty 标志 | 有 dirty 才排单次任务；先取出批次，再发布，发布期间的新 dirty 留给下批 |
| 建筑属性刷新 | 原生移除未发销毁事件时，缓存留有失效实体，每秒属性成长会重复报错 | 发布前验证实体；刷新时通过缓存索引清理失效项，扫描恢复先验证再读原生方法 |

钱包加减、购买校验、奖励结算仍同步执行。合并的是显示刷新；回调读取最新钱包，不使用首条事件的旧金额。建筑/技能结构变化、科技等级团队传播仍即时处理。树木布局、允许英雄和伐木工采木、防御塔不得攻击树木及不得播放攻击动作的限制保留。

没有给每个单位新增全局攻击/受击监听。血条 0.1 秒采样和塔 0.25 秒目标检查仍保留：原生受伤/目标可见性等变化并非都由项目事件总线派发，完全移除这些检查会漏更新。

## 测试范围

- 100 棵模拟树收到 100 次无关战斗记录销毁：不进入树证据队列清理；相关树只清自己的队列。
- 200 次同帧采木：仍精确结算 200 次；共享 1 次全场枚举，两位玩家分别查询城墙（共 2 次）。
- 200 个稳定模拟单位、100 次血条轮询：初始发布 200 次，后续重复发布 0 次；伤害、治疗、最大生命、缩放和生死变化下一次采样仍发布。
- 资源 UI 测试覆盖最新钱包、同队不同玩家隔离、连续事件不延期、单位销毁、旧局回调取消、商店关闭、HUD 重入 dirty 不丢失。
- 禁树、攻击怪物、击杀换敌、转职失败不刷新与地面寻路策略保留相应回归。
- 1000 次取消起手不会无限积累无编号攻击记录；当前队列只保留 3 秒有效窗口，过期可释放。失效建筑清理测试覆盖原生移除、迟到回调和索引复用，存活建筑的成长数值不变。

详细测试输出与实机状态记录见 [验证记录](ai/validation/20260924/combat_performance.json)。以上是模拟工作量，不是实际帧时间或当前游戏中的单位数量。

## 树木出血：待实机确认

当前资源树是 `enemy_tree` / `npc_dota_creature`，使用原生 `mango_tree` 模型。KV 历史没有被移除的禁血字段；代码里的命中音效是 `Hero_Tiny_Tree.Impact`，已有按树限流。没有发现项目主动为每次采木创建血液粒子。

本地原生资源/API 审计尚未找到可证实有效的单实体禁血接口。没有添加猜测的 `BloodColor` 字段，没有把树改成建筑/假人，也没有用全局关血掩盖问题。当前不把血效标为修复，更不把它直接视为卡顿主因。

本轮已在真实 `enemy_tree` 测试实体上执行只读探针：`SetBloodColor`、`GetBloodColor`、`SetBloodType`、`GetBloodType`、`SetSuppressDamageEffects` 等检查接口均不可用。只证明这些接口未暴露，不能据此断言引擎没有其他实现途径。

只读接口检查（Workshop 服务器控制台）：

```text
script_reload_code tests/manual_tree_impact_api_probe
```

如果接口仍不存在，下一步应在隔离测试树上对照现有模型、历史 treant 模型和原生假人的命中特效，确认模型表面与原生单位类型各自的影响，再选择局部修复。

## 实机对照方法

新开测试局以加载这些 Lua 改动。在相同镜头、相同单位数量下对照正常采木与全部停止采木，分别观察实际帧时间。服务器控制台可执行：

```text
script_reload_code tests/manual_combat_performance
```

该工具仅显式执行时启用，默认记录 15 秒；完成后恢复被包装的 Lua 函数并一次性输出 `[COMBAT_PERF]` 汇总。不生成/移动/攻击单位，不改档案。重复执行不会叠加捕获。暂停期间 Think 可能推迟执行，恢复后会结束；退出旧服务器也会卸载工具。

输出包含调度器任务数、树清理/塔巡检/伐木工/血条回调次数、最频繁的事件和请求。若引擎允许读取，则输出 Lua 堆大小；这不是进程 RAM 或显存，工具也不强制垃圾回收。计数工具本身有少量观测开销，不能把它的统计当作 GPU 时间。

本轮实机隔离塔测试通过：攻击怪物、丢失攻击指令后的恢复、击杀换敌、回到 idle，树攻击起手次数为 0，测试结束残留句柄为 0。当前新地图的 395 个落点、272 条实际 marker 路径全部通过。未复现完整的 7+ 伐木工/4+ 塔负载，未测前后帧时间；建筑缓存补丁已通过本地生命周期回归，补丁后的实机重测尚未完成。

同时可用客户端已有 `survival_tooltip_perf` 查看技能 UI 绑定；说明见 [技能 UI 性能记录](TOOLTIP_PERFORMANCE.md)。若脚本计数下降后仍卡顿，再结合相同场景的帧时间、Dota 驻留内存、显存和磁盘换页排查。

## 后续关注点

- 真实属性成长可能继续触发数值界面更新，不能用不刷新来隐藏已经变化的攻击力。
