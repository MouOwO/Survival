## 玩家界面与付费

生产版不初始化真实现金支付控制器；Lua服务端同时拒绝现金下单、查询、撤销、付款码、付款外链和月卡现金开通，延迟HTTP/档案刷新回调也重新检查策略。缺失或旧版支付API默认关闭。显式development与Tools模式才能做开发支付回归；客户端标记不能开启生产服务端支付。

G币与积分钱包消费继续走既有原子扣款、发货接口。已有月卡权益和签到保留，不新增未经定义的月卡钱包SKU。界面隐藏充值加号、现金开通及人民币价格文案。

这是关闭本次生产客户端真实付费能力，不是通过替换币种名称规避授权。历史金融字段、真实历史订单单位及开发支付测试不伪造；不能声称上传字节中所有人民币字符串已被抹除。现网付款后台仍在运行，本轮没有停止它或更改现有订单。

## 四账号准入

游戏配置 `scripts/vscripts/config/test_access.lua` 在开发目录默认 `enabled=false`。受限测试候选必须启用并填写四个真实、互异SteamID64。服务端从PlayerResource取得身份，不信任客户端payload；连接、角色、档案、UI请求、内部奖励请求和异步回调均复查。身份尚未就绪时不获取数据、不允许操作；明确非名单后断开连接。

后台可通过独立测试服务的 `SURVIVAL_TEST_STEAM_IDS64` 环境变量启用同样四账号限制。非空配置必须准确四项，错误时拒绝启动。该门禁补充既有可信游戏服认证，不是Steam身份证明，也不绑定四台物理电脑。未在现网启用。

交接命令和保护规则见 [workshop_test_handoff.md](workshop_test_handoff.md)。工具默认只校验；明确apply才新建独立addon，不覆盖开发用survival、不自动上传，且拒绝未配置名单的当前候选。

## 云端存档缺口

现网存档与付款服务只读健康核对通过，存档已有4个Lua worker和有界并发HTTP处理，不需要为四台电脑建立四个服务。

但运行规则仍以 `http://127.0.0.1:8765` 为存档地址，实际公网代理只有付款服务，没有存档HTTPS入口。Valve托管服务器无法通过这个回环地址连接我们的ECS。不能为了打通而把后台共享令牌放进客户端分发的Lua。

最小测试部署应使用独立HTTPS入口、隔离数据库/凭据、四账号启动前验证，不启用真实付款。自控游戏host可从私有服务器配置注入令牌；Valve托管需要确定工坊ID后完成受控专服认证引导，不能采用公开匿名登记即信任的方案。本轮只完成本地门禁代码及部署方案，没有新增公网监听、数据库迁移、服务重启或云端发布。

现网版本、指纹、完整复现命令与已知旧测试问题记录在 `validation/20261021/four_client_backend_preflight.json`。普通抽奖券的实际正式玩法产出尚未确认，后续实机验收需要覆盖。
