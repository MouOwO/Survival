# survival_c6 近景性能优化，2026-09-19

已完成地图优化、编译和游戏内验收。保留当前手动保存的地形；没有重新生成地面、涂色或寻路。普通空地近景约 60 FPS。400 只基础怪物集中围攻同一目标仍约 12 FPS，原生移动处理是剩余主要瓶颈，不能将这版称为“400 只同屏流畅”。

## 实际修改

- 292 处 `ivy_128a` 替换为 Valve VPK 中的 `classical_ivy002`、`classical_ivy004`，各 146 处。按原模型局部包围盒匹配位置、三轴尺寸与旋转，保持原有遮盖范围。两者使用原生常春藤材质。
- 这部分实例累计三角形由 **608,528 降到 38,544，减少 569,984（93.7%）**。这是藤蔓的网格预算，不是全图面数或逐帧可见面数。
- 3,666 处低矮草丛、灌木、花草及藤蔓停止投射动态阴影。树木、岩壁和建筑主体阴影保留；没有更改全局画质、碰撞或植被远处淡出距离。
- 47 个斧王、47 个石头人比例展示模型设为 `editorOnly`，在 Hammer 保留，在游戏编译中排除。真实练功房生成点保留。
- `wall_engagement_slots.lua`：同一堵墙同一服务器帧共享等待队列清理；FIFO 排名在成员不变时复用，新成员直接追加，移除后重建。前排 4 个位置每次仍检查死亡。
- `modifier_enemy_wall_ai.lua`：读取引擎强制目标，避免重复写入；已有追击不重复下达相同攻击指令。空闲恢复、导航变化和更换目标仍会下达指令。未改变出怪数量、伤害、攻击频率、碰撞规则或 AI 的 0.5 秒检查间隔。

## 实际怪物压力与限制

测试机：i5-14600KF、GTX 1050 Ti 4 GB，DX11，1600×900，近景镜头距离 1800，原有垂直同步设置保留。使用基础 `npc_survival_wave_monster`、真实 `modifier_enemy_wall_ai`、不可移动的大血量测试目标，正常时间速度运行。不是静态展示模型。

分四片空地的 100、200、400 只测试均完成；最后一轮活体和 AI 数分别保持 100、200、400，采样窗口有 38、137、336 只发生明显移动。所有测试单位均由专用脚本清理。该测试覆盖基础移动与攻击，不包含正式波次的全部碰撞半径调整、附加装备、Boss 技能、炮台弹幕或联网压力，不能据此推算最终玩法容量。

普通空地优化后采样 **59.969 FPS / 16.675 ms**。同一近景的部分 GPU 项目，当前轮优化前后分别为：阴影 3.720→3.505 ms，反射 2.628→2.337 ms，GBuffers 2.856→2.703 ms。这些局部数据和前后截图支持负担有所降低，但前测波动较大、60 帧又可能受同步限制，不宣称整体 FPS 提升比例。

400 只集中到同一目标时，最终有效采样 **11.757 FPS / 85.059 ms**，服务器 BeginSimulate 约 **55.998 ms**。加入攻击指令缓存前的对应诊断为 11.645 FPS / 85.874 ms；两个区间波动很大，不能将其差额视为可靠增益。VProf 明确显示 `CDOTABehaviorMoveTo::Update` 是主要热点；缓存没有解决原生拥堵移动的主要成本。

后续若要求大量怪物持续挤在单口，需单独设计等待/集结机制和局部拥堵控制，并与攻击规则一起测试。这会涉及战斗行为，不能靠继续删掉近景植被解决。当前版没有偷偷限怪或关闭怪物碰撞。

当前引擎 Release 统计的 GPU Frame 显示 NaN，实时三角形计数显示 0，这两项不用于结论。`opt_stress_400_cluster.png` 早期截图实际仍是分区测试阶段；有效集中测试证据为 `cluster_final.png` 和 `cluster_final.log`。曾受原生 `script` 命令不存在、热重载及测试局结束影响的过程采样已排除。
