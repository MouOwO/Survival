## 证据和归因边界

- `game/dota/console.log`：23:35:15 记录体验物品生成，23:35:31 最后记录 Breakpad；存在物品 SummaryDescription 缺失提示。缺失文案本身不能证明闪退原因。
- `E:/steam/dumps/crash_dota2.exe_20260926233531_1.dmp` 与退出时间吻合。异常为 `0xc0000005`，执行地址为 `0x0`，栈顶代码指针候选为 `server.dll+0x2473f64`。这是引擎原生访问异常，不能等同于已定位到某行 Lua。工具仅扫描栈内候选地址，没有完整展开/符号化调用栈；原始元数据在 `output/title_removal_20260926/crash_metadata.json`。
- 物品使用路径在 OnSpellStart 内同步进入清理，调用持有者 RemoveItem，并可能继续 UTIL_Remove 当前物品。当前施法对象在引擎尚未完成回调时被销毁，是与“点击使用即退出”吻合的高风险路径。它是主要嫌疑，当前转储不足以证明唯一根因。
- 原 XML 在全屏 HUD 层直接放了两张预载 Image，开局就实例化，不经过“已启用称号”状态判断；只使用 `visible="false"` 属性，没有独立的 CSS collapse 资源容器。动态称号面板默认 collapse，但静态预载图片绕过了动态显示控制。这个设计与左上角露图高度吻合；没有该次实时 DOM 快照，不能声称已在引擎内复现具体隐藏属性失效过程。
- 原前端测试自行构造 Panel，没有加载实际 XML/CSS，所以没有检测到预载图片的初始显示。原 Lua 测试把 RemoveItem/UTIL_Remove 简化为设置 removed 标记，没有模拟引擎使用当前施法对象的生命周期，不能发现这种 native 崩溃。

1. 编译成功及 mock 测试通过，只能说明对应范围通过，不能代替实际游戏渲染和引擎生命周期验证。未做实机验证时明确说明。
