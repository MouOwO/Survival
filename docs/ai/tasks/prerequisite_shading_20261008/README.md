# 科技、转职与升级入口的前置置灰规则

## 行为

- 科技、建筑升级、转职、训练和合体的置灰只反映真正的前置条件：等级、前置科技、转生、权限或合体材料单位资格。
- 钱包中的木材、金币、人口变化不再切换按钮激活状态，也不再触发这些技能的资源状态重建。
- 点击后由服务端检查资源与当前执行状态；资源错误显示“木材不足”“金币不足”“人口不足”。队列、数量上限或升级中状态仍由服务端拒绝重复执行。
- 建造在进入预建造前保留资源预检，实际扣费时仍由服务端复核。
- 真正完成的满级科技隐藏；已经排队至满级但尚未完成的科技不误判为完成。
- 主城升级、研究完成、转生、队列和单位变化驱动相关按钮刷新。共享高级研究所的原生按钮保持共享可操作性，各玩家的前置状态分别投影。

## 投影约定

`prerequisite_met` 决定前置是否满足；`completed`、`removed` 决定已完成或移除；`available` 保留执行状态信息，不能直接作为新投影的置灰依据。

`resource_check_on_cast = 1` 表示资源由点击后的权威事务检查；此类入口兼容字段 `can_afford = 1` 不代表钱包实际余额。旧协议未提供 `prerequisite_met` 时保留原有 fallback。
