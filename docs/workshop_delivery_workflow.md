# 本地修改与游廊交付

统一入口为 `tools/release_pipeline.py`。Git 推送、编译、签名、本机暂装均不等于游廊已更新。

## 每轮交付的结果

| 结果 | 必需证据 | 对用户的表述 |
| --- | --- | --- |
| `LOCAL_ONLY` | 源码、编译或候选完成，尚无匹配的实际上传和官方下载 | 仅本地更新；列出未完成阶段 |
| `UPLOADED_PENDING_DOWNLOAD_VERIFICATION` | 同一发行 lease 内实际 SDK 成功回执和 canonical journal；官方下载尚未完整通过 | 已上传，官方下载校验未完成 |
| `WORKSHOP_SYNCED` | 同一目标的双仓源码、完整签名包、SDK 回执、最新 journal、官方完整下载及所有分卷/资源校验全部一致 | 本轮改动已同步游廊；附版本和 Steam manifest |

云端 API 部署单独报告，不用后台部署代替客户端更新。每轮最终报告同时列出两个 Git 仓库的提交、分支和保留改动。

## 操作顺序

1. 检查 game/content 两仓及当前已发布 journal，以带唯一说明的 stash 保存改动，执行 pull，再 pop 本次实际创建的 stash。只提交任务文件，双仓推送。
2. 运行 `python -B tools/release_pipeline.py pending --full`，核对新增、修改、删除、源码/编译绑定和历史未发布项。可直接映射的文件也属于待发布项；“能够构建”不等于“已发布”。不把旧包的一个 `source_revision` 当成整个 Git 树。
3. 在独立发行族中绑定不可变 game/content 提交、operator 提交及全部调用工具。新改动产生新候选，不改写已经签名或验收过的候选。计划从实际已发布签名 manifest 的逐资源字节投影。
4. 通过入口的 plan、prepare、build 构建完整五分卷签名包。候选/上传目录使用新的外部路径，拒绝额外分卷；裸 VPK 和 LAB 不进入 game/content addon 树。
5. 在受控普通客户端中实机验收本轮签名包。动画验收需要实际画面推进、连续重播和返回界面；模拟测试或“日志结束”不能代替。测试结束后，正常关闭同一进程、等待 keeper 释放，再完整恢复原安装。
6. 按新目标及最新父 journal 生成显式请求，在同一 lease 内运行 `complete --apply --request ... --request-sha ...`。只发起一次上传，然后执行官方完整下载验证。失败保留 pending、journal、证据及备份，先核对实际结果，不自动重传。
7. 用 `delivery-status --download-receipt ... --full` 分别检查本轮目标包与整个工程。历史待发布项必须继续列在工程账本；只发布本轮范围时，不能声称整个 HEAD 已同步。
8. 只有官方完整下载通过后，才推进发布基线和退役旧产物。混合基线仅推进实际已交付的资源及对应源码，未交付文件即使在 HEAD 中存在也继续待发。

## 旧包清理

`retire-plan` 仅输出计划，不执行删除。清理范围限定在 `D:/Survival_发布候选` 和 `D:/Survival_工坊输出` 的已识别旧构建目录；先保留目录身份、控制记录、回执和迁移位置，再核对真实绝对路径、重解析点、进程/文件占用及依赖。

当前上传/安装、实际父基线、未完成恢复或发布的候选、必要恢复备份、密钥、后台发行、真实排演与玩家数据保留。历史记录中的弱引用不自动等于活跃依赖；身份或占用不明时保留并列出原因。不得通过清空 journal 或删除恢复依据来制造“干净状态”。

旧目录放在 addon 树之外不会自动被游戏挂载。发现旧画面时，应先比较实际 Steam manifest、安装五文件、运行资源和最新 journal，不能仅凭磁盘上存在旧包判断“旧包污染”。

## 2026-11-03 已查明的交付缺口

只读官方查询仍指向 `2026110104` / Steam manifest `7025356658517360342`。本机 `0301` 的电影重播及回执修复没有对应 SDK 上传回执。四个电影文件及四个主题纹理在两版中相同；运行 JS/CSS 则不同。因此当前证据说明修复未发布，不能声称已证明电影文件回退或旧分卷混装。

## 成本及计数

发布检查是用户请求触发的一次性工作，不挂到游戏刷新循环。待发审计每轮各仓一次 `ls-tree`、持久 `cat-file --batch`，仅对差异流式取哈希；有总字节/单文件预算及未知阻断状态。初次审计约 1.17 秒、10 个 Git 进程、248 次 blob 请求、11,652,066 字节，255 条待发记录中含 242 条历史源码项。此数值不是游戏 FPS 或原生桥耗时。

交付判定按资源路径建立索引，成本 O(N)，其中 N 约 6917；只读控制文件有大小上限，不反复读取数 GB 分卷。退役扫描只查看两个外部根的一级目录及有界控制文件，不打开 VPK 数据体；最终真实删除前仍需重新核对路径和占用。
