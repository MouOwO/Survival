# 存档服务扩容与验收流程

适用目标：4000同时在线、100000注册、每天约4小时高峰；总预算每月3000元以内。当前上海4核8GB经济型ECS是专用测试机，公网峰值7Mbps、按流量付费。这里的并发是账号/存档HTTP服务，不是Dota战斗服务器人数。

## 采购前先做什么

1. **Codex先做**：固定源码与业务协议，验证成熟合成档案、首结算、幂等、奖励、分级负载、集中退出、4小时稳定性；记录实际CPU、内存、磁盘、网络和清理状态。只在隔离测试库操作，不复制真实账号数据。
2. **用户再做**：在阿里云控制台出具同地域、同计费周期的报价，不付款。分别查询企业通用/计算型8核16GB、16核32GB，以及8核16GB加RDS PostgreSQL的方案。记录实例规格、系统/数据盘、带宽上限及计费方式、首期总价、续费总价；截图不包含密码、密钥或授权令牌。
3. **Codex再做**：按已测瓶颈比较这三种报价，明确哪个配置还需要原生验证。选择前先算续费和流量总账，不以“8核”直接承诺4000人容量。
4. **用户确认采购后**：用户在控制台购买/变配；Codex准备好备份、回滚、参数、部署包和测试命令，再在获得对应部署授权后切换。正式后台/游廊发布各有独立验收，Git推送不代表已部署。

## 默认比较方向

优先比较一台企业规格8核16GB、应用与PostgreSQL同机、独立SSD数据盘和外部备份。这一方案运维组件较少；只有实测资源或隔离需求支持时，才选择16核32GB或独立RDS。现有经济型ECS共享CPU资源，不能把短测没有CPU steal解释为持续性能保证。官方[实例规格说明](https://help.aliyun.com/zh/ecs/instance-types-and-specifications-faqs)说明了经济型与企业规格的差别。

公网按流量计费时，带宽上限控制瞬时速率，账单仍由实际流量决定。提高上限需要先确认费用与授权；目前没有修改这台ECS的7Mbps配置。可参考[官方流量计费说明](https://help.aliyun.com/zh/cdt/internet-data-transfers/)。

固定租金、磁盘、备份、监控、旧服务器重叠费用及预计流量合计应不超过2400元/月，另留600元余量。没有取得账号内控制台续费报价前，不写具体ECS/RDS月租承诺。年付总额除12只是月均成本，不等于可以按月付款。官方入口：[ECS价格计算器](https://www.aliyun.com/price/product#/ecs/detail)、[RDS PostgreSQL](https://www.aliyun.com/product/rds/postgresql)。

## Codex负责的实施顺序

1. 核对目标服务器空闲、系统/架构、磁盘空间、端口归属和SSH主机指纹；只传测试公钥，不要求用户发送密码或私钥。
2. 固定运行源码、官方PostgreSQL镜像和配置摘要，建立全新隔离目录/数据库。限制进程、连接数、等待队列、SQL/HTTP期限和总测试时长；失败保留回执，不在原库继续种数。
3. 先2账号功能与幂等，再40成熟账号；通过后再100、200、500、1000、2000、4000。每档记录真实到达人数、实际业务成功数与拒绝数。上一档失败时，大档诊断只能说明拒绝和资源保护行为，不能写成大档业务容量通过。
4. 档案P95目标1000ms、周期结算1500ms、完整最终流程10000ms，错误为零。原500/1500ms严格目标另报。不能只统计成功请求、忽略排队/奖励后刷新，或把路由百分位平均成总体百分位。
5. 验证数据库和SQLite耐久设置、奖励幂等、历史时钟、完整落库、受保护交易表、退出后的HTTP/lease/连接池归零。测试中的合成奖励不等于真实支付验证。
6. 用已通过的明确档位和数据形态执行4小时连续负载，记录增长与泄漏；不把40人的4小时当4000人的4小时。最后正常停止、采集全量回执并登记产物。
7. 对目标采购硬件重新跑同版验收。源代码、数据库或硬件变化后，旧机器的通过记录只作对照。

数据库参数按实测连接、查询与内存预算设置；不以关闭fsync、同步提交或FULL耐久换取成绩，不靠无限连接、无限队列或延长请求期限掩盖过载。长期运行还需要独立备份及实际恢复演练；生产数据迁移和演练另按授权范围执行。
