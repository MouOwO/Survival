## 射程问题

`long_range_volley` 的正式 CSV 和效果参数均是 **箭塔射程 +500、攻击力 +800**，本轮保留这两个数值。

此前领取已经写入科技统计，建筑投影也算出了新范围，但 `tower_combat_rules.set_attack_range` 只尝试 `Script_SetAttackRange/SetAttackRange`。原生 `npc_dota_creature` 不提供这两个写接口，因此增加的射程没有进入引擎。此前测试对象恰好提供了虚构的 setter，掩盖了此错误。

现在复用已注册的 `modifier_survival_hero_attack_range`，以 `ATTACK_RANGE_BASE_OVERRIDE` 和复制的 stack 更新真实范围。自动寻敌、手动目标检查、后续弹道以及范围指示继续读取实际范围；原生自动搜敌仍为 0，防止箭塔攻击资源树。已有塔领取时立即更新，后建塔和升级后的塔继承；重复领取事务不叠加，其他同队玩家不获得这份加成。

`test_tower_upgrade_targeting.lua` 已改为模拟真实对象形状：没有两个射程 setter，只能通过实际注册的 modifier callback 改范围。它执行正式卡表 → 领取 → 科技 → 建筑投影 → 新范围内攻击命令，并核对显示、新塔、后续升级及玩家隔离。

## 保留的组合约定

百分比攻击卡仍使用项目现有 `BASEDAMAGEOUTGOING_PERCENTAGE`，相加作用于基础攻击；`PREATTACK_BONUS_DAMAGE` 附加攻击不被这一属性再次乘算。因此“攻击力提高 N%”在叠加附加攻击时并不等于最终总攻击整体乘 N%。逐卡报告明确记录此边界，本轮没有重构整套攻击叠加平衡，也不宣称所有组合完全等同总攻击乘法。

融合沿用“素材 CSV 基攻 × 合成系数 + 素材实际攻击增量”的继承公式。融合前的攻击收益保留为快照，新卡按究极塔自身增加收益；步调只更新新塔的一份动态英雄投影，旧素材已继承贡献保持。攻速和射程不从素材继承，按究极塔固定基础与当前科技重算。

## 新兵作训面板修正

用户随后测试 `recruit_training` 时，来源提示显示 +100%，但攻击总值没有翻倍。领取及原生攻击 modifier 已生效；选中单位快照优先读取建筑的未含原生 modifier 的攻击缓存，而旧百分比汇总只读取 managed buff，漏掉了新兵作训、炮塔成长等独立 modifier。绿色仍算出静态 +72，因而白色攻击又被减去了 72，造成截图中的误导。

现在基础箭塔以精确的建筑攻击缓存为基准，汇总真实 native BASE 百分比与 PREATTACK 附加值；百分比相加，附加值最后只加一次。保持成长归白色、固定收益归绿色的原有分类。Tooltip 明确显示固定天赋攻击加成和「新兵作训：基础攻击×2（基础箭塔 LV1–4）」。未改变伤害、卡牌数值、领取次数或生效范围。

新增 `tools/test_recruit_training_display.lua` 执行正式三选一领取 → 真实效果运行时及 modifier → 选中单位请求 → 真实显示明细。覆盖 72→144、累计基础攻击 4232.6→8465.2、科技 +800、玩家隔离、新建 LV1–5、升级撤销、引擎 getter 已含倍率时不重复乘、兼容查询、成长百分比相加及 PREATTACK 50 最后一次加入。以 HEAD 旧 router 运行该用例，会在领取后的攻击最小值 72≠144 处失败；修复后通过。

原生 JS 资源已编译并同步 Content/Game；未改底部 HUD 布局。该局 Dota2 未开放可连接的本机调试端口，未重启当前对局，因此新增修复尚未游戏内验收。旧静态成长、召唤 UI 攻速及 UI visibility 测试的原有失败均在 HEAD 上复现，记录于 `output/recruit_training_20261011/existing_failure_baselines.json`。

## 虚弱宝珠面板修正

随后核对 `weakening_orb`：正式参数为 -50%，效果已在目标怪物挂载独立的 `modifier_rogue_weakening_attack`。旧选中单位快照只汇总 managed buff，遗漏此原生 BASE 攻击修正，因而仍显示减攻前的数值。现改为从波次／挑战怪的 `GetBaseDamageMin/Max` 起算，汇总真实 BASE 百分比与 PREATTACK 平值，按句柄去重，最后只恢复一次无尽波次攻击缩放。引擎 getter 已包含减攻时不会再重复减半。英雄、分身及其他非怪物分支保持原有取值路径。

减攻挂载后派发已有 `UNIT_COMBAT_STATS_CHANGED`，通过现有合并调度器刷新正在查看同一怪物的玩家，不新增轮询，也不再消费卡牌。目标规则保持此前已确认行为：领取时锁定尚未开始的后续首个含 Boss 或精英的正式波次，同波优先 Boss，否则首个精英；当前怪物、普通怪、挑战怪与练功房目标不参与消费。正式 N1 数据中，第 4 波领取作用于第 5 波 Boss，基础攻击 1302→651；第 5 波领取作用于第 6 波精英，1762→881。其他玩家对应波次的怪物不被削弱。

新增 `tools/test_weakening_orb_display.lua`：129 项断言通过，执行真实三选一领取、生命周期、modifier、选中单位请求及 Tooltip 数据链。覆盖 100→50、攻击区间 100–200→50–100、重复事件／领取不叠减、Boss 优先、精英兜底、玩家隔离、双方查看者刷新、已含减攻的 getter、两种兼容查询、句柄去重及无尽攻击缩放。以 HEAD 旧 router 执行同一测试，准确在 HUD 攻击 100≠50 处失败；修复后通过。新兵作训 188 项、Boss 战斗 108 项、建筑显示、生产 UI 与回城 UI 回归亦通过，Lua 语法和配置 CheckOnly 通过。完整输出与可恢复源码位于 `output/weakening_orb_20261011/`。
