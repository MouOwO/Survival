# 2026-09-28 攻速纠正、战斗性能优化与修改复盘

## 已修改

普通伐木工基础间隔恢复为 1.5 秒，100% 攻速对应每秒 2/3 次。八级训练配置、生成配置、默认回退及普通/合体单位 KV 保持一致。合体原有减间隔 0.5 秒保留，由运行时注册应用，因此无其他加成时合体间隔为 1 秒。之前把普通基础改为 1 秒是误解，已纠正。

现有计算顺序为：先用科技、存档、个人和领袖的百分比计算频率，再从其倒数扣除存档、合体和性格的固定间隔缩减，最小间隔 0.05 秒。欢呼还可通过引擎 modifier 增加攻速。因此合体会改变攻速，但仅合体不能解释用户看到的 1.6 次/秒；当局真实加成仍需运行时采样。

塔每次攻击成长原先广播通用永久属性变更，触发建筑恢复扫描、完整属性及技能刷新，并牵连英雄、工人、建造师和金矿。现在战斗成长事件携带作用范围；箭塔攻击成长只更新本玩家已注册箭塔的原生攻击和项目缓存。使用永久服务提供的绝对总值和已缓存的科技/倍率计算，避免增量误差；首次无缓存时才使用完整刷新。普通科技、装备、存档加载仍走完整更新。

保留原有箭塔共享成长规则和逐击即时伤害更新。仅显示推送合并：选中单位属性及游戏信息以 0.1 秒窗口合并同一玩家的重复通知。不同类型 UI 使用独立调度键；护甲变化标志不会被后续攻击变化覆盖。主动请求仍即时响应。

## 验证

- 普通间隔 1.5 秒、百分比攻速、减间隔、移除加成及合体间隔 1 秒集成回归通过。
- 20 座模拟箭塔、1000 次成长：逐次伤害正确，其他玩家隔离；地图扫描、完整建筑发布、永久属性全量读取以及攻速/射程重设均为零；再次全量刷新数值一致。
- 500 次选中战斗属性通知合并为一次最新快照，护甲更新标志保留，建筑与战斗队列互不覆盖。
- 游戏信息 500 次英雄通知加 500 次永久属性通知合并为一次构建/推送；主动请求立即响应，重置取消旧任务。
- 永久成长载荷与权威总值一致；600 次其他战斗成长通知不触发金矿刷新；塔/英雄成长不触发工人刷新。
- 合体、合体 UI、快照调度/差量、生产/回城路由、英雄基础血量/玩家隔离、工人训练、箭塔自动升级和升级特效回归通过。

这些是 Lua 5.1 模拟/集成回归，不是实机帧率测试。只读运行时探针返回 PERF_NO_GAME，未安装事件监听或定时任务；当前无法复现当局服务器耗时、FPS、输入延迟。需新对局加载 Lua 后再采样，不能据此承诺完全无卡顿。

## 待用户决定的建议（未执行）

1. 攻速显示分清单位：面板写“攻击频率 0.67 次/秒”，悬停列基础间隔、攻速百分比、合体减间隔、科技/存档/性格来源及最终间隔，避免把 100% 与 1 次/秒混同。
2. 调整合体与百分比攻速的叠加顺序：建议先扣基础间隔再应用百分比，即 (基础间隔－固定减间隔)/(1＋攻速百分比)。现公式在高加成时很容易触及 0.05 秒下限；是否提高下限需要结合后期平衡决定，不能作为纯性能优化偷偷修改。
3. 箭塔逐击成长改为仅自身：目前一座攻击会增加同玩家全部箭塔攻击，塔越多共享增长越快。建议仿照伐木工改为攻击者个人成长，升级继承；这是玩法变化，当前优化保留共享语义。
4. 自动升级加资源预留：允许设置金币/木材最低保留量，资源不足显示暂停原因；保留当前七选一路线手选、选定后全阶段自动的规则。
5. 挑战结束保护已获奖励：30 分钟到立即停止新挑战/奖励并冻结战斗，再完成已入队存档写入后结束，设置短超时与失败记录。当前超时结束直接 SetGameWinner，和手动结束对 pending 存档的检查不同；存在收尾风险，尚无实测丢档证据。若严格要求 30:00 出结算，需提前预留保存窗口。
6. 可选简化战斗特效：合并同一目标短时间内的飘字、控制非关键粒子密度；保留真实命中/伤害与英雄升级原版金光。需实机区分渲染和服务器瓶颈后验证收益。
7. UI 统一样式来源：存档的脚本内颜色与 CSS 覆盖并存，容易反复出现旧色/禁用色覆盖。整理为一套配色和字号角色；保留当前选择的外观，再统一落点。建筑单选紧凑、伐木工多选编队、镜头单次跳转等既定交互可以保留。
