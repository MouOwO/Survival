# UI 动态协议与重复大包审查（2026-11-03）

当前状态：**仅本地更新**。本审查不构成签名、普通客户端验收、上传或官方下载验证；正式工坊 0104 未因本轮源码工作改变。本轮没有部署后台、改概率、修改玩家存档或执行真实抽奖交易。此前独立后台任务的历史状态不由本文重新认证。

审查范围为 HUD、存档、每日福利、地图抽奖及其共同 UI 通道。本文不声称全项目全部事件、NetTable、HTTP 或网络报文都已小于 50 字节。原生实机结果与模拟计数分开记录；后续实机、双仓提交和发行结果由主操作者补充。

## 1. 问题、范围与证据限制

用户报告重复 `CUserMsg_CustomGameEvent` 大包与游廊卡顿。旧实机日志的一次离线统计包含 1,617 条超大消息，其中 3,532 字节 723 条、27,254 字节 356 条，峰值秒 128 条。此计数说明频率和体积，不足以仅凭大小把每个包归因到某一业务事件。日志分析工具为 `tools/analyze_custom_event_log.py`，本文不复制原始身份、会话或支付内容。

真实源码中确认了以下可重现成本：

- 私有 HUD 波次投影重复包含完整 N1—N10 难度说明；难度目录已有独立启动来源。剔除该重复字段的真实十难度夹具 JSON 从 2,933 字节变为 560 字节，1,000 次真实资源变化投影不再序列化目录。此处是 JSON 测量，并非对应原生包大小或 FPS。
- 存档首发有 20 类、945 行；旧重复预取会重置基线并同步重发。保留旧协议的有界队列已消除相同来源的重复预取工作，新客户端改用本地目录与整数变化量。
- 每日页不再依赖周期性完整目录快照；3 秒客户端完整轮询取消，时间相关展示改为客户端依据权威时间/截止值计算。真实状态变化、日界、周界、月卡到期及领取回执仍有服务器触发。
- 抽奖结果不再依赖一次额外完整奖池 HTTP 快照才能传给新 UI；仍以原 HTTP 事务成功应用的档案为权威，不乐观增券或奖励。

没有调整消息 enforce 上限、隐藏警告、拦截引擎日志或停止支付租约来制造改善。

## 3. 协议、身份与原子性

- 事件名为 `cw`，仅单 key `d`；内容为无 padding 的 base64url。业务字段不传名称、图标、说明、固定奖励、目标、服务器错误长文或档案 GUID。
- 完整 256 位 schema SHA 在 hello 视图通过八个 uint32 校验，之后使用短 schema/session/epoch/view 别名。视图包括 hello 1、HUD 2、daily 3、archive 101—120、lottery 201—204。
- 普通帧含 7 个 canonical varuint header；schema/session/epoch/view 为 1—16383，revision 为 1—2097151。生产控制器在 revision 1048575 前切 epoch/full，epoch 用尽要求新 session；不能靠随机 32 位 header 或全为 1 的测试掩盖容量问题。
- body 为显式 record ID、field ID、typed uint/sint/bool 或 remove。大整数使用 lo/hi，保留安全整数范围；社交概率通过 IEEE754 binary64 高低字精确传输，不静默四舍五入。
- 多片必须全部到齐并 typed 校验，应用成功后才 Commit revision；缺片、错 schema、冲突片、旧 epoch/旧 session 不得应用半份奖励状态。重同步仅失败触发，使用 latch 合并，不添加正常周期 ACK 或轮询。
- 客户端 request token 1—16383 单调递增、不复用；服务器仍生成独立原事务 nonce，并绑定当前 account/match/mode。typed token 是本地关联，不能充当支付、扣券或奖励权限。
- 关闭视图取消待发整页/组包，不继续构建整目录；daily 的极小 known/can_claim hint 单独保留。重开建立可信新视图基线；换局、销毁、槽位复用和旧 callback 失效。
- 四玩家索引与队列彼此隔离；不存在共享某玩家所有权/请求 token 的全局业务快照。共享静态目录不含私人档案。

## 6. 权威规则和特殊边缘

**抽奖**：公开奖池静态内容必须与已认证后台返回的 `catalog_md5` 和当前 catalog session 相同。本地 manifest 随双仓源绑定。整个 archive bundle hash 可因非抽奖配置改变而不同；相同 public MD5 允许复用本地 UI，交易继续使用原 `active_hash` 权威校验。未取得有效目录时 known0；MD5 不同则 known0/enabled0/error6，禁止 draw/read，不能拿旧标签展示新池。测试包含“大 bundle hash 不同但 public MD5 相同允许”与“MD5 不同 0 交易拒绝”。

真实回执只有原档案成功应用后才标成功；HTTP ok 而档案未确认时维持 pending，不伪造券/奖励。新非堆叠奖品原回执的 owned_count 可能为 **授予前** 数值；post-commit 物品所有权另读实际档案，不能用回执值或 `+1` 猜测。结果数量、池、枚举、已注册 membership 全部校验后才提交。未知后台错误映射固定本地提示，不发私密长文。原重复兑换、保底、抽取、权限、nonce、幂等、忙锁与重试规则不修改。

**签到/福利**：每日日界、累计/遗漏、12 个唯一奖品、三轨道的 progress/period、每档 claimed/can_claim/status 保持原投影结果；静态奖励和门槛留本地。ACK 绑定本地 intent 与目标日/档/周期；success 必须同时得到权威已保存标记，不能凭一个 ok 增加积分或物品。未知值不以 0 冒充同步完成。

**存档/社交**：原装备、升级、晋升与社交事务仍走既有规则。异步终态通过 nonce→token 的服务器索引返回数字 ACK；closed 时保留结果，不发送整页，重开 full 携带最新终态和期望档案版本。ACK 先到而行状态尚未更新时，客户端等待正确档案版本，不能凭 ACK 乐观奖励或重发收费意图。
