## 分阶段修改与复查

1. **固定几何和投影**：按地图 `build_bounds`、64 单位间距、建造平面高度生成共享行列线。6144×6144 区域是 194 条线；不是为 9216 个格子分别生成四条边。纯数学测试覆盖负坐标、透视投影、视口裁剪和世界圆到屏幕椭圆的转换。
2. **独立白色底层**：`survival_static_grid.js` 缓存世界几何及摄像机投影。Panorama 原生 `opacity-mask` 使用预编译 RGBA 纹理；移动/旋转遮罩时对子网格反向变换，网格仍固定在世界坐标上。白色网格不读取占地校验结果，快速移动也不隐藏。行列线及视口内角标在进入预建造前预热。
3. **静态禁建底图**：服务端启动时分批计算整个建造区域的地形、树木和禁建区域，每批最多 128 格、约 2ms 工作预算；用 V3 两位状态编码发送给客户端。预计算独立于鼠标及预建造会话，取消技能不取消它。客户端合并同列连续红格，并保留其布局；快速移动不清空、不隐藏红区。新建筑及移动单位仍由动态覆盖层更新。
4. **逐格占地**：`survival_grid_state.js` 按吸附坐标读取底图及最近校验，每格独立红/绿，未知格为灰色。原先的横条拼接、重复分隔线和 639 个周边色块预热池退出主渲染路径。每个投影四边形使用两个相对顶点的原生 `clip: radial(...)` 裁剪同一个填充，避免条带和三角形内部接缝；白线、角标统一绘制在色块上方。城墙仍为 256×256、4×4 格，2×2 建筑显示四格。

## 更新边界

- 地图边界/格距/建造平面改变：重新生成固定世界几何。
- 摄像机/分辨率改变：更新投影和可见节点，视口外角标不实例化。过度缩小时仅降低角标密度，64 单位行列线不变。
- 鼠标移动：保留白线、角标、静态红区布局，更新范围遮罩、反向变换及吸附图标；只有跨格或状态变化才重画落点。快速移动暂停动态查询，静态红区和本地落点颜色保留。
- 阻挡信息更新：修改色块；不生成白色网格。
- 取消预建造：隐藏，保留缓存供下次使用。

## 实现边界

本实现使用 Dota 2 Panorama 保留的共享线条/角标和原生透明度遮罩，不是 Unity 静态批处理，也不承诺单次 draw call。固定网格位于建造平面（template_map 为 Z=384），不为台阶或装饰建筑逐点贴地；非法地形仍由真实地形校验判红。范围外轮廓按世界圆的透视投影计算，内部羽化使用屏幕椭圆径向渐变。

Lua 启动预计算需要重新运行地图才能完整启用。调试数据位于 `GameUI.CustomUIConfig().SurvivalStaticGridPerformance`、`SurvivalGridStatePerformance` 和 `SurvivalGridPerformance`。静态底图是建议显示数据；移动单位及新建筑不写入它，最终建造仍检查真实地形和占用。如果未来加入地形编辑、砍树等玩法，应额外增加底图失效更新。

2026-09-29 本轮实机核对：保留已有暂停对局，用隔离的只读地形快照验证实际地图的白线、静态红区、整格绿区、右下角透视对齐；没有重置建筑占用或推进对局。数学/模拟回归另外覆盖混合颜色、启动任务及晚加入客户端，完整的新局预加载与运行中 FPS 仍需实测。原生 `matrix()` 虽能经过资源编译，运行时并不支持，因此最终方案只使用已在实机验证的径向裁剪，不使用矩阵样式或三角形拼接。额外修正隐藏界面预热时的视口回退，并让图标与落点使用同一建造平面，避免指向高地时两者分离。

### 红格完整填充与鼠标平面拾取修正

合并后的红色列条宽高差很大。此前尝试按宽、高分别归一化裁剪角，但用户实机截图仍显示错位和斜缝，不能据此认定原生裁剪语义已经验证。当前方案将每个填充及其子裁剪都放在同一个正方形坐标框中，框边长取投影包围盒较长的一边；投影四角不动，仅增加不可见的框空白。这样像素角度与归一化角度完全相同，不再依赖非正方形面板的角度缩放。保留 64×512、512×48、37×283 的非正方形投影样本，并验证实际 paint 输出在透视变换下覆盖每格内部，及两个裁剪层使用相同正方形尺寸。

## 2026-09-30 跨岛拖动、鼠标图标与投影开销

图标改为直接读取屏幕鼠标坐标并除以 Panorama UI 比例，独立约 60Hz 更新；不经过世界坐标投影、不随 64 单位吸附，也不等待服务端。只有建筑占地继续吸附。鼠标失去地形命中时仍显示图标，但不允许据此提交建造。

相机参考面从地图中央的 256 单位小块改为镜头附近的 1024 单位块，每移动超过 1024 单位重新选取，避免在很远的小块上拟合后向整屏外推的误差。参考位置来自视口中心，与鼠标无关。整数像素投影回归覆盖四个相距数万单位的镜头位置；12 个往返落点误差均小于 8 世界单位。临时投影失败后，即使回到相同相机，也重新建立有效投影。

中心建造区保留原生技能圈；远处禁建区使用与网格同一椭圆的轻量边框，避免原生粒子贴较低地形而网格仍处于 Z=384 造成上下分离。内部淡化保持原遮罩。热加载时新增面板尚未出现则保留原生圈，完整效果需新局加载。

拖动开销复查及改动：
- 状态层投影直接使用已拟合的网格平面，离开视野/相机背后的红区不再回退到大量引擎 WorldToScreen 查询。
- 红区在投影前按可见世界矩形剔除；96×96 的连续阻挡样本从 1152 个窄条合并为 144 个最多 8×8 的矩形，覆盖面积不变；完全不可见时投影次数为零。
- 角标在枚举前按候选面积设步长，防止特殊镜头下先遍历几十万个点再抽稀。保留全部网格线。
- 为热加载控制器增加代次校验及事件退订，旧预热、绘制、输入维护循环不再与新控制器争用同一批界面。

新增 SurvivalGridFramePerformance 保留累计帧数及相机、预览布局、状态层的 JS 最大耗时；不会逐帧打印日志，也不代表 GPU 帧时间或 FPS。独立图标更新测试不触发投影、网格布局或校验请求。静态网格、状态层、客户端流程、新旧 helper 集成与纹理测试通过，资源已编译。实机检查时 Dota 位于主菜单并提示客户端版本过低需更新，因此本轮远处边框最终画面及 FPS 尚未实测。
