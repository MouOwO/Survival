# 两个测试入口

项目根目录和桌面只提供“离线逻辑测试”与“联网登录测试”。具体日常操作见根目录 `测试入口说明.txt`。先正常退出旧 Dota 再切换，入口不会终止已有游戏。

| 入口 | 代码与存档 | 适用范围 |
| --- | --- | --- |
| 离线逻辑测试 | 当前 development 源码；本局独立内存档案；无云请求 | 怪物、英雄、技能、建筑、局内背包；允许作弊和调试命令 |
| 联网登录测试 | 已验收 `svt_w24` 冻结副本；四账号独立测试库 | 登录、云端档案、抽奖目录及云数据集成；禁止作弊和数据修改调试命令 |

离线并不代表游戏不需要运行 Steam 客户端；它指不依赖云端认证与存档接口。Tools、development 和显式 `survival_offline_logic_test=1` 必须同时满足。身份仍使用引擎提供的真实 Steam 账号，内存和对局隔离负责区分测试档，避免临时账号标识与原生加载门禁不一致。非 Tools、生产包及网页登录冲突均拒绝启用离线模式。

离线档案不读取任何旧 JSON，不写云端；新局清空，版本序号维持单调以兼容档案保护。原生资源/UI/模式/难度门禁和游戏内调试入口保留，不能把临时 provider 用在正式云端战果结算。抽奖目录、支付及排行榜等云能力需要联网环境；现有永久档案测试限制继续适用。

联网入口复用已验收副本，自动核对并复用或启动本机固定目的 Steam TLS 中转。它仍依赖本机在线，稳定云端出站节点尚待配置。首次网页登录后可明确选择记住浏览器30天，之后有效期内跳过 Steam 登录，但每局仍须确认授权码。退出网页登录会撤销浏览器身份，不删除测试档，不自动终止已批准的局。

离线启动设置 `sv_cheats=1`，联网设置 `sv_cheats=0`。服务端中央开发策略还会读取受信的网页登录配置：只要启用网页登录，就拒绝聊天作弊、资源/英雄/科技/武器/波次/存档等调试修改，即使运行在 development 与 Tools 中也一样；已经注册过的回调同样重新核对权限。正常游戏购买、升级、召唤及只读诊断继续保留。配置缺失或错误时拒绝作弊，不影响正常初始化。

联网实际冻结副本需包含同一门禁。入口按 `publishing/workshop/online_cheat_policy_20261025.json` 核对发布内容标识、受保护策略文件和 production 配置的 SHA-256，防止误用旧版本。完整签名和资源验证在候选构建与安装时执行。此设置不把本地主机变成可信托管服务器；原有独立测试库和战果可信度限制继续适用。

`tools/workshop_test/launch_test.ps1 -Mode Offline|Online -CheckOnly` 只检查本地入口和依赖，不启动游戏或中转。实际进程与安全诊断保存在忽略的 `output/test_entry_runtime`。冻结联网包与当前开发源码不会自动相互覆盖。

2026-10-25 的 UI/数据综合测试及候选交付状态见 [本轮验证报告](validation/UI_DATA_QA_20261025.md)。本机冻结副本、签名候选和工坊已发布版本分别记录，不能把本地入口通过当作原游廊条目已经更新。

2026-10-24 原生离线此前已完成身份一致、加载就绪、模式/难度选择并进入地图，局内加木材命令已生效。两个根 CMD 的只读检查通过，联网 v02 此前已完成真实 Steam 登录、云端读档与在线进度回执。浏览器记住功能已通过53项服务测试并部署，跨日效果由明确 Cookie/数据库期限和重启测试验证，尚未经历实际30天。

禁作弊更新已安装签名 v03，完整核对6627份运行文件，仅中央权限模块变化。原生联网在载入地图和点击“开始”后均拒绝 `script_reload_code`（引擎报告 cheat command ignored），授权界面正常出现；本次未批准新对局或写入云档。原生离线探针确认项目调试权限、引擎作弊均开启，现金业务关闭；带非空测试支付令牌的回归也确认离线支付路径零 HTTP。策略1504组、调试入口与旧回调178项、保护前后48组行为及启动边界测试均通过。

## 从游廊测试联网版本

四人直接游廊候选 `WS4-MP-09` 已完成分发和四槽原生建房测试，但普通游廊中授权请求创建仍失败，正式游戏阶段和手动刷新后也未恢复。原条目已恢复签名 v08 单人入口并完成官方重新下载校验。直接多人尚未打通，详见[四人入口记录](arcade_multiplayer_20261025.md)。两个现有开发 CMD 保持原用途。

沿用[孤城逐晓 · 封闭测试](https://steamcommunity.com/sharedfiles/filedetails/?id=3824360109)，保持不公开列出、原封面与四账号限制。历史 v03／v04 分发记录继续保留；最后一次成功验收的 WS4-ENTRY-05 自动入口与原游廊完整流程以[发布回执](../publishing/workshop/workshop_entry_release_20261024.json)为准。

2026-10-25 的 v08 UI/数据修复已在本机冻结联网入口完成重进读档与数量显示验证。原条目更新申请收到 Steam 失败回调，不能把本机通过视作工坊已更新；上传现场、远端对账及下载验收状态分别见[本轮分发记录](../publishing/workshop/ui_data_qa_release_20261025.json)。长提示框中央悬停不稳定仍为待修项，完整范围见本轮 QA 报告。

当前恢复版：先正常退出旧 Dota，让 Steam 完成更新，再从 Steam 正式启动 Dota。在原条目创建单人 `ws4_entry` 房间，保持作弊关闭；进入后自动重开同条目的 `template_map`，随后按原生界面正常开始，用当前游玩的同一 Steam 账号核对短码并在网页批准，再返回选择模式和难度。这沿用原 v05 的已验收单人路由；不能让多名客户端各自执行跳图命令并称为同一局。

v04 原游廊曾报告 `WS4-WEB-04/start/create/0`，表示请求创建失败，并非后台 HTTP 返回。该版已每5秒跨阶段重试；官方资料没有证实必须等到正式战斗才可 HTTP。普通无 Tools Dota 直接启动原 ID 已完成真实批准、读档 revision 27–30和开局；新入口探针也已自动切同 ID 并取得短码。这些对照不替代最终原游廊完整验收。

游廊当前提示使用玩家电脑作为主机。本轮没有新增专用服务器托管，也没有证明降低延迟或真实双人通过。`changelevel template_map` 已实测导致 `CLIENT_NO_MAP`，不得作为保留多人连接的修复。当前失败发生在游戏创建 HTTP 请求对象时，不能通过更换账号密码或只更新云存档后端修复；尚未找到适用于此场景的官方 HTTP 开关。作者端固定 Steam TLS 中转仍需在线，独立测试库与联网禁作弊限制继续适用；两根 CMD 保留作离线调试／联网登录排查。
