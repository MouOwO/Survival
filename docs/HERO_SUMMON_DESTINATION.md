# 祭坛英雄召唤落点

## 2026-09-23 故障原因

`destination_not_traversable` 来自召唤前的 GridNav 校验，与后端认证无关。
原代码优先使用 `player_N_hero_spawn`，仅校验这一点；地图没有标记时也只校验祭坛前方 260 单位的一点。

当前 `template_map` 实机与源图一致：0 号出生标记为
`(-6336, 13342.38867, 152)`，1 号为 `(1600, 13269.50879, 152)`。
两处地面高度约 127.25，但 `GridNav:IsTraversable` 为 false。
源图中这两座木材房及标记分别向北移动约 542.39、469.51，导航掩码仍在旧位置。
2、3 号原出生标记可通行。

## 修复规则

- 专属出生标记保持优先；以 64 单位间隔、从近到远检查半径 384 内的候选点。
- 专属点附近无解时，再检查祭坛前方及其附近。搜索不会遍历全图。
- 点位贴地，中心和英雄半径 32 的八个方向均检查导航与英雄禁区。
- 与对应标记／祭坛高度相差超过 64 的位置不采用，避免落到水面或下一层。
- 局部检查动态单位、建筑和隐藏墙体的实际碰撞半径；无敌单位也纳入检查。
- 通过检查后才替换玩家英雄；实际传送复用这一贴地坐标，不再重新取原标记。
- 英雄资源异步加载完成后，重新检查落点；无解时提示清理障碍，不消耗召唤机会。
- 若引擎替换完成后落点校验失败，将新载体隐藏并恢复为可重试状态，避免锁死在 replacing。
- 原生技能同步／异步失败均结束冷却并提示；修正异步回调中技能变量的作用域。

本次修改解决召唤落点，不修改整座房间的导航网格。两间已移动房间的全部行走范围仍需将源图导航与新布局同步；找到合法出生点不代表整个房间均可走。

## 验证方法

```powershell
lua scripts/vscripts/tests/test_hero_summon_destination.lua
lua scripts/vscripts/tests/test_hero_summon_flow.lua
lua scripts/vscripts/tests/test_hero_instant_blink.lua
```

`tests/manual_hero_summon_destination.lua` 提供 Tools 专用实机烟测：检查四个玩家的真实标记、解析落点及临时单位传送；只清理自己创建的临时单位，不触发玩家存档、奖励或真实召唤。

本轮结果：落点回归、7 个召唤流程集成场景及瞬移回归全部通过。
实机 `template_map` 四个玩家位置共 40 项检查通过，0 失败，剩余临时单位 0。
0、1 号分别在距原标记 128、64 单位处找到同层安全位置，附近 128 单位范围各有 5 个方向可寻路；2、3 号直接使用原标记，各有 8 个方向可寻路。
这次实机使用临时单位验证落点与传送；真实祭坛按钮点击后的整套英雄替换尚未实机验收。

Lua 在新开一局时加载，无需重启 Python 后端。
