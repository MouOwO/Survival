# 防御塔销毁与原位重建

## 2026-09-24 修复

箭塔销毁分为同一帧的业务清理和短暂保留的死亡表现：

1. 手动消除调用 `ForceKill(false)`，确认死亡后立即清理；自然死亡复用同一入口。
2. 先删除建筑登记、释放格子和数量，释放全部转职预留，再通知建造者并释放人口。迟到或重复的引擎死亡通知不再执行第二次清理。
3. 旧塔保留主体和挂件，调用模型原生死亡活动，取消碰撞、控制、选敌与血条。约 4 秒后单次清理剩余实体；引擎提前移除主体也会清理挂件。没有新增副本 NPC 或每塔轮询。
4. 新塔可以立即使用原格子。旧死亡通知、升级回调和外观预加载回调不能恢复旧塔，也不能误清新塔。

数量规则沿用配置：每玩家最多 7 座**未转职基础箭塔**；少于 7 座显示建造入口，达到 7 座关闭入口。转职释放基础塔名额，各路线继续独立限额。移除了融合一次后永久隐藏基础塔建造入口的旧闩锁；终极塔自身的数量限制仍由融合系统管理。

### 根因

- 原死亡入口在释放格子/数量前清理外观，且提前标记 `cleaned`。外观清理异常可能让后续清理无法重试。
- 建造者用 `nil` 同时代表“基础箭塔”和“没有登记”，重复创建/死亡通知不能可靠去重。
- 建筑列表以及升级恢复扫描只检查实体句柄有效，死亡动画期间尸体仍可能被重新登记或刷新。
- 转职预留释放使用 `or` 短路表达式，首条成功后不再检查后续路线。
- `fusion_completed` 的永久禁建状态不根据当前基础塔数量恢复。

## 验证

以下 10 项本地 Lua 回归通过：

- `test_tower_destruction_rebuild`：真实建筑服务、格子服务、事件总线与路线计数；7→6→原位重建到7、尸体不占格、重复死亡、自然死亡、外观异常、人口只释放一次、路线预留释放。
- `test_builder_tower_rebuild`：原生技能槽恢复、7塔限制、玩家隔离、转职计数、融合后恢复。
- `test_building_death_visual`：死亡主体/挂件保留、一次性清理、异步外观回调、实体编号复用及场景重置。
- `test_building_upgrade_lifecycle`：尸体与失效句柄不会重新进入升级/属性缓存；旧实体事件不影响新塔。
- `test_tower_class_preflight`、`test_tower_upgrade_targeting`、`test_tower_idle_state`：转职失败无副作用、升级及攻击/待机行为保持。
- `test_io_building_ambient`、`test_visual_carrier_health_bar`、`test_wall_quick_upgrade`：粒子/血条兼容及城墙升级回归。

这些是服务组合测试和引擎接口模拟，不等于实机动画验收。本轮控制台探针返回 `GameRules=nil`，没有运行中的测试对局，未操作当前地图或玩家建筑。普通塔、英雄外观塔及以常驻粒子为主体的塔，其原生死亡动作/尾效仍需游戏内逐类确认。
