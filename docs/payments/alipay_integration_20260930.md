# 微信 / 支付宝共用商城

更新：2026-09-30。支付宝正式应用 `2021007102660118`，收款商家 PID `2088980017268461`。支付后端发布目录 `/opt/goufayu/payments/20260930-payment17`；客户端 Lua 和 Panorama 已更新并编译。

## 玩家怎么购买

1. 首次更新后重新进入一局，用顶部“商城”或右侧“商品商城”选择商品。
2. 在订单确认页选择“微信支付”或“支付宝”，核对价格与奖励后点击购买。
3. 微信在游戏内显示二维码；支付宝自动打开浏览器官方收银台，也可点“打开支付宝收银台”。如果自动打开没有响应，用该按钮或复制下方链接打开。
4. 付款后返回游戏，服务端会自动核对到账并刷新存档；也可点击“查询付款结果”。

当前 5 件属性商品、特殊抽奖券都为 50 元。特殊券每次增加 1 张且可重复购买，方便核对到账。道具、属性和权限礼包共用原子发奖逻辑。

同一账号、同一商品只能存在一个未完成订单，切换支付方式不会生成第二笔可同时付款的订单。需先点“取消订单 / 更换支付方式”，确认关单后重新下单。支付宝若仍未生成平台交易，旧的签名表单可能仍有效，服务端会保留该订单直到确认可关闭或到期，不会直接抹掉付款记录。订单有效期 30 分钟。

## 商品表继续怎么改

仍使用 `data/csv/商城支付系统/payment_products.csv`、`payment_rewards.csv`、`payment_categories.csv`。改完运行项目根目录 `sync_payment_shop.cmd`，微信和支付宝同步生效，无需维护两份商品。详情见 [CSV 操作说明](../payment_shop_csv_guide.md)。

## 服务端实现

- 支付宝使用现有“电脑网站支付”的 `alipay.trade.page.pay`，RSA2 公钥模式，不要求额外申请当面付。
- 游戏客户端仅提交 SKU 和支付方式；账号与对局由游戏服务端提供，价格及完整奖励由数据库固定。
- 正式通知地址：`https://pay.xiaofengnet.com/v1/payments/alipay/notify`。下单时传入 `notify_url`。
- 通知验证 RSA2 签名、AppID、商家 PID、订单号和金额；查单也验证支付宝对原始响应的签名，业务错误同样必须验签。`TRADE_SUCCESS` / `TRADE_FINISHED` 才进入发奖。
- 原有 `payments.deliver` 事务同时更新道具、属性、权限与订单凭证，重复通知只返回同一结果。浏览器返回页不能触发发奖。
- 后台查单补偿遗漏通知；游戏轮询状态后重新加载权威存档。
- 两种支付方式共用商品限购，交易号唯一性按支付渠道隔离。原有微信订单不改价、不改奖励。
- 支付宝私钥和平台公钥保存在 `/etc/goufayu-payment/alipay`，仅管理员与支付服务可读；客户端、CSV、Git 均不存密钥。
- 表单明确使用 UTF-8，并在支付宝提交 URL 中传 `charset=utf-8`。CSP 放行实际官方跳转链：`openapi.alipay.com` → `unitradeprod.alipay.com` → `excashier.alipay.com`。

接口构造参考 [支付宝官方 Python SDK](https://github.com/alipay/alipay-sdk-python-all)；通知字段核对和应答参考 [官方支付异步通知说明](https://developer.alibaba.com/docs/doc.htm?articleId=105902&docType=1&treeId=193)。当前代码直接使用项目现有 cryptography 实现上述协议，不引入额外 SDK 运行依赖。

## 维护与回滚

发布工具 `server/payment_backend/upgrade_alipay.py` 支持 `validate` / `activate`，接收公开的商家 PID，密钥始终从受限目录读取。只有具名、清单哈希匹配的 release 可激活。自动回滚测试通过后才备份和切换服务。

激活前配置与 Nginx 备份位于 `/etc/goufayu-payment/config.before-<release>.json` 和 `nginx.before-<release>.conf`。启动或 Nginx 校验失败会自动恢复前一发布；新增数据库结构兼容原微信入口。手动回滚前须核对是否还有支付宝未完成订单，不能让其失去验签、查单和到账处理能力。

原来的 `refreshdata` / `refreshmoney` 测试入口仍受 Tools 模式、账号名单及服务端开关限制，保留 `TODO(PAYMENT_TEST_ONLY)`。本轮没有执行真实账号清理，也没有修改商品价格。

## 收银窗口点击修复（同日）

收银窗口增加独立的内部点击拦截区域，窗口层级高于黑色遮罩。窗口空白处、禁用控件不再把点击传给遮罩；仅当前最上层窗口的外部遮罩执行关闭，关闭后取消点击命中，延迟的遮罩事件不会重新打开窗口。

同时修复支付宝开通标志的类型兼容：游戏事件可能将 Lua 布尔值传为数字 `0/1`，客户端同时识别 `true/false` 与 `1/0`，避免把已开通的支付宝按钮误判为禁用。

当前真实 Tools 对局已验证：点击支付宝后选中高亮及“支付宝购买 ¥50.00”正确切换，窗口保持打开；点击窗口内部空白处保持打开；点击外部遮罩关闭。验证没有创建订单、付款或重启对局。客户端资源已重新编译，交互测试与商城回归通过。
