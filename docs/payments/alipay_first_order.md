## 支付和发货流程

1. 游戏客户端只发送购买意图和商品编号。可信游戏服务端提供已认证的玩家身份；网页不能通过传入别人的账号指定收货人。
2. HTTPS 后台读取商品配置，保存唯一商户订单号、玩家归属、10 分金额、商品及奖励快照、配置版本和待支付状态。重试复用同一订单。
3. 后台使用应用私钥，通过官方 SDK 构造 `alipay.trade.page.pay` 支付链接或表单，游戏打开支付宝收银台。该产品不等同于 `alipay.trade.precreate`，不能承诺它直接返回可嵌入游戏的 `qr_code`。
4. 支付宝向独立的 `notify_url` 发送支付结果。后台用支付宝公钥验签，再核对 APPID、收款商户、商户订单号、订单金额和支付状态；查单作为补偿路径。不能根据页面跳转、客户端“付款成功”消息或付款截图发货。
5. 支付确认必须可靠持久化，同时建立可恢复的发货任务；发货按商户订单号去重。同一订单重复通知、回调与查单并发、服务重启均不能重复增加奖励或属性。
6. 发货通过数据库事务提交库存、对应已实现属性、档案版本和发货收据，协调现有档案并发写入。不能先读取整份旧档案，再覆盖期间产生的游戏奖励。
7. 游戏向自己的后台查询订单和最新档案，展示已到账。需要验证当前局刷新、重连和下一局的持久化结果；仅数据库写入成功不等于当前局 UI 已刷新。

电脑网站支付链接构造参考 [支付宝官方 Python SDK](https://github.com/alipay/alipay-sdk-python-all)。异步验签、订单核对及重复通知处理参考 [电脑网站支付结果异步通知](https://developer.alibaba.com/docs/doc.htm?articleId=105902&docType=1&treeId=193)。支付结果以通知或查单为准，参考 [电脑网站支付快速接入](https://developer.alibaba.com/docs/doc.htm?articleId=105899&docType=1&treeId=270)。
