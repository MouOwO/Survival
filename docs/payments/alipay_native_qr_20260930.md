# 支付宝游戏内付款二维码

## 当前状态

2026-09-30 使用正式 AppID `2021007102660118`、PID `2088980017268461` 的现有密钥实测 `alipay.trade.precreate`，支付宝返回经 RSA2 验签的 `ACQ.ACCESS_FORBIDDEN`（无权限使用接口）。用户确认尚未开通／添加当面付能力。电脑网站支付已可用，但不能据此认定直接生成二维码的权限也已开通。

调试使用单独记录、未对外展示的 50 元订单号，设置 1 分钟绝对到期时间。预创建被拒绝；随后关闭接口返回经验签的 `ACQ.TRADE_NOT_EXIST`。没有扫码、扣款或发奖，没有修改玩家的在途订单。

## 商户要做的操作

1. 支付宝商家平台 → 产品中心，查看“当面付／扫码支付”，按实际游戏经营类目确认是否可签约并申请。
2. 支付宝开放平台 → 正式应用 `2021007102660118` → 可调用产品，检查对应扫码支付能力是否已添加、生效。如页面不同，向支付宝客服确认该应用与商家 PID 是否具备 `alipay.trade.precreate` 权限。
3. 开通生效后通知技术人员重新核验接口，再启用游戏内二维码。现有 AppID、PID、密钥、HTTPS 域名及通知地址可以继续使用；无需再发送私钥。

官方 [扫码支付接口及错误码](https://developer.alibaba.com/docs/api.htm?apiId=862&docType=4) 将 `ACQ.ACCESS_FORBIDDEN` 说明为无权限使用接口；[支付宝官方 Easy SDK](https://github.com/alipay/alipay-easysdk/blob/master/APIDoc.md#facetoface) 将 `precreate` 列在当面付能力中。具体经营场景能否签约，以支付宝审核结果为准。

## 已实现的流程

游戏确认商品 → 服务端按数据库价格和奖励创建订单 → 调用 `alipay.trade.precreate` → 验证支付宝响应签名、订单号及官方二维码地址 → 保存二维码 → 游戏内原生面板显示 → 手机支付宝扫码 → 通知验签／签名查单 → 同一套事务发奖与存档刷新。

- 客户端不会在创建订单后自动打开网页；游戏内二维码同时支持微信、支付宝。只有玩家主动点击备用付款页按钮才会打开浏览器。
- 服务端配置 `alipay_checkout_mode` 支持 `page_pay`（默认，现有已开通能力）和 `precreate`（直接付款二维码，需额外权限）。权限未核实前保留 `page_pay`，避免将现有支付宝购买切换成失败接口。
- 新旧模式共用商品、账号归属、限购、付款通知和原子发奖。未完成的网页订单保持原模式和原到期时间，切换配置不重新创建它们。新二维码订单的备用网页仅显示同一个二维码，不再生成另一份网页支付表单。
- 预创建失败不会退回网页模式或把网页链接伪装成支付宝付款码。网络失败使用相同订单号重试；付款码到期、关闭或已发奖后隐藏。
- `/v1/payments/alipay/notify` 地址不变。客户端不会收到私钥、平台公钥、商户配置或买家信息。
