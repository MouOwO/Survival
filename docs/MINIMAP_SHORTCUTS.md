# 小地图右侧快捷操作

更新：2026-09-26。实现与模拟验证完成；本轮尚未进行 Workshop 新局实机验收。

| 显示 | 鼠标与快捷键效果 |
| --- | --- |
| 蓝胖图标，下方“空格” | 选中本人的建造师并移过去镜头；召唤正式英雄后仍选建造师 |
| 城堡图标，下方“F2” | 正式英雄返回本人主基地旁的安全位置，并跟随英雄镜头；当前选中建筑也能使用 |

F1 固定选中本人的正式英雄，存活时定位镜头；阵亡时仍可选中查看，但不把镜头移到隐藏位置。每次读取当前英雄及服务器 `survival_hero_skills/player_N` 的正式身份，未召唤、召唤失败残留的隐藏替身和旧身份都不选中；沿用同一聊天、弹窗及准入保护。小地图仍保留上述两个入口。

两个按钮竖排放在小地图右侧，整体宽度由 176 收窄至 64；单项高 76，图标 52×52，下方居中显示 20px 快捷键文字，两项间距 6。去掉右侧名称、大底色和宽框；建造师保留蓝胖头像及柔和细边，回程为透明底浅色城堡 SVG，无方框。继续随分辨率和生产面板位置向上避让，并按实际缩放后的范围屏蔽世界血条。

按钮和键盘复用同一动作。建造师取服务器 `survival_builder_identity/player_N`，不使用正式英雄或普通 creature 不可靠的引擎 owner getter 代替这份身份。身份未到、单位已死亡时按钮不可用。回程在未召唤、阵亡或技能冷却时不可用，保留原回程技能的 1 秒冷却。聊天/TextEntry 输入、模态窗口、旧箭塔销毁确认窗、未准入或本人失败时不触发这两项操作。输入仍走唯一 dispatcher，旧 Workshop 上下文不会重新注册出第二条动作。

## 回程调用与落点

1. `ui_bootstrap.js` 提供 `SurvivalBuilderSelection.Select/CanSelect` 和 `SurvivalShortcutGuard.IsBlocked`。
2. `combat_stats.js` 提供 `SurvivalReturnHomeInput.Request/CanRequest`。请求 `ui_return_home_request` 的客户端载荷为空对象。
3. 原 `ui_request_router.lua` 使用引擎注入的 `PlayerID`，检查准入/失败状态，以 `HERO_SUMMON_GET_REQUEST` 找本人的正式英雄，走 `CastAbilityNoTarget` 正常施法与冷却。
4. `hero_return_home_service.lua` 再次核对本人正式存活英雄；复用 `hero_summon_destination.resolve(..., moving_unit)`，按玩家而非队伍查找本人存活且已建成的主城。
5. 在主城旁半径最多 640 的同层范围寻找落点，使用英雄实际碰撞半径（至少 32），避开建筑、隐形城墙、不可通行地面与英雄禁区。移动对象不阻挡自身。
6. 缺少主城或没有安全落点时提示失败；移动成功后才发送原训练房退出、`HERO_RETURNED_HOME` 和镜头事件，保持现有挑战退出及再次挑战流程。

本次未新增客户端事件或冷却规则，未修改 CSV 数值。
