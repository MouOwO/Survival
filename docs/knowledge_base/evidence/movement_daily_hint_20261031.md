# 开局移动卡顿、每日奖励提示与复杂度规则｜2026-10-31

用户确认在线建造者卡顿主要发生在进游戏的一两分钟，并要求将禁止反复大规模遍历、必须分析复杂度写入持续协作规则。本轮为开发代码修复，尚未另发游廊或部署后台。

## 原因证据和修复

现有原生日志 `offline_20261031_024503_370989.log` 记录 188 个不同头像场景在 10:45:53–10:46:30 连续加载，READY 时间跨度 37 秒，单个报告加载中位 189.5ms、最大 357ms。它与用户反馈的开局时间段吻合，但不是线上帧率归因实验。

- 场景控制器原来在 Prepare/Hide/身份解析中反复扫描全部缓存；满缓存稳定头像 300 次刷新写入 114900 次样式。改为资产/模型/场景键索引、直接可见节点引用、去重链式队列及计数，稳定成本不随 188 个缓存增长。相同测试只剩第一次遮罩收起时一次样式写入。
- 后台场景完成后间隔至少 500ms；复用现有调度检测选中单位位置，移动期间不发起新的非选中场景加载，连续静止 250ms 后恢复。已开始的工作正常收尾；当前选中冷场景立即抢占。188 场景仍可最终预热，官方背景遮罩及 100ms 稳定显示规则保留。
- 技能主/查询双树改为按真实容器身份缓存槽位索引，重建/销毁/换选中时失效；仍检查真实技能与原生键位变化。相同样本递归查找从每次24201降至975，余下为技能槽小子树的实时标签检查。稳定刷新不再反复递归搜索整棵 HUD，QWER 清理、查询树、64 槽与原生重写修复保持。
- 收尾核对发现另一批原生头像节点缓存修改与已编译版本不同。原件已备份，整合时保留有效节点缓存，并补齐负查找重试、缺查询头像恢复及完整祖先链脱离失效；行为trace与此前已验证版本逐项相同。稳定隐藏只需一次根部清理查找，晚到头像不能永久隐藏；重新同步编译后验证。
- 建造网格原本用模拟时间 `Time()` 判断同步回调的 2ms 预算，同一回调内时钟固定会使预算失效。新增 `core/performance_clock.lua`，预算和诊断均优先读取真实 `GetSystemTimeMS()`，独立 Lua 回退 `os.clock`；TTL/玩法计时保持游戏时间。分批输出及实际建造判定不变。

独立服务端计数没有发现裸移动执行全图扫描或 HTTP：1000 条 move 为 3000 次实体解析/2000 次 modifier 查询，合法区域 guard 不 Stop/传送。不要把建造预览的条件扫描或开发版活动深拷贝当成已证实的线上裸移动根因。被动采集当前暂停本地局的 12 秒 scheduler 为零 tick，不能作为 CPU 性能验收。

## 每日奖励入口

在真实左上角 `HandoffNav_benefit` 使用静态暖金光。只消费 `survival_daily_snapshot` 的已确认可领取状态，涵盖普通/月卡签到和手动日/周档位；自动发放及公测独立弹窗奖励不提示。还有任意一项可领即保持，最后一项持久化确认后熄灭；提交/pending/失败不能提前假装领取成功。未准入或状态未知不亮。

准入完成后最多三次、间隔五秒的初始化读取，成功后沿用服务端推送；HUD 读取缓存布尔值，仅变化时切 class，不增加高频奖励轮询、动画计时器或奖励规则。
