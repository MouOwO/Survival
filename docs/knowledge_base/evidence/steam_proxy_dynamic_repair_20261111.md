# 2026-11-11 飞鸟动态端口与 Steam 登录中转恢复

## 现象和原因

玩家删除账号信息后重新登录遇到 `steam_verification_unavailable`；手动执行“修复Steam登录”后仍失败。该工具的安全摘要为 `STEAM_TRANSPORT_UNAVAILABLE`，显示云端 web 健康、TLS 中转配置开启、18768 监听存在，但官方验签探针失败。本机和云端中转之间 TCP 可建立，TLS 握手超时；本机直连 `steamcommunity.com:443` 的 IPv4/IPv6 都超时。旧 SSH 中转直接连接 Steam，不能使用飞鸟本地 HTTP 代理。旧环境里的 `HTTP_PROXY=127.0.0.1:7890` 已无监听。

用户说明正在使用飞鸟代理，当前端口 `20874`，端口可能变化。实际只读核对：飞鸟 `core.exe` 同时监听多个回环端口，`20874` 可完成 HTTP CONNECT 和 SOCKS5；使用 HTTP CONNECT 向 Steam 官方 OpenID 端点发送不含账号的无效断言，收到 HTTP 200、官方命名空间和 `is_valid:false`。另一个监听端口不能完成此验证。没有读取代理账号、玩家断言或会话令牌。

## 修复

增加本机 Steam 专用桥接器 `tools/workshop_test/steam_proxy_bridge.py`，仅监听 `127.0.0.1:18770`。原有固定、主机密钥锁定的 SSH 反向转发仍只在云端 `127.0.0.1:18768` 监听，但本机目标改为桥接器。桥接器从当前 `core.exe` 的回环监听端口里验证 HTTP CONNECT，仅连接固定的 `steamcommunity.com:443`；传递的仍是加密 TLS 字节。云端 `player_web_auth` 继续对官方主机名、SNI 和证书做验证，认证规则和服务器代码未改变。缓存成功端口；旧端口关闭后下一次请求立即扫描并选择新端口。SSH 旧命令只作为精确匹配的迁移停止目标，其他 SSH 仍不可停止。

桥接器有单进程回执和精确 PID／创建时间／镜像／命令身份校验，最多 8 并发、每方向 256 KiB、20 秒空闲超时。飞鸟停止或节点不能访问 Steam 时失败关闭；本机和代理需要持续在线。此方案不提供公开服务的可靠运行保证。

## 验证与交付范围

- 30 项隔离测试通过，覆盖旧中转安全迁移、动态端口失效后重新发现、仅从飞鸟进程回环监听选择候选、固定 CONNECT 目标、代理认证／重定向拒绝。
- 本机桥接器真实端到端无账号探针：Steam 官方证书校验通过，HTTP 200，官方返回 `is_valid:false`。
- 切换后云端正式验签探针：`steam_transport_ok=true`，`invalid_assertion_rejected=true`，web health 与监听均为 true；手动修复回执为 `RELAY_RESTORED`。
- 用户关闭旧授权页并重新打开后，回复“已能登录”。未重放旧回调、未代用户消耗券或更改账号资料。

性能成本：无游戏帧循环或定时扫描。首次请求／旧端口失效时各读取一次系统进程与 TCP 监听表；本机只读实测 TCP 表 14,160 行、`netstat` 一次 178 ms、候选数 4，最多检查 8 个。稳定连接只向缓存端口建立一次 CONNECT，O(1) 时间和空间；端口变化为 O(L+P)，L 为当前系统 TCP 表行数，P≤8。8 个并发上限。网络握手与本机代理时延属于登录路径，不能等同于游戏 FPS。

本轮只改变本机辅助工具和说明，未修改游戏客户端运行资源、云端认证服务、账号数据或游廊包。当前游廊仍为 `2026111102`，Steam manifest `7805846272729005356`；后台 WS4 和 web auth 均未部署新版本。
