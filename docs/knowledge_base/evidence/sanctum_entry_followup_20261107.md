## 原因和修复

自定义技能栏将 `ability_enter_endless_training` / `ability_enter_shadow_realm` 交给 `ui_ability_cast_request`。原 router 对祭坛召唤已有直达分支，但传送仍走建筑 `CastAbilityNoTarget`，随后立即回复“成功”，没有确认 OnSpellStart 或业务执行。与其相邻的既有代码已经记录这种建筑技能可能只接受指令、未执行 OnSpellStart。相同完整 router 测试模拟此原生边界，旧源码确实回复成功而训练服务调用为 0；当前游戏日志没有捕获到该用户点击，不能写成已在本局观察到此原生失败。

现在两个传送技能使用服务端固定映射直接调用同一个 `training_room_service.enter`，不接受客户端 action、价格、目标或其他玩家身份。保留所有者、当前祭坛实体及实际技能绑定、caster、技能等级、激活、隐藏、被动/点施法、冷却和玩家准入验证。只以真实服务 `ok == true` 回成功，失败发一次既有 UI 通知并退回本次启动的冷却；被拒绝的冷却中请求不会清除原冷却，也不回退到原生重复施法。

原训练房入场预检始终使用原价 50000 + 首秒预留 50000，但实际扣费对持有长青轮纹者打 75 折，所以 75000–99999 金币被误拒。现在一次读取自己的权益，使用同一实际入场价/每秒价进行预检、扣费与提示；保留原“入场费 + 首秒预留”规则。英雄仍需 10 转。无轮纹最低 100000（入场 50000，首秒 50000），有轮纹最低 75000（37500 + 37500）。不足明确显示“金币不足”、实际所需和当前金币；资源未就绪不冒充余额为零。资金不足检查先于场地查找，不再被落点错误遮住。

事务顺序为资金/资格检查 → 校验场地 → 准备新目标 → 成功传送 → 实际扣费 → 替换训练状态。目标初始化、传送 false/抛错或实际支付拒绝时清理新目标并恢复原位置，旧训练目标、倍率及费用任务保留；失败不收取入场费。不用回城服务做回滚，避免误退出已有房间/挑战。旧目标删除有异常时使用原生 RemoveSelf 清理，不能将已完成付款误报失败。每玩家短暂防重入，所有返回路径释放；旧费用闭包发现身份不符直接退出，不清除新房间。原生回滚和两种移除接口同时失败只能尽力恢复，不承诺绝对原位。

## 成本与验证

静态入口映射初始化两项，O(1)。每次点击 O(1) 固定映射、当前实体/技能身份检查，至多一次训练服务调用；稳定未点击成本为 0。删除这两入口原来的原生再施法和 0.1 秒诊断任务，没有新增计时器/场景扫描。成功仍一个既有结果回包，失败一个结果加一个既有通知；低频点击反馈不冒充高频 <=50B 状态流。

训练入口按玩家 ID / action ID 索引；命名场地和落点查询次数有界，不遍历整个地图实体。一次 resolve 的场地数据供入口、目标、半径共用，避免旧代码的重复 resolve。新增防重入空间 O(P)，P<=4，调用结束释放；房间状态同样每玩家一份。沿用原每秒扣费任务，每活跃房间 O(1) 状态/距离/本玩家余额处理，没有增加频率。折扣使用既有权益查询，没有发网络请求或扫描场景。
