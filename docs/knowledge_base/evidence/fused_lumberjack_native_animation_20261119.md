## 原因与处理

普通伐木工参考 BAT 为 1.5 秒，原生攻击动画点为 0.75 秒。原合成路径仅缩短 BAT，没有按真实攻速缩放原生动画。原生对照中目标间隔 0.35 秒，但实际 AttackStart 间隔约 0.7667–0.8 秒，前摇约 0.7667 秒。单独切模型、模型缩放、攻击伤害或攻击上限 modifier 均未造成命中时重置 sequence/cycle，不能据此归因。

修正保留普通 BAT，通过合成专属原生百分比攻速 modifier 表达原有最终间隔，交给引擎同步缩放完整动作与前摇。不添加逐帧动作重启、攻击指令或序列覆盖。普通伐木工路径保持现有实现；科技、个性、合成与 UI 的最终间隔计算继续使用原公式。

设普通参考间隔 B、已有最终间隔 T、已有原生百分比攻速合计 P，比例 r=B/T；本 modifier 增加 `(r−1)*(100+P)` 百分比。现有固定 IAS 及百分比来源继续生效，原生攻击周期等价于旧属性公式。助威、肉鸽伐木攻速和 managed buff 的百分比源按 modifier 身份增量维护，加入、数值变化与销毁时更新，兼容同一实体合成前已有 buff。肉鸽敌人减速只施加到波次/挑战怪，英雄被动减速走敌对目标，塔专属 modifier 不属于伐木来源。

本轮发现旧全局上限 modifier 的忽略上限回调名称不符合当前引擎。只在新增合成专属 modifier 声明 `MODIFIER_PROPERTY_IGNORE_ATTACKSPEED_LIMIT` 并实现实际官方二进制存在的 `GetModifierAttackSpeed_Limit`，未扩散修改英雄或防御塔全局行为。热重载曾保留旧 native 声明，故以全新进程冷启动结果为准，不以热实例的失败结果冒充通过。
