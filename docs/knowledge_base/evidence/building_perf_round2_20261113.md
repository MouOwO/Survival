# 多建筑性能第二轮：范围查询、生命周期与原生测量

本轮按用户要求继续检查模型尺寸、调用热点、尸体/粒子生命周期、循环复杂度和距离计算。后台与付费数据不改。所有诊断夹具、日志、回归与原始帧时间保存在树外 `D:/Survival_本地工具/runs/building_perf_round2_20261113`。普通游廊验收与离线 Tools 测试须分开陈述。

## 已修复路径

1. `wall_melee_queue.lua` 的间距检测原来对每个候选遍历全部预留记录并开方。现在按128单位网格覆盖每个预留身体的包围盒，只访问候选周边网格；同一记录跨格去重，真正碰撞仍按原阈值精确判断。释放、死亡补位、实体ID复用和位置晋升同步维护索引，空格立即删除，城墙搬迁/重置释放旧队列。
2. `wall_melee_contact.lua` 的范围、到位与身体间距阈值改为距离平方；严格/非严格边界分别保留。实际导航长度、归一化、`距离+容差` 等运算仍保留必要开方，不能把它们直接替换为平方。
3. `worker_system.lua` 的树枯竭事件直接按攻击者 entindex 获取已有工人索引，并核对对象身份，替代全工人查找。
4. 血条客户端维护存活键与位置索引，收到死亡/移除包立即释放面板和引用。全屏遮挡只在进入遮挡时隐藏一次；新的面板默认隐藏。移动单位和镜头的存活血条仍逐帧投影，保持原有跟随效果。
5. 金矿只读取永久奖励中所需的5个字段，避免每次产出和重排任务复制完整权益、显示快照及聚合无关玩家。读取仍来自当次权威数据，不引入过期缓存；收入、暴击、分数累积与间隔算法未改。
6. 原生Tools发现轨道炮回调 `GetIntellect()` 缺少当前绑定要求的布尔参数，会使回调失败。改为 `GetIntellect(false)`，同时复用已有护甲字段查询，保持原伤害、目标、持续时间与先前移除占位塔的结果。

## 定向回归

`source_regression.json`记录17组定向检查及源码摘要，包含三个旧源码负对照：旧血条累计死亡行、旧完整权益查询、旧轨道炮参数均按预期被拒绝。现有几何/墙接触、四玩家权益生命周期、纯净模式永久奖励、金矿免费/付费升级、工人训练、血条清理和粒子重复清理检查通过。离线测试的开发身份桩仅在独立Lua进程中生效，不改生产准入。

实际生产后排函数跑同一60/90单位回归：记录检查1,003,764→94,820，18,125个返回目标及滚动摘要551760066一致。计数器自身有开销，CPU秒数和次数都不能写成实机FPS。另以4玩家各1万项无关效果执行4000次金矿查询，无无关字段遍历，验证即时更新、返回值隔离和独立字段状态。血条验证1000条死亡快照不进入活动遍历、1000次持续遮挡不重复写隐藏，复活/容器恢复/换局停止仍正确。

## GPU模型尺寸对照

在同一个纯内存Tools局，19建筑、30伐木工、6融合工人、42UR权益、第16波。固定镜头，暂停消除战斗变化，只修改19个建筑的 `SetModelScale`，随后全部恢复。截图确认视觉尺寸确实变化。三个独立20秒样本的GPU忙均值：原尺寸14.4462ms，半尺寸14.3555ms，恢复原尺寸14.2519ms。恢复比半尺寸更低，差异在本轮漂移内，没有可重复的GPU收益。不能以暂停局证明运行时FPS改善；工具宿主存在60Hz合成/等待。

`gpu_scale_restored`因丢失前台未完成，另一次焦点准备因PowerShell5.1中文脚本编码被拒绝，均保留；显式核验唯一Tools窗口并激活后，`gpu_scale_restored_verified3`完整20秒通过前台核验。有效样本分别使用自己的CSV/回执，不拼接失败采集。

几何尺寸缩放不会直接减少网格三角形、骨骼或材质批次；资源包压缩也不等于降低渲染成本。应按真实GPU热点处理LOD、材质/阴影、贴图驻留及粒子覆盖，本轮不直接缩小正式模型或压低全局画质。[Unity官方LOD说明](https://docs.unity3d.com/Manual/LevelOfDetail.html)与[平方距离优化建议](https://learn.unity.com/course/performance-and-optimisation/tutorial/fixing-performance-problems-2019-3)作为方法参考，不能冒充Dota实测。

## 对象生命周期与分析工具

现有尸体服务已经停粒子、保留短死亡表现、下沉、隐藏、移除。真实隔离样本对70个带尸体标记实体执行ForceKill：12秒时剩1个有效句柄，后续对场景复核该标记实体为0；脚本UTIL_Remove插桩调用0，未复现脚本集中销毁峰值。该样本不能证明所有单位类型无泄漏，也不支持把真实战斗NPC批量藏到永久池中。隐藏本身不验证AI、碰撞、奖励、网络和修饰器已释放；将销毁集中到同一帧还可能制造峰值。如未来测到该热点，应立即解绑玩法与视觉，用有工作量/真实耗时上限的队列逐步回收，并验证重用状态，而非无限缓存尸体。[Unity对象池官方教程](https://learn.unity.com/tutorial/use-object-pooling-to-boost-performance-of-c-scripts-in-unity)也以明确复用与容量上限为前提，不能直接套用其GameObject生命周期。

本机已使用Source 2 VProf/VConsole、现有 `survival_perf_capture` Lua调度汇总、客户端函数探针和PresentMon/NVIDIA指标。它们分别回答原生调用树、Lua任务累计/最大耗时、JS次数与耗时、CPU/GPU帧时间，须区分包含时间和自身时间。探针只在Tools显式开启，正式游廊不持续打印或插桩。十进制无限小数并不会自动增加浮点乘加指令成本；不通过随意取整改变资源、伤害或几何语义。
