# 十戒每层胜利后回城：源码修复与待验范围

本轮仅本地源码更新，后台未改。用户要求击败十戒后英雄回城；当前仍保持用户操作中的0704及只读监测，不热换Lua、不编译/签包或切换安装。原游廊仍2026110104 / manifest `7025356658517360342`。前两轮单位快切、剑圣Q视觉及说明修复已提交推送，但尚未进入当前运行包。

## 行为与来源

十戒对应 `challenge_11` / `encounter_challenge_11`，按深渊审判+N选择第N+1个Boss，每次个人session只有一个成员。因此用户要求落实为每层胜利后的回城，不能只在第十层补一个传送。

原CSV的 `completion_teleport_policy=reset_to_stage_entry` 使成功升阶后个人session等待1秒，再加入并传送下一层。本轮CSV及配套生成Lua仅将这一个字段改为 `return_home`，11个配置中的其他字段完全不变。生成使用 `tools/build_configs.py:build` 单表入口并核对无额外投影漂移；回执 `output/ten_sin_return_0704/config_projection01.json`。

当前层授权击杀时，在奖励同步回调前捕获该玩家正在前台十戒中的正式英雄。材料成功结算、个人session完成后，再验证相同session、前台挑战、存活且仍是同一个正式英雄，然后复用 `hero_return_home_service.return_unit`：回到自己的主城安全落点，沿用已有落点校验、回滚、特效和镜头；不传送建造者、分身、替换后的英雄、其他层或已离场的人。

个人胜利session现在直接完成，不再排下一层自动进入任务。仅清前台标记还不够：旧回调依然会将回城者加入下一层共享Boss，导致其留在家中也可能继续获得队友的下一层击杀奖励。新逻辑要求再次主动进入后才重新订阅、获得下一层奖励资格。全局共享Boss的1秒重生及其他挑战的原策略保持。

费用必须保持：旧自动续层不再次扣费，而只把个人session改为completed会让商店误走新购买、再扣10万木材。采用单独的服务端 `resume_without_charge` 待续层资格，个人挑战仍是completed、不在任何下一层Boss参与表中。商店显示与购买分支读取同一服务器资格，主动成功进入后由新session替代旧资格；失败则保留。第一次进入、其他玩家或第十层已完成不能伪造该资格，转生付费分支不变。

特殊失败保护已向用户说明：材料合成失败可能保留在Boss地面，同时本层已被通关锁定，直接传走会无法取回。因此该次保留英雄在现场和原错误提示，不自动重发/重试奖励；主城缺失、落点阻挡、死亡或英雄已换等情况由现有安全条件拒绝回城。回城失败不回滚已成功的材料/武器进度，也不恢复自动加入下一层。某位玩家原生传送异常不应中断同场其他参与者结算。

## 成本与验证

新增逻辑只在真实死亡事件触发，沿已有共享Boss当前参与者列表处理，最多4人；每人固定次数的session/正式英雄检查及至多1次现有回城调用。初始化无新扫描，稳定期无新定时器/轮询或消息；原有本地回城落点解析成本继续复用，不能将整个落点查找误报为O(1)。原个人下一层等待任务被取消，全局Boss重生仍由已有索引与调度器负责。无云端HTTP、奖励概率或奖励数量改动。

`test_shared_challenge_bosses.lua`、`test_challenge_respawn_pacing.lua`、`test_hero_return_home.lua` 三套通过，前两套也经独立复跑。覆盖全部10层、同Boss多参与者/异层/未参与者、重复死亡及实体复用、死亡/英雄更换/切房、材料保留、回城失败、不自动进入下一层或领奖、失败重进保留免费资格及成功重进后消耗；原全局1秒重生、其他挑战策略保留。最新回执 `output/ten_sin_return_0704/service_regression02.json` 绑定最终源码，01版证据保留不冒充含费用修复。

本人主城回城整套测试覆盖同队异城、错误归属/分身、无主城、阻挡、落点回滚及视觉失败不影响成功。该测试最初因当前正式Steam准入拒绝伪造玩家ID失败，现仅在测试进程预置测试配置，不改生产准入配置或原断言；不能把该初始失败写成实际回城逻辑故障。额外旧 `test_player_challenge_cleanup.lua` 仍引用已移除的 `challenge_11_prepared_by_player` 测试上值，导出本轮修改前的Git基线实际复跑也同样失败；原输出及基线摘要保留在回执，本轮未扩大重写它，也不声称全仓测试全部通过。
