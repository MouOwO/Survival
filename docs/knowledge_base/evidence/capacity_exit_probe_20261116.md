# 五分钟集中退出实验（默认关闭，未部署）

按用户最新指令：全部2000账号就绪并持续业务5分钟后集中退出；准备与登录时间另计，原30分钟与2小时作为最终回归，当前先快速对照。新probe由现有5秒成功业务观测触发，复用已经签名写出的同一次快照，额外15秒仅覆盖原公共活跃证明的端点与采样余量；Locust duration是安全上限，未全员活跃不得提前退出或替换失败账号。

真实Locust负对照发现旧入口保护只能避免新的活动请求，仍会因延迟kill打断on_stop。新CooperativeTaskSet复用每用户Event；正常stop只设置STOPPING并唤醒等待，不注入kill；运行中工作流完成后进入真实final checkpoint/release。强制停止和原45秒清理预算继续保留。回归执行实际TaskSet/User/stop方法，并核对清理开始数、完成数和中断数，不能把进入on_stop当作清理完成。

显式对照：direct、0至3秒确定性错峰、32/64/128槽协程队列。均在原清理总预算内；队列和延时计入同一全局退出意图起点的finalization耗时，不提前记成功、不盲重放写入。它们是隔离客户端原型，未部署到真实服务器；服务端持久队列另需可靠入队、幂等和恢复验收。

复杂度：每用户初始化O(1)、一个Event；稳定等待O(1)替代原sleep，无新增业务HTTP或SQL。停测每用户O(1)状态/事件，不额外遍历账号；排队/错峰每次退出O(1)，信号量上限128，存在原45秒总截止。观测仍每5秒一次，复用snapshot，增加O(1)条件；达到完整活跃证明后只触发一次quit，无新轮询。最多10000用户的Event空间O(N)有界。服务器运行文件、鉴权、奖励和SQL正确性门保留。

前轮2000共同活跃1895.382秒，261417完成HTTP/394错误；退出1530完成、394失败、76清理中断，SQL在线470，原失败保留。新监听队列令退出期间Host ListenDrops增量归零；单SSH/四SSH小回包原生组件均2000成功，四SSH更快但不能据此认定全部真实超时来自通道。继续分离清理取消、请求排队、回包体积与事务处理成本。
