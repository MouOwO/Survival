# 波次怪不攻击城墙：原生复现与修复｜2026-10-31

用户报告原游廊常规 N1 怪物不攻击城墙，要求检查全部模式并同步之前未发布的优化。官方未缓存查询确认当时仍为 3004 / item `3824360109`；尚未发布本轮 3101。

## 两个独立根因

1. `wall_melee_contact.resolve` 在距离城墙超过512、已经有合法前排路径时，错误给首次抵达者分配后排等待。原生 N1 单怪停在距离641的合法后排点，16个前排接触点仍真实可达、前排无人；它再也进不了512范围取得攻击位置。
2. `modifier_enemy_wall_ai.OnCreated` 对正式波次关闭 `SetIdleAcquire`。原生 fresh actor 在已前排锁定、未缴械且目标合法时仍没有原生目标/攻击记录；仅修改获取半径0/128/600均无效。另一只全新正式怪仅开启该标志、仍保持半径0，就出现原生目标和持续伤害。fresh 对照不使用 PerformAttack，避免混入强制攻击或热身目标缓存。

正式修复：首次远距抵达沿已验证路径继续原生移动（`routing=true, claimed=false`），进入512后才由原分配器实际申请前排。保留已有真实后排预约、碰撞、四面各4容量、路径预算和墙移动失效。正式波次启用原生获取标志，但搜索半径仍为0；原指令/反击/伤害三层只能攻击城墙的规则保持。

发布前又复现一个关联边界：已有后排点超过512时，即使前排死亡出现真实空位，仍不能回圈补位。最终contact修复按实际地形合法空key决定继续routing，并保留后排记录直到真正前排claim才释放；空位结果按状态revision与位置缓存身份共享，稳定O(1)，不因远处多个演员同时清队列而放大扫描。部分地形实际只容3个且已满时继续保持原等待。1个/4个前排死亡补位已加入完整运动回归；最终原生回放单独验证此后续边界，不把下面较早的四模式数据冒称为该最终代码的重新实测。

没有放宽攻击过滤、模式区域或门禁，没有瞬移怪物、缩小碰撞体或制造第二层目标来掩盖错误。测试准备允许移动建造者和提供本局内存资源；修复后验收没有手动移动怪物、修改 idle/acquisition 或 PerformAttack。
