# 一转挑战误报商店页（2026-11-09）

## 已确认的原因

用户在已发布 0901 普通游廊客户端右键一转挑战，原生提示“该内容不属于商店页”；关闭挑战面板重新打开后即可挑战。当前进程未启用 `-vconsole` 或 `-condebug`，发现的 `game/dota/console.log` 停留在 10 月 24 日，未将它冒认为本局日志，也未向游戏发送购买、控制台或注入命令。

该文字来自 `shop_catalog.allowed_in_mode`。原购买请求仅携带商品 ID、请求 ID 和研究所实体，没有当前页面；服务端从可被关闭/回收的 `opened_players` 推断模式，缺失时默认 `shop`。因此前端仍显示挑战卡片，服务端却把转生项送入商店分类门禁，拒绝发生在实际扣费和召唤之前。截图和用户重开结果证实页面失步；本局具体是哪条清理路径触发，没有实时日志直接复原，不声称已观测 CW 断连。

## 修改

现用 `shop_remaining_5d5c1152eb.js` 和备用 `shop_ui.js` 的购买请求均携带 `mode: currentMode`，content 镜像配套。路由只转发页面字段，玩家身份仍从事件来源派生，不接受客户端冒充能力来源。服务端只允许 `shop`、`challenge`、`research` 三种明确页面，随后使用真实目录分类及原来的资源、建筑、英雄、转生、库存/冷却、收费和授予校验。旧调用未携带 mode 时维持原分支；购买去重仍使用原请求 ID。

页面只是操作上下文，不授予资源或进度，也不重建整个观察快照。显式研究页面同样保留目录分类检查；来自服务端研究技能和金矿技能的既有分支不变。
