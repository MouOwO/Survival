# 怪物动态头像与饰品修复（2026-10-30）

用户授权：先把一个怪实机修好，再推广其他野外怪；允许离线验证，完成后更新原游廊条目。此决定替代 10/29 仅用原生 NPC 头像的临时回退；我方剑圣保留现有独立头像处理。

## 已证实的原因

- 世界饰品是跟随骨骼的独立 `prop_dynamic`，NPC 原生头像未把这些附属实体一起渲染。换成 `dota_item_wearable`、Creature.AttachWearables 和对原生英雄调用 ReplaceEconItemSlot 的离线试验均未解决，已恢复原单位 KV 和世界换装逻辑。
- 旧 ScenePanel 在等待 SceneLoaded 时先隐藏了父容器，实际引擎因不可见而不能完成首次加载。正式渲染器先让容器可见，再等待场景与背景加载完成。
- 官方材质引用的纹理直接用于 Panorama Image，实机呈浅粉白色。对原纹理无损解码、以 BGRA8888／无 mip／无 LOD 的 UI 纹理重新编译后，原月亮墓园等背景正常；不是重绘背景。
- 部分模型没有字面名称 `idle`。生成器读取实际编译模型 ASEQ 活动映射，选择原头像活动对应的真实序列并循环，饰品随同一骨骼播放。
- 清除背景颜色时空字符串会触发原生背景色解析错误，已改为有效透明色。

## 最终实现

`tools/build_monster_portraits.py` 从现有 asset_catalog／asset_components／asset_activity_modifiers 生成正式背景场景。身体、皮肤、组件模型及父子骨骼关系取世界配置；镜头、灯光及背景纹理取本机 Valve `scripts/npc/portraits.txt` 和安装 VPK。纹理解码使用 Source2Viewer CLI，可通过 `--texture-converter` 指定工具。

覆盖 97 个外观身份（默认怪物饰品组 91＋指定挑战怪 6），去重为 88 个背景场景、24 张原背景。game 保存可读场景源、清单、UI 源与编译资源；content 保存二进制可编辑 vmap、PNG／VTEX 和 UI 配套源码。生成器 `--check` 检查一致性，`--compile` 配套复制和官方编译。

`monster_portrait_renderer.js` 用原生 DOTAScenePanel 渲染完整身体和组件，使用官方镜头参数、不套防御塔放大倍率；最多保留 3 个场景，稳定身份复用，选择切换隐藏旧场景，加载超时回退原生头像。正式路径不调用 SetUnit 覆盖地图中的完整模型。服务端权威 model_asset_id 与当前选中实体一致时才启用，晚到快照不能替换我方英雄。原生输入层与我方剑圣特殊处理保持兼容。

背景采用原纹理像素；不额外模拟 Valve 材质的四角颜色混合和粒子背景。不要把原生相机参数与完整原生 NPC 头像渲染链混为一谈。

## 实际验证

- 正式资源：88 个地图＋24 个纹理由 Valve 编译，112 项均 `0 failed`，配套 5 个 UI 文件编译通过。
- 离线真实客户端：97/97 身份的 ImageLoaded＋SceneLoaded 均通过；十转怪逐个通过真实单位选择事件绑定底部头像；饰品、原背景和特殊模型有实际截图检查。
- 同一个静止展示单位的头像区域两帧有 6194 个像素变化，确认动画播放；这不是静态头像替代。
- 自动回归覆盖 97 个真实配置身份、稳定复用、首次可见加载、3 项缓存上限、超时、重建／热重载、释放句柄、迟到快照、多选和我方剑圣。旧原生回退、建造者、左上英雄头像与回调生命周期回归保持通过。
- 原始私有测试记录位于 `output/rebirth_native_20261030/verification.json`；十转整组图与底部头像图留在同目录。所有临时测试面板及试验地图／背景已经从正式资源路径移除，测试入口不随包发布。
