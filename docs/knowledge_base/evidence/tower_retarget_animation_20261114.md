## 原因与实现

隔离 Tools 中原生记录确认，死亡事件重选目标后，引擎在下一次允许攻击前短暂进入 idle_anim。削减重复攻击指令没有消除该动画间隙，因此最终不包含指令合并方案。也未采用改变 BAT、出手点、播放速率或反复重启动作的方案。

只为 class_1 暴击塔保存已经出手、尚未结束的 attack01_anim / attack02_anim 后摇。相关目标死亡并找到后继目标时，延后 2.5 个引擎帧检查一次：仍为原塔、原世界、原模型和有效攻击目标，尚未开始新攻击、旧后摇未结束且当前确为 idle_anim，才各调用一次 SetSequence / SetCycle，按真实经过时间续接原相位。回调始终返回 nil，不轮询。不续接尚未出手的前摇；新攻击、再次重选、idle、销毁立即使令牌失效，目标死亡/出范围、缴械、模型/世界变化、超时或时钟回退均放弃。

攻击目标优先级、原有 SetForceAttackTarget / MoveToTargetToAttack 链、攻击间隔、出手点、伤害及特效均保留。诊断采样器、录屏、控制台探针和测试夹具不加入运行代码。

## 成本与风险

初始化 O(1)，按单塔当前模型最多缓存两个动画时长；销毁清空，模型变化重建。稳定同目标攻击路径不增加动画原生读取、计时器或视觉写入，只清空一个 Lua 令牌字段。相关击杀换目标 O(1)，最多一个单次延迟回调、一个待处理上下文及一次 SetSequence/SetCycle；无场景遍历、网络或粒子创建，也不改变原有 0.25 秒 AI 调度。

首次合格击杀读取 sequence/cycle/model/world/time 和一个动画时长，模型两种动画缓存命中后不再读时长。回调只作定长实体/世界/目标与时间检查；目标合法性沿用 targeting.valid 的平方距离检查，无范围集合查询。Lua 定向夹具验证 10000 次稳定更新新增动画查询/计时器/视觉写入均为 0。测试调用计数不能代替 FPS；单次回调原生计时约 0.0364 ms，只说明这一次路径成本，不能承诺所有战局帧率不变。未加入高频监控来证明帧率。

单次延迟检查可能错过更晚的原生 idle；此时放弃续接，保持原战斗行为。若击杀发生在下一次尚未出手的前摇中也主动跳过。未来模型动画名或引擎行为改变时需要新实机验证，不扩大到其它塔或所有动画。
