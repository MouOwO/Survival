# 120秒渐退现实场景（默认关闭）

仅本地候选，正式后台及游廊未部署。用户保留2000人集中退出目标，并增加更贴近实际的2000人在120秒逐渐离开场景；平均约16.67退出/秒不等于容量承诺。四通道集中退出实测仍独立保留，不能用渐退通过代替集中退出通过。

新--exit-smoothing gradual120-v1需显式四通道、容量client-v3和完整共同活跃证明。全部就绪并成功业务5分钟后，取得一次本次拥有的完整用户集合，由一个协程按个人预定时点逐一调用正常退出；尚未到时的玩家继续原活动、读档和周期存档。真实2000人窗口固定120秒；两账号原生校验专用2秒窗口，不能称已覆盖120秒容量。

每人的finalization从自己的预定退出意图计时，含当时在途工作、最后存档、奖励后读及会话释放；45秒总截止不延长。整个群体120秒窗口另记first/last实际意图偏移与最大调度迟滞，不混成同时点击的端到端耗时。最后一人完整收尾后才发起全局退出；提前全局停止会取消唯一协调协程并保留失败，不能把未完成波次记成功。

复杂度：初始化一次O(N)拥有用户快照和O(N)有界引用；一个协调协程按索引执行，状态变化每人O(1)，没有定时重扫用户集合。稳定请求路径新增HTTP/SQL/扫描均0；结束取消一个自有协程，旧回调不会跨用例。最多4000目标受原容量限制。2000假时钟调度验证实际生产协调器只枚举一次，首末个人意图相差120秒；真实Locust两用户调度证明首人结束后另一个继续业务，提前取消和45秒超时禁止新写入均已通过。模拟计数不等于实机FPS或线上容量。

本轮只有cli、guard和locustfile三份operator运行源码变化，游戏、后台业务、奖励和SQL保持父版。6项新配置负例和4项真实/规模/取消/截止回归通过；完整相关回归与两账号原生、2000真实渐退仍需最后验证。可靠后台异步退出队列并未由本候选实现。若正式采用延后结算，必须先持久化稳定退出请求并确认，再有界消费与幂等恢复，不能仅把任务留在可能关闭的游戏实例中等两分钟。
