## 原因与改动

用户实测：首次打开存档仍卡顿，没有看到加载动画。此前 1004 只预取数据和固定外壳；176 行通关存档仍在第一次完整回包中同步创建、装饰，皮肤再次遍历条目。主线程忙时，已有 0.2 秒窗口动画没有机会绘制。

- 外壳、分类导航和首次选择装饰在启动时准备。入局认证就绪后沿原有 20 类本玩家预取数据，分批预建当前分类全部条目、其他存档分类首屏；当前目录为 320 张预建卡片，避免一次创建全部分类造成新的启动卡顿。收藏分类继续由原收藏控制器处理。
- 每批最多进行 2 行原生操作、最多检查 32 行数据，使用真实 `performance.now()`，不可用时回退 `Date.now()`；每完成一行检查 3ms 耗时预算。单行原生构建不可抢占，超过预算则该批立即结束，不能声称所有帧都不超过 3ms。后台间隔 50ms，前台首批让出 34ms，后续至少 17ms；其他窗口和按住鼠标时暂停后台，前台打开立即抢占。
- 按用户追加要求移除首开“正在读取／加载”等句子，冷打开只显示原生 CSS 转圈。首屏具备后移去大遮罩，其余条目继续静默分批构建；已预建卡片直接显示。各分类有独立容器，切换只隐藏旧容器、显示新容器，保留面板、事件、图标及滚动容器。
- 打开仍校准权威数据；相同完整回包不再重新显示加载遮罩或重建原生行。少量变化沿原有按 ID 增量更新。筛选、实际成员变化或大批数据变化才重新安排该页的有界构建。
- 皮肤装饰随单张卡片准备，前台提交不再扫描全部行。tooltip 与诊断使用当前页面直接引用，操作仍走原认证 intent。
- 修复首次回包早于启动预取时误清缓存、半途关闭筛选后后台接续模式错误；销毁、换局、同局认证会话替换和已取消回调均失效。工作队列结束即停止，无新增稳定状态轮询或 HTTP 调用。
