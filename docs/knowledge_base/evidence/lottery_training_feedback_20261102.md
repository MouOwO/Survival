# 游廊抽卡演出与训练提示（2026-11-02）

本轮只处理抽卡演出播放失败和训练容量提示的中文展示；共享 Boss、头像、D 技能、商品权益和后台支付均沿用各自原有验证边界。

## 现场事实

用户报告普通游廊抽卡“潮汐秘藏”全屏显示“播放时发生错误”。Root 的只读复核确认本机安装的是已签、未发布的 0201 测试包。其四段 WebM、抽卡 JS/CSS 六项实际 VPK 数据的 SHA256、MD5、CRC 均与签名 manifest 一致；四视频和 0104 对应资源也完全相同。该次本机故障不能归因为漏打视频。视频头是 WebM/VP9/Vorbis，头信息正确不等于原生解码成功。

旧播放器只捕获同步异常，实际异步失败仍等 7.05 秒 watchdog。已安装 Valve 原生 Movie 布局/CSS说明错误文字由 `MovieError` 类控制；不能仅凭二进制存在某个字符串，臆造可用的 JS 播放事件。原生视频错误的具体产生原因尚未由当前日志证明，也没有证明换资源 URI 或重编码能解决。

## 开发修复

演出仍优先播放原视频；异步错误时使用当前奖池既有主题纹理的原生动画，不再停留于黑色错误页。备用演出由固定少量面板的 CSS transform/opacity 完成，使用原始服务端已确认结果；不发送新抽卡、领奖或余额请求。关闭、跳过、替换演出及旧异步回调按代际失效，结果完成回调至多一次。

训练的 `training_queue_full`、`training_max_count_reached` 等稳定机器错误码原样漏到操作回执和通用通知。现只在两处已有展示边界补齐实际训练码及人口/名额/生成错误的中文映射，保留内部机器码及接收玩家。主城附近没有可通行空地原本已返回中文，不能把它写成新发现的英文泄漏。未知非训练错误沿用既有行为。

## 性能与验证边界

训练消息常量表初始化 O(C) 一次，每次真实错误 O(1)，稳定刷新无新增工作，没有新增原生或网络调用。演出仅轮询持有的单个 Movie 状态，演出外不轮询、不遍历 HUD 或场景集合；动画由原生 CSS 执行，不能把模拟调用计数称为 FPS 改善。

训练路由的双链参数化测试已验证中文、私有接收对象、稳定业务错误码及不增加请求。旧 `test_worker_system_training.lua:161` 在当前与不可变 037a4df 的 worker 模块下均失败，测试缺少已准入账号上下文；业务源码相同，失败不归因于本次文案。测试专用已准入上下文中的导航、扣费、退款、人口、回滚和队列检查通过，生产门禁未放宽。

最终演出回归、官方编译和 Git 同步以配套 JSON 的实际结果为准；开发源码与当前游廊安装包不是同一阶段。没有以单元测试代替新普通游廊的播放、画面或 FPS 验收，本轮尚未签新包或上传游廊。

JS/CSS 两项已通过官方编译，game/content 源码一致。七项演出模块场景、真实 ACK→异步失败→原生动画→结果卡片/单次反馈、十连布局及缓存更新回归通过。旧反馈测试缺少当前生产缓存模块和既有 hash 字段的测试契约，已修正测试并加实际失败流程；同一旧失败在不可变 037 的旧测试/旧播放器组合下也复现，没有修改领奖业务取绿。

## 原生预览实测

第二轮有效 Tools 离线实例为14292，HTTP关闭、存档仅本局内存，1600×900，暂停局。四奖池共12张早/晚/结束原生截图实际展示同主题淡入、缩放、光环变化，并收回演出层、回到抽奖窗口，券数保持0。普通夏季视频另有3张实际金门影片变化及正常结束截图；这是松散开发资源的播放，不能证明新普通游廊包的解码已通过。

Root另将此前未播放的地图视频在game/content两边临时改名，再调用同一个普通视频预览入口。原生日志08:19:49真实出现 `native playback failed; using themed presentation`，三张截图实际显示自动进入星门主题动画并正常结束；不是只调用备用演出预览冒充失败分支。`finally`立即还原两份视频，SHA256均与原始字节一致。该受控缺片实验验证了真实 MovieError→备用动画的通路，不证明用户原游廊故障也是缺片。

实际点击“跳过”在命令返回后661ms完成，早于3650ms自动结束时间，截图确认立即回窗；随后关闭抽卡窗口，截图确认遮罩清理、暂停世界可见。共20张有效截图有逐项路径、SHA和尺寸，只有稀疏阶段证据，没有逐帧流畅度或FPS结论。首次32636的三个视频截图属于已结算画面，明确剔除。Root正常关闭14292后另行确认进程不存在，未强杀；未抽卡、领奖、购买或兑换。
