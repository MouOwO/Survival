# 商城兑换码、服务器登记与运营Excel（2026-10-29）

用户要求：商城标题右侧加入兑换码入口，沿用购买按钮；简洁官方输入框及兑换/取消按钮；错误走官方提示。除VIP相关内容之外的商城奖品支持兑换，另有全奖码，信息写入服务器，Excel放桌面。

本地实现：`black_lion_market.js` 在标题右侧放置同款购买按钮，独立 `redemption_code.xml/css` 使用Valve原生TextEntry与ButtonPrimary规则。Valve的原始CSS不在本机content源树，所以复制经本机官方资源解码的相关控件规则，不直接依赖缺失的dotastyles.css源文件。三项Panorama源码已同步content，game对应运行资源由Valve编译器生成并检查新鲜度。输入校验、请求期间禁重复点击、取消关闭、迟到回包不重开、未知结果沿用原request_id与官方HUD错误提示均有交互回归。

游戏侧复用真实玩家的商城传输和权威档案应用。请求只含兑换码及请求标识，没有客户端奖品、价格、余额或账号字段。服务器独立协议强制真实对局session、规范化码后计算SHA256；不向客户端返回冻结奖励定义或内部operation。账号切换/对局切换会拒绝旧回包。未登录或内存离线provider不会伪造永久到账。

运营目录为127项可兑换商品与128个码（127个单品/礼包码、1个全部非VIP奖品码），包括已实现的金币渠道商品、两种抽奖券、100G币标准份额和30天签到月卡。VIP等级/充值成长、召唤权限、专属礼包和勋章均排除；两项尚未实现或暂停的历史配置与VIP项目一并在Excel排除页说明。全奖码按奖品去重，不重复计算礼包与其单品的永久加成；已拥有的唯一物品跳过，其余继续发放。月卡按原到期时间续30天，永久月卡保持永久。

数据库新增三张专用表 `redemption_codes/claims/attempts` 和两个最小权限RPC；表启用RLS，应用角色不可直接读写码表。每账号每码一次、账号/请求ID唯一、全服限次和每分钟10次限制由事务锁保证。初次接受时冻结奖品，发放复用原商城Lua结算；属性、库存、礼包标记、钱包、月卡权益、revision和回执在同一事务完成。丢失回包和并发重试读取同一回执，不重复发奖。码表调整保留历史claim和已接受的奖励快照。
