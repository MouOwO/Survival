## 使用者只需跟的六步

1. **先完成代码与测量准备。** 我负责：压测协商新协议并检查解码；加入真实无尽批次、缓存目录命中和冷启动场景；连接复用；拆除SQLite请求热路径的串行写/过期清理；正式账号准入；稳定云端Steam验签出口。现有仅4/5测试账号门禁不能通过塞入10万白名单解决。此步不购买资源、不改生产。
2. **核对并短期购买候选。** 你只需在ECS/RDS控制台按上表选规格、同VPC、月付或短期测试计费，记录实际续费报价。提供资源ID、地域/VPC和私网连接地址即可；凭据留在私密配置，不放聊天、Git或报告。RDS迁移适配完成前不提前长期购买。
3. **准备隔离演练。** 我负责新空数据库/专用身份、10万合成注册记录、典型和高状态存档，按真实业务准备可领取奖励；测试发生器与被测业务分开。当前lab只允许回环固定地址且容量模式拒绝生产主机，接RDS或Nginx完整链路须先扩展受校验环境合同，不能靠改常量绕过隔离。测试不调用真实Steam或支付网关。
4. **自动阶梯测试。** 目标20→100→500→1000→2000→4000，前级不达标停止升压；4000 ready用户稳定至少60分钟，通过后再做4小时浸泡、集中登录/同秒结算、断线恢复、重复命令与幂等、DB重连/故障切换。普通业务模型约180 RPS，活跃模型约367 RPS；必须同时测真实到达率和完成率，禁止慢系统或限流导致请求发不出来却被判通过。
5. **绿灯后迁移切换。** 先完整备份、克隆恢复、角色/扩展/数据摘要核验，再约定维护窗口停写、最终同步、切新服务、只读核账后恢复写入。保留原account pepper、认证secret与会话、支付/兑换领取、限额、幂等及迁移记录。旧环境保留作恢复证据；新库开始写后不能直接切回落后的旧库。
6. **按红绿灯维护。** 自动报告看延迟、错误、CPU/内存、IO、锁和池等待、出口及每日数据增长。CPU/内存、SQL锁、出口分别处理，参数变更先预览、备份、执行再验收；已有写命令结果未知时不自动重放。用户无需日常手工改PG配置。

## 数据增长与上线边界

每天4小时4000人、每60秒一次结算为96万次/天、2880万次/月。`online_time_idempotency`保存的是小结算响应，完整profile在Python后追加，不能按40KB/行硬算；但里程碑发奖调用的`out_of_match_reward_idempotency`可能持久保存完整profile。需分别测两表行宽、索引、WAL、备份增量及重度账号增长。当前18.4MB小库不能外推10万人长期成本，幂等表不能为省空间任意清空。

冻结schema未给这些幂等请求设置年龄拒绝或清理任务，在线会话90秒lease及PWA四小时令牌都不是旧请求的幂等TTL。旧奖励/跨午夜/当时封顶回执也须保持。只可先设计已完成outbox的有界清理，同时保留对应已完成操作或永久去重标记；不能只删operation而留outbox使其重新结算。若每条全成本分别为512B/1KiB/2KiB，2880万条约占14.75/29.49/58.98GB/月，仅为敏感性模型，尚未实测且未含派生表、WAL及备份。

第一批可一键化的范围是：只读体检→生成采购/参数预览→隔离建库种数→阶梯压测→生成红绿灯报告。购买、维护切换和真实数据迁移另有明确确认步骤。**现有CLI还没有整套一键阶梯/监控/验收编排**，本轮交付的是可执行顺序和购买/验收清单，不能冒充工具已经实现或性能改造已经部署。

复杂度预算：10万身份准备O(N)，1000行分批/O(1000)内存；单用户状态和索引查询O(1)，没有按账号数定时扫描。连接池总量有界，稳定借还O(1)；进程监控按固定实例和路由数读取聚合指标，不遍历玩家存档。SQL语句与Lua子进程的真实次数随业务批次而增长，须单独计数，不把HTTP回包变小当作SQL调用减少。
