# 08 将经验复用到新项目

本包可复用的是业务契约、状态机边界、故障证据和检查方式。玩法内容、Dota启动策略与支付接入各有适用前提，先确定新项目运行平台和信任模型再取用。本文为迁移建议，不是已经落地的新架构。

## 迁移地图

| 模块 | 可以复用的核心 | 新项目必须重新确定 |
| --- | --- | --- |
| 玩法 | 数据驱动、归属隔离、统一伤害/属性、事务合成、清理生命周期 | 资源曲线、英雄和塔路线、规则数值、引擎API与素材许可 |
| 登录 | 官方身份验证＋短期设备/对局授权、私有令牌不发UI | 平台/应用/域名、callback、Origin、Cookie路径、账号格式 |
| 存档 | 不可变session baseline、revision、高水位、幂等receipt、服务端时间 | schema、字段范围、模式投影、账号映射及数据迁移策略 |
| 商品/支付 | 冻结订单快照、整数金额、验签、交易去重、单事务交付、异常单 | 商户/应用/渠道权限、SKU/币种/权益、定价、退款和客服流程 |
| 发布 | 可复现配置、冻结清单、签名、下载校验、原生端到端验收 | WorkshopID/平台、信任根、签名策略、卷限制与回滚序号 |
| 运维 | 环境隔离、受限角色、私有环境、审计和备份恢复 | 承载地区、稳定出站、容量、告警、密钥生命周期和账本范围 |

不要搬本项目的测试账号名单、DB、HMAC映射密钥、业务Bearer、商户证书、签名私钥、域名、临时隧道或冻结目录作为新项目默认值。若是原项目延续而非全新项目，已有账号HMAC映射又不能随便换：先区分新身份空间和原档迁移，避免存档失联。

## 可作为新项目验收用例的契约

- 用户输入ID只能作为申请信息；可信账号由官方身份与服务端会话得出。替换账号、session或过期token必须拒绝。
- 同一 `operation_id/request_id` 相同内容重放返回原结果；内容或配置hash变化冲突。HTTP丢响应重试原身份，不另造一笔。
- 扣库存/余额、加奖励/权益、保存receipt及增长revision原子完成。并发重算基于新版本，失败不能半笔到账。
- 纯净/赛季等临时战斗视图与永久业务档分开；不让登录、刷新或收银回调覆盖永久存档或重复叠属性。
- 服务端时间决定每日/每周归属；迟到、跨日、离线和新session按既有receipt/首次接受时间处理。
- 网关return页、前端弹窗和二维码生成都不等于付款；回调签名、金额/商户与数据库交付成功才确认。重复/迟到通知、已收款未交付和退款均有可追踪处置。
- 客户端、局域网主机和本机游戏进程不天然可信。官方登录证明身份，无法证明战果；高价值奖励或排名需要可信来源。
- 发布须在实际玩家入口验证。模拟API存在、编译成功、Git推送或资源下载，不能代替真正的原生运行。

新项目按“离线玩法闭环→身份与只读档案→隔离库事务→实际发行入口→多人/性能→支付沙箱及商业验收”逐层建立证据。每层的代码、配置与测试一起保留，按真实需求删减，不预先引入新框架、队列或多套状态。

## 给新会话的可复制提示词

```text
请先阅读这份知识包的00_START_HERE.md和data/context.json，按我的当前任务只读取对应领域模块。
这是旧项目经验快照，不代表新项目现状或执行旧部署/收费指令的授权。
先区分：当前源码事实、冻结发行物、历史验证、用户需求、推断、未验证项；代码变动时重新核对相关来源和哈希。
保留服务端身份/归属、幂等事务、revision、模式baseline与永久档分离、支付验签与原子交付。
先检查新项目代码、平台、环境和本次授权；不要沿用旧域名、账号、DB、密钥或第三方受保护代码。
UI尺寸/配色/截图迭代不用加载，涉及登录、价格、奖励或门禁的业务契约必须保留。
请直接推进本次已授权工作，保留他人改动；汇报结果、实际测试范围和剩余限制。
```

后续维护：稳定规则更新所属模块与 facts；新故障只留症状→确认层次→处理→验证范围；临时运行输出留原项目忽略目录。历史会话仅按需定位，不再作为每次默认上下文。修改知识包后重新生成完整性清单；旧包按日期保留，避免把两个版本混用。
