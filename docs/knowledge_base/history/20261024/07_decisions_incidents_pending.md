# 07 关键决策、故障经验与待验证事项

本页压缩排查过程，保留可复用原因与证据边界。发布日期和当前实现分别核对，不把历史需求写成完成记录。完整字段证据见领域 JSON 和原项目 `publishing/workshop/`、`validation/`。

## 必须记住的故障

| 现象 | 已确认到哪一层 | 有效处理与不能推导的结论 |
| --- | --- | --- |
| `FATAL ERROR: Failed to read 16 bytes` | 对应大 inline VPK 的原生读取失败；同内容分卷通过 | 使用目录包＋4个外部卷、每卷小于1GiB；校验完整集合及尾部原生资源。不是笼统“代码没提交” |
| `Invalid_NotOnDedicatedServer` | 当前游戏上下文无有效 Valve dedicated 凭据 | 私有改不公开列出仍失败；转独立玩家网页登录。普通云业务 VM 不自动变 Valve 游戏专服 |
| `WS4-WEB-04/start/create/0` | HTTP 请求对象构造失败，未到 Send | v05 自有轻入口固定重开同条目真实地图后成功；不是后端返回 HTTP0。内部原因和官方白名单说法仍未知 |
| 加入器 `guest_file_missing`／`bytes_changed` | 安装/资源阶段，未到 VPN | 查文件集合、长度、SHA、解压目标；实际出现0字节资源。完整修复与校验，不能随便改 manifest 放过 |
| `install_runtime DirectoryNotFound` 长名 | Windows目的路径超长 | 短解压根目录加扩展长度路径安装；包内最长文件名曾达186字符。当前常用入口已不依赖旧 guest 派发器 |
| VPN 在线却连接失败 | 开组件不等于加入同一私网；后来证实已互通 | 两端同网、地址/端口/允许规则核对。密码仅本机私有说明保存，不进入知识包 |
| 双人进入即断开 | 主机日志接收队列溢出，前台恢复后稳定 | 用户已确认双人能玩；严重卡顿仍在。一次前台稳定不能替代正式hosting与性能验收 |
| `steam_state_invalid` | 可包括回调过期/重放，或上游验签首次失败后刷新掩盖首因 | 保存安全首因；同浏览器已消费state不重复验签；使用新挑战。杭州Steam TLS另有临时中转依赖 |
| `origin_rejected` | 授权页ReferrerPolicy使form POST出现Origin:null | 仅授权成功HTML使用same-origin；精确Origin/CSRF校验保留。不是删除Origin保护 |
| 攻击面板正确、伤害不对 | 原生整数setter边界、独立装备flat与逻辑倍率可能不同 | 受控原生范围投影、共享过滤只还原一次；测试实际carrier扣血。UI正确不是伤害正确证据 |
| 配置弹速正确、原生仍错误 | 实际引擎无预想的SetProjectileSpeed；旧mock却提供了它 | 有效缓存独立写入，原生modifier bonus适配。测试覆盖缺API路径，不为通过模拟虚构接口 |

第三方只作为可观察流程参考。Tower Feast 的受保护核心与后台未破解；梦之岛可读客户端表明可同条目重开目标图，未验证其受保护 HTTP 内核。我们使用自有实现与资源，没有把别人的支付/签名核心复制进项目。

## 当前快照与长期规则的区别

当前开发 `all_difficulties_unlocked=true` 会把整局写入隔离；正常进度门槛和保存路径不因此消失。模式当前开放四种；暗影界尚无战斗掉落。旧文档里主机独享难度、N1–N5起步、全局90怪上限和公共技能容量3等描述，不能覆盖2026-10-24开发源码。具体事实以02及其哈希快照为准；配置变更后重新核对。

v05 是冻结 v04 的受限入口叠加，180保护模块和冻结主入口正文保持字节一致，不能声称把当前dirty工作区玩法、商城或验收开关全发了。关键认证交付 game `b5a1ecde0e6fa8a8b07c51d3fd3d99601b57cde2`，content `3b3c567112763ddade02799c262cee9044d51f9f`；整理期间有其他任务随后提交，最新状态看 repository_snapshot。Steam manifest 和 Git commit 是两套版本标识。

## 后续工作，按依赖推进

1. **原入口重复验收**：冷启动、记住登录、每局确认、令牌过期/撤销、错账号、断线/旧回包与失败重试。已有单人成功不覆盖所有错误分支。
2. **稳定云出站**：移除作者电脑临时Steam TLS依赖，重新验证官方证书、固定端点及OpenID流程；接入告警和备份恢复。不要通过关TLS验证解决。
3. **多人承载选择**：VG/散夜仍未建立可验证作者接入。核对游戏进程部署许可、房间分配、资源同步、Steam身份、UDP网络与延迟；租业务ECS不自动完成这一步。先选方案再验证2–4人公网与长局。
4. **持久化和玩法验收**：决定何时关开发只读开关；同步模式进度、掉线名单、合作奖励、波次个人失败和通关保存屏障；测两个独立账号并发与重连。历史旧BUG按新局和当前代码复测，不能照旧文档一概报仍存在。
5. **正式商业化单独验收**：WS4继续真实支付关闭。生产开放需可信奖励来源、商户产品权限、独立订单测试、金额签名、重复回调、异常单/退款处置和备份恢复；支付宝precreate权限及实际付款证据仍须补足。测试重置不是退款。
6. **内容与性能**：补完未发布模式和暗影界之前先确定玩法目标；高波次、伤害大数、四人技能/寻路、60分钟资源清理分别采样。模拟基准不能报告为实机FPS，单机顺畅不能报告为公网联机顺畅。

这些是证据支撑的后续候选，不表示本次整理已批准购买服务器、公开发布、真实收费或执行远端变更。
