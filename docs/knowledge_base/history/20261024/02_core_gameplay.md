# 核心玩法与维护入口

审计日期：2026-10-24。范围：当前 game 开发工作区的 Lua、CSV、v3 战斗规格及发布回执；本次没有运行游戏或回归测试。文中源码路径均相对 game 仓库；精确证据与数值快照见 `data/gameplay_facts.json`。

## 先分清开发源码和线上冻结包

游戏主循环是「确认身份和资源就绪 → 房主选模式与全队可用难度 → 经营基地、发展工人和塔、召唤英雄 → 守波与挑战 → 通关后存档挑战和结算」。队友同阵营，经济、建筑、英雄和奖励仍按玩家归属管理。

**当前开发源码处于只读验收配置**：`config/mode_release_config.lua` 的 `all_difficulties_unlocked=true`，新局会开放已发布模式的全部配置难度、绕过进入进度和日限额，同时把账户写入隔离到整局结束。中途关开关不能把测试收益变成正式存档。不要看到菜单说明“奖励正常保存”就认定当前验收局会写账户。

线上 v05 是另一份签名冻结包。`publishing/workshop/workshop_entry_release_20261024.json` 记录原条目 `3824360109`、序列 `2026102405`、入口 `ws4_entry → template_map`，已验证普通 Steam 原游廊入口的**单人授权、读档、游戏和云端检查点**。目标地图声明四人，不代表这版已提供或验证多人托管；当前仍限四账号隔离测试、依赖作者电脑的临时 Steam TLS 中转，支付和可信排行未开放。本次未重新取得冻结包的模式配置原文，不能把开发分支的新规则直接写成 v05 已上线事实。

## 开局双门禁、模式与难度

原生队伍设置由房主开始。第一道业务门禁要求引擎真实玩家名单、身份认证、资源预载和客户端就绪全部满足；此时认证拿到的是身份及永久进度，还不是某模式的战斗属性。房主选定本局模式后才加载对应档案，第二道 `gameplay_gate` 满足后才释放建造者、英雄初始化与业务 `GAME_STARTED`。它们不暂停引擎原生阶段，因此画面仍在加载时引擎可能已进入 `GAME_IN_PROGRESS`，不能据此跳过业务门禁。选择者由引擎房主权限判断，普通运行不退化成“最先收到请求的人”。

当前发布开关仅允许常规 `standard`、纯净 `pure`、丰饶 `rich`、极寒 `cold`；天灾、归墟、天域、摸鱼虽然已有部分配置，仍未开放。2026-10-24 v3 配置的难度范围为常规/纯净 N1–N10、丰饶 N1–N30、极寒 N1–N50；未发布模式有表不等于可玩。

关闭验收开关后的正常规则：丰饶要求任意战斗模式持久通关 N3，极寒要求 N5；模式各有独立通关表，缺表视为后端尚未支持。进入模式后 N1–N4 开放，N5 起要求**本模式**前一难度通关。常规仅在专属表不存在时兼容旧 `clear_counts`，显式空表不继承其他模式成绩。难度取完整参局名单的权限交集，掉线不应悄悄移出名单来提高权限；全局日限额与独立模式限额共同约束进入。验收配置暂时绕过进度/限额，未发布模式仍被拦截。

丰饶、极寒使用常规档案的战斗投影，但保留各自持久模式身份与进度；纯净模式去掉历史永久战斗加成，资格判断仍取认证进度。所有异步回调要核对账号、模式和本局 session，拒绝旧局回包串入新局。主要入口：`systems/startup_loading_service.lua`、`match_setup_service.lua`、`team_difficulty_service.lua`、`player_profile_service.lua`，规则在 `config/mode_progression.lua`、`difficulty_config.lua`。

## 经营链：资源、人口、建造与科技

主城解锁建筑和训练层级；伐木工攻击资源树取得木材，金矿提供金币，农场与建筑升级扩大人口上限，工人与部分建筑占用人口；木材、金币再投入墙、塔、科技和英雄。`resource_system.lua` 的账户按 `player_id` 隔离，初始木材是档案给出的完整起始值，不是额外奖励；重复档案刷新只应用差额，不能再发一次全部起始资源。

2026-10-24 建筑表：墙、主城、农场、普通/高级研究所、挑战建筑、祭坛各基础限一；防御塔每玩家合计七座，包含基础、转职与终极塔。订单和施工先预占名额，转职不释放，销毁/死亡才释放；每路线五座是另一重限制。金矿基础五座、主城三级解锁，占两人口，权益和特殊效果可能改变上限；祭坛需主城四级。高级研究所还要求已完成的普通研究所，挑战建筑也检查已完成研究所。详见 `config/generated/building_definitions.lua`、`systems/building_system.lua`、`player_tower_limit_service.lua`，不要只读建筑说明文字推断当前价格。

主城训练采用串行队列：排队先预占训练数量，轮到队首才扣货币和人口；取消或完成失败只退已扣部分一次，计时回调带代际检查。伐木工有八阶，各阶普通工人可按表合成对应超级工人；前七阶带性格池，第八阶无性格，不是“合成后自动升一阶”。修理工按归属修复受损建筑。金矿产量、效率、暴击和周期升级分别计算，科技效果按玩家存储并回收失败操作。入口：`worker_training_queue_service.lua`、`lumberjack_fusion_service.lua`、`gold_mine_system.lua`、`research/research_technology_service.lua`。

## 塔路线、合成与战斗结算

基础箭塔到阶段末再选七条转职路线：死亡/暴击、神秘/激光、闪电、机枪、多重、冰霜、防空；实际行配置位于 `config/generated/tower_class_*.lua`。显示品级不决定升级索引。快速升级累加跨越行的木材/金币成本，人口只算当前到目标占用的差额，不能把沿途人口全部相加。终极合成要求同一玩家的七路线终阶塔各一座，防重入并限制每玩家一座终极塔。

索敌过滤死亡、友军和资源树，并检查防空资格及真实攻击距离；优先 BOSS/进攻 BOSS/波次首领，再按距离和稳定索引选择，无真实敌人才回退训练假人。原生自主索敌被项目策略约束，不能为修复“塔不动”重新放开原生乱打资源树。攻击节奏以秒为间隔计算，固定减间隔与百分比攻速顺序有意义，不能拿动画速度当伤害次数。

伤害走 `combat/damage_service.lua → damage_filter_service.lua` 与事务记录，区分普攻、持续伤害、溅射、反射和纯表现来源；最终以引擎实际命中记录为准，表现弹道不得再次造成伤害。项目护甲与超大数值缩放有适配层，不可在技能内重复减甲或重复还原倍率。入口：`tower_route_config.lua`、`tower_fusion_service.lua`、`tower_targeting.lua`、`combat/attack_cadence.lua`、`config/armor_balance.lua`。

## 英雄、背包、转生与局内构筑

每人最多一个战斗英雄，祭坛和主城资格、拥有者、权益、召唤位置都在服务端检查；异步预载完成后重查，失败不应丢失原承载单位。当前六个启用英雄，其中付费英雄也可由对应认证道具解锁，不等同于授予全局 VIP。历史内部 ID 不保证对应当前显示名，例如 `hero_shadow_fiend` 实际是光之守卫。

逻辑背包、装备实例和物品 ID 是业务实体，原生物品只是呈现载体。合成事务按玩家加锁、以 `request_id` 幂等，并在同一次变更中完成全量材料检查与扣料/产出；装备属性统一汇总，避免外壳与逻辑装备重复加成。HTTP 权威房间的永久变更必须走服务端事务，不能本地修改后假报保存成功。主要入口：`content_inventory_service.lua`、`inventory_transaction_service.lua`、`weapon_synthesis_service.lua`、`equipment_instance_service.lua`、`equipment_stat_aggregation_service.lua`。

转生挑战依序推进，由有效击杀奖励改变转生、属性、攻击成长和技能，不由点击直接发奖。当前技能表：二至四转三选一、排除已拥有/满级、选择内去重、总容量十；后续技能点与专属效果走奖励服务。肉鸽分别管理建造者开局池与 BOSS 池，候选、领取和重抽按玩家记录，未选或重抽不等于永久移出池。训练房需本人存活英雄、合法传送点和费用；十转年轮圣殿按当前表收取入场及持续金币，十五倍作用于指定成长收益。暗影界目前**只有传送，怪物和掉落未启用**。房间优先个人 marker，缺失时仍存在旧共享点回退，不能宣称所有地图都具备物理隔离。

## 波次、墙、败退与终局

`waves_config.lua`、`human_monster_rules.lua` 将 v3 规格映射为模式/难度/波次怪物和出怪节奏。运行时按玩家建立波次通道、目标墙和存活计数。当前上限九十只、持续超限十秒触发该玩家失败，回到上限以内重置；`generated/global_rules.lua` 旧注释仍写全场共享，**以 `wave_system.lua` 的个人计时实现为准**。已完成墙被毁只淘汰登记所属玩家，施工死亡不按成墙判负；失败者观战，其余玩家继续，全员失败才终止。

墙导航使用可恢复的障碍登记与实际碰撞，近战接触位负责正面攻击、候位和补位，不靠隐形实体、叠第二排或瞬移假修路。修改时一起检查 `wall_navigation_service.lua`、`wall_melee_contact.lua`、`modifier_enemy_wall_ai.lua` 和地图出生/房间 marker。

终局同时要求最后一波生成完毕、无生成失败、无待生成、无存活怪，漏生怪不能被算作胜利。胜利只结算一次，先冻结普通战斗，再固定合格获胜名单，发出个人通关事件并衔接存档挑战阶段。合作奖励有共享事件和逐玩家提交机制，队友获奖不代表可复用同一账号凭据；重试沿用事件/请求身份，不重复发放。账户命令尚未确认时保持待保存状态，不能仅凭本地动画展示成功。

## 维护顺序与不可破坏的边界

常规数值源是 `data/csv/`，经 `tools/build_configs.py` 生成 `config/generated/`，不手改生成 Lua。v3 战斗数值同时以 `data/balance/human_spec_v3/human_spec.json` 和 `接入规格_人话版_v3.xlsx` 为输入，由 `tools/import_human_monster_spec.py` 交叉校验生成 `normalized.json` 与 `human_monster_spec.lua`；修正表已计入，不可再乘一次。模式开放与只读验收由单独的 `mode_release_config.lua` 控制。旧 `docs/MATCH_SETUP_AND_MODES.md` 的两模式、仅房主难度等描述不是当前规则。

始终保留：真实引擎身份和单位归属；每玩家资源/限额/奖励隔离；门禁完成前不运行玩法；所有花费、合成、召唤和奖励复核权限及幂等；旧回调不跨局；在线禁止开发作弊，离线测试仅显式 development + Tools + 关闭网页登录时允许，配置缺失/异常拒绝放行；离线档只在本局内存中存在。开发验收、四账号云测和公开运营是三个不同验证范围。
