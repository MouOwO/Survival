# 01｜架构与协作

## 三个权威层

| 层 | 权威与职责 | 不能替代的边界 |
| --- | --- | --- |
| Lua服务端 | 模式、难度、角色归属、经济、建造、战斗、波次和本局投影 | 客户端按钮或显示值不是奖励依据 |
| Python／PostgreSQL | 账号、永久档、订单、支付核验、持久权益、幂等发放 | 本机Dota房主不是可信支付或竞技裁判 |
| Panorama | 交互意图、状态投影、弹窗、购买/兑换反馈、授权入口 | 不信任前端传入的价格、金额、库存和Steam身份 |

浏览器通过Steam官方OpenID完成身份验证，游戏内无需Steam密码；网页短码绑定本次对局。网站承载身份、存档、订单和协调服务，不能仅凭网站存在就运行Dota战斗实例。当前原生多人路线已可在玩家主机承载对局；独立专用对局服务器、调度和公开多人平台仍是不同能力，不能混为已交付。

## 两仓与生成链

game：`D:/SteamLibrary/steamapps/common/dota 2 beta/game/dota_addons/survival`，开发分支dev；content：同安装根 `content/dota_addons/Survival`，分支master。content保存Panorama源与可编辑地图/美术，game保存运行Lua、CSV及编译资源。两仓不是同一个Git仓库，提交号与同步状态分别记录。

配置以CSV、人话规格JSON/工作簿和明确的生成脚本为来源，运行时使用生成Lua。不要只改生成文件而丢失源配置，也不要把旧CSV注释当当前最终数值。尤其人话怪物规格的最终覆盖发生在倍率后，见02。具体生成入口先查 `docs/ai/`、对应工具和配置schema；保持只生成目标表，不全量重写不相关资源。

地图当前Hammer保存文件是权威，使用 `tools/map_c6/compile-main.ps1`，禁止用早期生成器覆盖手工地形。只凭修改时间不能证明编译产物对应源码，必须验证嵌入source CRC和内部资源CRC。

## 交付规则

检查两仓分支/上游/未提交改动/未推送提交/历史stash，使用唯一说明保存修改；记录自己的stash对象，pull按现有策略，pop仅自己创建的stash；冲突先核对原数据。同步后只暂存本任务，源码/编译产物配套审查，commit、push并核对远端HEAD。没有改动的仓库不空提交。不能reset丢数据、强推、清空历史stash或把别人的修改打包提交。

本知识整理前，game有原102项编译美术、UI、粒子、缓存/bundle改动；content工作区干净。这些是明确保留的既有工作，不属于知识库提交。地图源码按content现有LFS；game主地图VPK沿用binary属性，不能自行改变.gitattributes。

## 异步与所有权

每次请求绑定经过验证的玩家、对局及请求版本；切局、重连、实体销毁和旧回包不能写新状态。永久档与模式战斗投影分离，结算使用固定baseline、服务器时间、版本校验和幂等收据。购买完成后从后端读取权益，而不是前端自加库存。具体规则见03/05/10。

## 证据优先级

当前开发行为查当前代码/配置；冻结发行行为查其签名清单；用户实机、日志和支付回执按入口/账号/版本分层；单测和静态检查只能证明其覆盖范围。历史聊天和旧文档保留原因，不自动覆盖新事实。未确认的Valve内部HTTP规则、服务器托管能力和guest下载权限必须写未知。

重要资料放版本化知识库或独立D盘归档，不能只放游戏output。并行任务清理output前须排除活跃构建/验收记录及其依赖，先保留可验证恢复点。本轮已发生过output并发清理，经验见07。
