# 自有商城与游戏内扫码支付，2026-10-26

用户要求继续使用本项目自己的商城 UI，并希望在游戏内展示二维码、手机扫码付款。原生二维码在技术上可行，项目也已有相关实现；当前对局与云端档案尚未接通，不能把恢复商城界面等同于真实支付到账。

## 当前实现与交付边界

本轮将原游廊商城入口接回原有黑狮商城窗口、商品行、美术和详情组件，保留首页／礼包／促销／VIP／全部商品五个分类及每批 20 条的增量滚动，展示正式配置的 173 项报价。现金与钱包报价即使使用同一 SKU 也分别保留；报价数不等于不同商品数。

这里只读展示目录。账户余额、持有量、剩余限购和购买资格未知，不能显示为已同步的零或已获准购买。所有付款、充值和兑换入口继续关闭；公开目录不会覆盖原认证目录，认证回复可在退出只读窗口后恢复。窗口所有权、关闭及重载有独立清理，避免旧界面回调影响新窗口。

本轮未创建真实支付订单、调用支付网关完成交易或发放真实购买奖励。没有验收商户 Native／预创建权限，也没有验证真实手机扫码到账。实机与工坊发布验收见下方待补记录。

## 已有二维码及支付代码

- 游戏端 `panorama/src/scripts/custom_game/payment_test.js` 的 `drawQR` 使用 `qr_matrix` 生成黑白 Panorama Panel，并校验矩阵内容和尺寸；不要求在游戏里加载外部二维码图片。原生收银台已包含商品、金额、渠道、过期与订单状态展示。
- `server/payment_backend/service.py` 的 `qr_matrix` 生成带静区的矩阵，订单为待付款且未过期时才返回。二维码属于具体订单，不是通用固定收款码。
- `server/payment_backend/wechat.py` 已实现微信 `/v3/pay/transactions/native` 下单、查询、关闭和签名通知处理。官方文档说明服务端下单后得到 `code_url`，再展示为付款二维码：[微信支付 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)。
- `server/payment_backend/alipay.py` 已实现 `alipay.trade.precreate`，核对返回订单号和二维码域名；商户需要具备相应接口权限。已有网页支付订单保留原流程，预创建失败不会伪装成扫码成功：[支付宝统一收单线下交易预创建](https://developer.alibaba.com/docs/api.htm?apiId=862&docType=4)。

两份官方资料于 2026-10-26 浏览核对。它们证明支付渠道支持按订单生成二维码，不证明本项目商户权限、原游廊网络或云档案链路已经可用。

## 真实到账仍缺少的链路

当前原游廊采用已验证的直接多人、本局数据模式；已有实机记录显示游戏 Lua HTTP 创建失败，Panorama 的旧 `AsyncWebRequest` 也不能当作已可用替代。网站健康、工具模式或 UI 能绘码，都不能替代原游廊里的权威档案读回。

上次只读核验记录在 [商城目录与支付接入](payment_shop_20261026.md)：旧支付服务仍接 `goufayu_test:5432`，使用原两账号范围；`goufayu_ws4:15432` 的七张支付表为空，支付角色为 NOLOGIN 且无数据库 CONNECT。这些是此前核验事实，本轮没有据此修改数据库或宣称已完成接入。

最小接入顺序：

1. 原游廊对局通过可信通道连接后端，建立真实 Steam 账号与对局会话，读取同一 WS4 权威档案；客户端手填 SteamID 不能代替认证。
2. 配置独立 WS4 支付服务、最小数据库权限、正式商品快照、四账号范围及回调路径，保留旧服务和账本。
3. 玩家在自有 UI 确认商品和数量，由已认证服务端确定账号、价格、奖励、币种与商户并冻结订单。业务接口的服务端 Bearer 密钥不能放进 Panorama。
4. 只向该玩家发送其订单的二维码和状态。查询、取消必须核对订单归属；不能将带订单能力令牌的数据广播给所有玩家。
5. 支付渠道通知须验签，并核对金额、币种、订单、商户和交易号；用事务、行锁和幂等规则写账及发奖，重复通知不重复发放。
6. 游戏重新读取权威档案，核对版本、购买内容、余额和限购。现有 `payment_service.lua` 已等待 `profiles.refresh_player` 完成，刷新失败返回 `reward_refresh_pending`；账本 `delivered` 不能冒充本局已生效。
7. 验证实际小额交易、重复回调、过期／超时、重连以及两个账号隔离后，再开放真实收款。

固定收款码不能替代带账号、金额和商品快照的订单；客户端“已支付”消息不能触发发奖。网站可承载订单和档案数据服务，但游戏仍须有可靠的权益读回通道。仅展示网页入口二维码或付款码不会自动解决该问题。

开放前另有核价事项：`special_lottery_ticket_single` 配置 25 元，`video_p001` 配置 6 元，两者都发特殊抽奖券一张。当前沿用正式配置，不擅自改价；需核对不同 SKU 的活动定位、限购和权益关系。
