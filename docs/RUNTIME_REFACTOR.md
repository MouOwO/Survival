# 运行框架审计与重构验收

日期：2026-09-25。基线提交：`5ee5a8ba5d612c0908edf8543f14628b744307c7`。

本轮完成代码审计、可重复的操作量基准、第一批生命周期修复和本地回归。**实际 FPS、四人联机、长时间运行和当前 ECS 持久化验收尚未完成**。不把本地模拟当作实机结果。

## 1. 框架结论

保留 Dota 原生 Lua / KV / Modifier / Panorama，继续使用现有域服务、事件总线、调度器、CSV 配置生成和 Python 数据库入口。当前没有证据支持整体换框架、增加 ORM/消息队列，或重画已验收 UI。

现有分层能表达四人塔防需要的权威关系：服务端决定波次、伤害、消耗和奖励；Panorama 消费投影；Python/RPC 负责持久化事务。真正的问题是生命周期约束没有在所有模块中一致使用，以及大模块中保留了无作用的常驻工作。

审计时 `systems` 下约 159 个模块，`hero_passive_skill_service.lua` 约 3,735 行，`wave_system.lua` 约 1,422 行，`combat_stats.js` 约 2,840 行。行数只说明维护成本，不能作为性能热点证据。后续按技能或职责拆分时，保留原公共入口和同一伤害/属性权威，不建立第二套系统。

| 能力 | 本轮决定 | 原因与后续边界 |
| --- | --- | --- |
| 基础单位、技能、攻击/移动参数 | 优先现有 KV 与官方 API；CSV 权威字段继续由生成链同步 | 不在 Lua 定时重复写静态参数，也不手改生成配置 |
| 普通攻击、投射物、技能事件 | 继续使用原生攻击、ProjectileManager 和 Modifier 回调 | 事件型技能不需要额外 0.03 秒常驻轮询 |
| 自定义 War3 战斗属性/伤害 | 保留统一伤害服务和属性投影 | 直接替换为原生数值会改变已验收计算规则 |
| 防御塔排除资源树 | 保留现有小范围目标过滤与 idle 状态 | 树和怪物都用 BASIC 类别，现有 KV 分类不能表达项目的全部目标规则；不能撤销禁树换取性能 |
| 光环 | 本轮保留已有周期与叠加规则 | 原生光环是候选，需要先验证树过滤、目标类型、叠加与持续时间等价 |
| 定时任务与事件 | 加固现有公共模块 | 保留 API，修正取消/替换/跨局边界，复用稳定订阅快照 |
| UI | 复用 SurvivalUI.Lifecycle、已有组件与快照 | 关闭停任务、变化才写；不降低世界血条跟随帧率来隐藏开销 |
| 联机/持久化 | 保留服务端状态机及后端幂等/版本保护 | 共享队伍不等于同一玩家，账号、对局、请求三个边界均需检查 |

证据来自当前实现和行为测试；没有把未能实机验证的原生 API/KV 替换直接合入。

## 2. 已实施的修改

### 公共调度与事件

- `core/scheduler.lua`：取消正在执行的重复任务、同 ID 替换、清空或重新初始化后，旧回调不再复活；到期批次保存任务身份，不会误执行同 ID 的新未来任务。
- 用下一到期时间作为保守下界。没有任务到期时不扫描/分配到期列表；保持原有 0.05 秒派发频率。到期批次仍一次执行，不通过降频或限制发奖次数取得基准改善。取消最早任务最多多扫描一次，不会推迟其他任务。
- `core/event_bus.lua`：仅订阅变化时重建派发快照；旧局退订句柄不能删除新局同数字编号的订阅。保留原有在途快照语义：处理器内 reset 不会中断已开始的派发，嵌套及后续事件使用新订阅。

### 战斗

- 普通箭塔及只靠攻击事件的路线停掉空特效循环；激光、极地和空域光环保持原有间隔。
- `tower_skill_runtime.apply()` 通知 Modifier 重新判断是否需要周期工作；建造、升级、融合、搬迁、刷新和销毁都覆盖。普通攻击、技能伤害、目标过滤和粒子清理保持。

### 重连与档案

- 在线结算绑定捕获的 session/account，旧会话不能通过 PlayerID 查到并结束重连后的新会话。
- 档案刷新在真正安装快照前检查当前身份与可选会话守卫；请求被替代时通知等待者，避免断线结算永久停留在 `in_flight`。
- 正常终局档案更新、纯净模式基线和重复请求保护保留。详见 [在线奖励审计](ai/FISHING_REWARD_INTEGRATION.md)。

### UI 和测试设施

- 信息窗关闭后停止轮询，同帧快照合并，相同字段结构复用行；上下文替换释放旧定时器和订阅。保留原样式、TAB 入口、开窗时 0.25 秒健康刷新及初次显示。
- 该脚本已单独同步到 content 并编译 `game_info_panel.vjs_c`，没有全量覆盖 UI 源码。
- 增加统一离线回归入口，优先发现 Lua 5.1；修正两个与已提交行为不符的旧测试契约（认证前禁止自动开局、Modifier 的规范定义文件绑定/失败后节流恢复）。没有为通过旧断言而回退生产逻辑。
- 已有显式性能捕获增加塔特效 thinker、范围查询、攻击指令、ApplyDamage 的调用计数；结束后恢复函数，默认不启用。

## 3. 基准结果

同一测试驱动分别运行基线模块和修改后模块。以下全部是 **SIMULATION**，不是实际 FPS。

| 工作负载 | 修改前 | 修改后 | 保持不变的行为 |
| --- | ---: | ---: | --- |
| 1,000 个未来任务，200 次空闲 tick | 200,000 次任务遍历 | 0 | 到期后 1,000 个回调全部执行 |
| 10,000 次事件，8 个稳定监听者 | 80,000 次监听函数复制 | 8 | 80,000 次通知全部交付 |
| 4 座基础塔，15 秒 | 2,000 次空特效回调 | 0 | 原生攻击事件仍执行 |
| 28 座基础塔，15 秒 | 14,000 次空特效回调 | 0 | 升级/融合后需要的 thinker 会恢复 |
| 激光塔，3 秒 | 101 次回调，4 次伤害 | 完全相同 | 伤害 120/125/130/135；31 粒子创建、31 清理 |
| 信息窗关闭 60 秒 | 60 次回调 | 0 | 打开即显示当前快照 |
| 信息窗同帧 100 个数值快照 | 创建/删除节点各 900，文字写 600 | 创建/删除 0，文字写 1 | 最后一帧数值正确 |
| 20 次 UI 上下文替换 | 残留 21 定时器、21 订阅 | 0 定时器、1 当前订阅 | 当前 TAB 入口有效 |

计时器 `os.clock()` 的主机精度可能把极短离线运行四舍五入为 0 ms，这不代表零成本。比较以确定性工作量和行为为准。

测试摘要和基准保存于 [本轮验证记录](ai/validation/20260925/runtime_refactor.json)。原始本地输出、旧模块和 UI 编译前备份在忽略目录 `output/runtime_refactor_20260925/`。

最终本地回归：81 项 Lua/UI 检查、95 项后端单元/临时 HTTP 测试通过；21 个修改脚本的语法检查通过。Lua 回归使用 5.1.5。后端测试使用假 RPC/数据库，未连 ECS；信息窗单文件编译为 1 成功、0 失败，content 与作者源字节一致。

## 4. 可重复验证

在 game 项目根目录运行（本地 Python 虚拟环境也可替代 `python`）：

```powershell
python -B tools/run_runtime_regression.py
```

它只运行隔离 Lua/模拟 Panorama 测试，不启动游戏、不连接 ECS/数据库。可用 `--lua <Lua5.1路径>` 或 `SURVIVAL_LUA` 指定工具链；本机确认路径为 `C:/msys64/msys64/bin/lua5.1.exe`。报告默认位于 `output/runtime_regression/latest.json`，失败退出码非零。Node 场景执行真实作者源，Lua 场景模拟引擎与传输。

单独重复操作量测试：

```text
lua5.1 tools/benchmark_scheduler.lua
lua5.1 tools/benchmark_event_bus.lua
lua5.1 scripts/vscripts/tests/test_tower_effect_thinker_lifecycle.lua
node tools/test_game_info_lifecycle.cjs
```

前三项可追加保存的旧模块文件路径。UI 测试 `--measure-head` 测当前 HEAD；提交之后要与本报告记录的基线提交对齐，不能把移动后的 HEAD 称为原基线。

## 5. 实机验收矩阵与指标

新局加载代码，不对正在进行的对局强制热换核心模块。固定地图包、画质、分辨率、镜头和单位数量；先测原版，再测本版。每个场景留 30 秒预热，再取至少三段 15 秒采样，记录最差段；连续运行在 5/15/30/60 分钟重复同一负载。

| 场景 | 操作 | 记录 |
| --- | --- | --- |
| 单人对照 | 7+ 伐木工、4+ 塔正常采木，再全部停止采木 | 客户端帧时间 p50/p95、FPS、进程工作集/显存；Lua 查询/指令/thinker 次数 |
| 四人高峰 | 四个独立玩家同时出怪、范围技能、召唤物 | 同上；ping/丢包、各玩家怪物和奖励状态、服务端错误 |
| 战斗中 UI | 重复开关存档、商城、抽奖和信息窗 | 定时器/节点/订阅是否增长、私有数据隔离、隐藏窗口请求次数 |
| 重连/结算 | 两个玩家分别断线/重连，奖励回包期间断线，终局重试 | session/request 对应关系、每笔奖励一次、新会话继续运行 |
| 长局 | 同负载重复采样 | 内存趋势、任务/实体/粒子数量是否持续增长；不能只比较峰值 |
| 分辨率 | 1280×720、1920×1080、2560×1440 | 文字、点击区域、裁切、弹窗层级；未取得截图前不写通过 |
| 后端 | 测试账号、同请求 ID 重放、异常与恢复、独立备份恢复 | HTTP p50/p95、RPC 次数、revision/账本/库存对照，失败不写空存档 |

Workshop 服务端控制台执行现有只读捕获：

```text
script_reload_code tests/manual_combat_performance
```

15 秒后打印 `[COMBAT_PERF]` 汇总并恢复包装函数，不生成或移动单位、不改档案。Lua 堆不是进程内存/显存，调用次数不是 GPU 帧时间。客户端性能与网络数据需另采；普通控制台、VConsole 和自动连接器避免同时争用 29000 端口。当前已有 VConsole 占用/权限问题，不能据自动测试声称已跑完实机矩阵。

| 优先级 | 已发现的候选或风险 | 下一步；不直接改什么 |
