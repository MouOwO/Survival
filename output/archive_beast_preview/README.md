# 存档—瑞兽赐福 / 视觉确认稿 02

根据用户最新指定的主要参考图，第二版改为圆形存档标题、深靛蓝异形侧栏、细金边、暖白内容面板、金框卡片与深色名称条。`reference.css` 为本轮样式，`sidebar.svg` 为独立矢量装饰（无棋盘格或位图黑白边），所有文字和数据继续独立渲染。仍保留40项8列及全部九类导航；参考图中的建筑插画没有冒充瑞兽物品图标。

直接用浏览器打开 `index.html`。无需安装依赖或启动服务器。
`preview.png` 为 1600×1080 浏览器实渲截图；`preview-tooltip.png` 为滚动到末行、查看七禽扇效果的截图。
本次只新增独立预览，未修改或编译游戏运行版本，不向游戏服务器发送请求。

## 数据与边界

- 40种物品的名称、顺序、上限、品质、单件效果读取自 `data/csv/存档系统/archive_social_items.csv` 中启用的 beast 行。保留50、20、5、1等不同上限。
- 抽奖消耗、福签名称、每日限制读取自 `archive_social_rules.csv`。
- 顶部副标题读取自 `panorama/src/layout/custom_game/archive.xml`：征途留痕 · 永久成长。
- 简述和完整规则沿用 `archive.js` 原文。单件效果和数量叠加说明遵循 `archive_social_rewards.lua`。
- 项目当前瑞兽页使用文字印章占位图（seal/rune），没有该页最终物品图标映射。预览复用此表现形式并明确标注占位，不假装最终美术。
- 本地未读到对应玩家持有明细，因此各项数量是 null，显示“—/上限”，不会猜测哪六件已获得。用户提供的6/40、共6件、七禽扇、福签95为带标注的示例数据，不冒充服务器档案。
- 导航按用户指定九项排列，当前选中瑞兽赐福。其他分类按钮展示普通/悬停状态，点击说明本轮预览范围，不伪造其他页内容。游戏原有其他分类及“无法攻击”等临时提示逻辑未变。

## 交互与布局

8列网格包含全部40项，内容区独立滚动，标题、统计和底部操作栏不滚动。末行可完整滚入视口，操作栏占据实际布局空间。规则在独立区域正常换行。
悬停或键盘聚焦可查看项目现有效果；底部“查看交互状态”展示普通、未获得、已获得、满额及抽奖可用/禁用样本。
未获得只降低图标饱和度，名称及数量保持清晰。所有文字均为 DOM 文本；按钮、边框与纹理由 CSS 实现，无整图烘焙或透明贴图。

`window.ArchivePreview.setSnapshot(packet)` 可传入现有 beast 快照结构：`category_id`、`rows:[{id,count}]`、`social:{tickets,remaining}`、`last_draw:{pool_id,name}`、`pending`。
此接口更新真实明细、统计、余额、结果和按钮状态。缺失明细保持未知，不当作零。
预览抽奖按钮仅触发本地 `archive-draw-intent` 事件，等待宿主回传快照，不调用游戏接口，也不随机编造抽奖结果。

## 字体与验证

目标字体栈：思源宋体 Heavy/Bold、思源黑体 Medium/Regular，均使用 SC 简体名称。
本机没有检出思源字体；通过 Chrome `CSS.getPlatformFontsForNode` 验证，实际标题使用 **SimSun（宋体）**，物品名称和规则使用 **Microsoft YaHei（微软雅黑）**。目前不是指定思源字重的最终效果。
本轮是浏览器视觉预览，不能据此宣称 Dota 中思源字体生效。确认方向后需在 Panorama 接入并检查引擎实际字形、尺寸和字重。

运行 `node output/archive_beast_preview/verify.cjs` 可使用本机无界面 Chrome 验证并更新截图。
`verification.json` 记录40项、8列、9分类、滚动末行、字体及按钮状态检查结果。状态测试使用独立合成数据，仅用于断言，不写入默认预览数据或玩家档案。
