# 手动恢复 Steam 登录

遇到 `steam_verification_unavailable` 时，在**作者这台电脑**双击项目根目录的 `修复Steam登录.cmd`，等待结果。显示“验签通路正常”或“已恢复”后，从游戏重新打开授权页，重新点击 Steam 登录；刷新旧错误回调页仍会显示原来的失败。

工具先检查本机回执及完整进程身份、云端现役配置和真实官方验签通路。正常时不重启；仅在固定中转不可用且身份核对通过时尝试恢复一次。使用不含玩家资料的无效 OpenID 断言，必须由官方正常拒绝才算通过。保留官方证书、主机名、SNI及SSH主机pin，既有鉴权、账号、存档、订单和云端配置不改。不停止 Dota、Steam 或其他 SSH。

若提示仍无法连接 Steam：先确认本机可用网络／加速节点已连接，必要时换节点，再双击一次。若提示“云端登录服务不可用”“中转身份不符”或仍失败，保留窗口中的安全结果交给维护者；不要手动删除进程回执或关闭其他 SSH。工具运行时无后台常驻，不安装定时任务，不自动更改网络设置。

当前临时方案依赖作者电脑和网络持续在线；电脑关机、休眠或中转断开会影响新的 Steam 登录。这个入口解决手动恢复便利性，不代替稳定云端出站，也不代表商城空白／每日回执已修复。

命令行默认只读检查：`python -B -X utf8 tools/workshop_test/repair_steam_login.py`；显式恢复加 `--repair`。固定私钥仍只在本机既有位置供 SSH 使用，不复制到脚本或报告。双击入口定位项目目录，不依赖当前命令行路径。安全摘要保存在忽略目录 `output/steam_login_repair/last_result.json`。

成本：仅用户手动触发，无定时器、自动重试或场景集合。初始化和每次稳定检查均为 O(1) 时间／空间（固定上限回执与字段）。正常检查一次固定SSH调用，云端各一次监听查询、服务PID查询、health及Steam官方请求；恢复时最多两轮检查，加一次既有stop/start。最多三次本机精确PID身份核对，无进程全量扫描。跨进程文件锁防重复双击，退出或崩溃自动释放，不因遗留锁文件永久阻塞。生产官方TLS探针耗时与隔离测试的调用计数分别记录，不作为游戏FPS证据。
