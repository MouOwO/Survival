# 手动恢复 Steam 登录

遇到 `steam_verification_unavailable` 时，在**作者这台电脑**双击项目根目录的 `修复Steam登录.cmd`，等待结果。显示“验签通路正常”或“已恢复”后，从游戏重新打开授权页，重新点击 Steam 登录；刷新旧错误回调页仍会显示原来的失败。

工具先检查本机回执及完整进程身份、云端现役配置和真实官方验签通路。正常时不重启；仅在固定中转不可用且身份核对通过时尝试恢复一次。使用不含玩家资料的无效 OpenID 断言，必须由官方正常拒绝才算通过。保留官方证书、主机名、SNI及SSH主机pin，既有鉴权、账号、存档、订单和云端配置不改。不停止 Dota、Steam 或其他 SSH。

飞鸟代理端口会变化，因此本机增加仅监听 `127.0.0.1:18770` 的 Steam 专用桥接器。它从当前 `core.exe` 的回环监听端口中选择能完成 HTTP CONNECT 的端口，只允许连接 `steamcommunity.com:443`。云端固定监听 `127.0.0.1:18768`，经原有固定 SSH 反向通道接入桥接器；TLS 仍由云端对 Steam 官方主机名和证书进行验证。稳定连接复用已验证的端口；若端口变化或旧端口失效，下一次验签立即重新发现，无需手填 `20874` 等端口。代理未运行或不能连接 Steam 时明确失败，不绕过官方验签。

若提示仍无法连接 Steam：先确认飞鸟代理正在运行并能访问 Steam 社区，必要时换节点，再双击一次。若提示“云端登录服务不可用”“中转身份不符”或仍失败，保留窗口中的安全结果交给维护者；不要手动删除进程回执或关闭其他 SSH。工具运行时保留一个本机桥接进程及一个 SSH 中转进程，不安装定时任务，不自动更改网络设置。

当前临时方案依赖作者电脑和网络持续在线；电脑关机、休眠或中转断开会影响新的 Steam 登录。这个入口解决手动恢复便利性，不代替稳定云端出站，也不代表商城空白／每日回执已修复。

2026-11-19：CONNECT 200不能证明Steam可达。桥接器现在通过两个固定HTTPS DNS查询取得Steam公开IPv4；只有官方主机名、SNI、证书验证成功且Steam正确拒绝匿名无效OpenID断言，才缓存路径。缓存尊重DNS TTL，上限60秒；到期先更新同一端口，失败后才扫描其他飞鸟端口。DNS正文上限8192字节、最多32条记录/取2个公开A地址，拒绝重定向，不保存玩家断言。真实授权仍由云端独立校验。桥接进程直接使用Python真实基础解释器启动，避免Windows venv启动器退出后遗留实际监听子进程。身份不明的监听仍拒绝接管。

命令行默认只读检查：`python -B -X utf8 tools/workshop_test/repair_steam_login.py`；显式恢复加 `--repair`。固定私钥仍只在本机既有位置供 SSH 使用，不复制到脚本或报告。双击入口定位项目目录，不依赖当前命令行路径。安全摘要保存在忽略目录 `output/steam_login_repair/last_result.json`。

成本：无游戏帧循环、定时扫描或场景集合。桥接器首次连接或端口失效时各读取一次当前进程／TCP监听表；本机实测表14,160行、`netstat` 一次178 ms、候选4个，最多尝试8个本机回环端口。稳定连接按缓存端口只做一次 CONNECT，O(1) 时间和空间。变化时发现成本为 O(L+P)，L 为系统 TCP 表行数、P≤8 为候选端口数；每条 Steam 连接最多256 KiB/方向、20秒空闲超时、最多8个并发。正常工具检查一次固定SSH调用，云端各一次监听查询、服务PID查询、health及Steam官方请求；恢复时最多两轮检查和一次既有stop/start。本机精确PID身份核对与跨进程文件锁保留。生产官方TLS探针耗时不作为游戏FPS证据。

新版补充：TTL内100次稳定生产函数调用实测为100次CONNECT、0次系统扫描、0次DNS/预探针。TTL到期仅刷新缓存端口；冷启动/端口故障才扫描。每端口最多2个DNS服务，每服务最多2个地址的官方TLS/拒绝探针；有10秒单调时间准入预算，每个阻塞网络阶段最多3秒、系统查询各最多5秒，因此10秒不是硬实时总上限。冷路径实际探针5.71秒，实际运行桥接器TLS往返6.71秒；网络样本不代表每位玩家耗时。
