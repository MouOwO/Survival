# 无尽称号发布

按历史最高无尽层数解锁，1–80、81–160各为一档。现有九个称号的门槛是1、81、161、241、321、401、481、561、641层；超过第九档继续显示最高称号。默认自动选择最高已解锁档位，手选较低称号后可点击当前称号恢复自动。

本次最终发布以`fbf16c3e996f…`收藏稀有度版本为父包，候选为`60d6ce00a7d3…`，保留其全部收藏配置、兼容策略及商城规则。最初的`c9ddeb8…`离线草稿未部署。

所有发布输出都在忽略目录`output/endless_titles_80_20261016`。父不可变包是外部发布输入，未纳入Git；新电脑需通过`build_release.py --parent-bundle PATH`提供完整、哈希匹配的父包目录。

经明确授权的发布顺序：

1. `build_release.py`：构建并验证称号差异，不改运行指针。
2. `preflight.py`：通过已有固定主机密钥SSH连接，只读核对版本、函数安全设置和真实PostgreSQL配置指纹。
3. `finalize_release.py`：核对证据，生成精确配置准入SQL与不可变发布包。
4. `deploy_driver.py check`，然后依次执行`upload`、`backup`、`prepare`、`validate`、`activate`、`verify`。
5. `install_local.py`：仅在匹配的激活、核验报告均成功后更新本地游戏指针。

`validate`在事务内执行8项配置负例并回滚，再核对所有业务表；真实Lua结算器另验证27项称号规则。激活仅登记新配置和新增该配置的精确准入分支，不批量改玩家存档。玩家加载或后续结算时重新判定默认称号。

旧不可变包、配置及备份保留。`deploy_driver.py rollback`可切回准备好的父规则版本；回滚不删除已登记配置或恢复玩家数据，启动新对局前还需对应恢复本地指针备份。

本地配置模块在地图启动时加载，完成发布后需重新开图。已运行的旧对局继续使用旧配置哈希；本次未添加使旧会话强制升级的兼容规则。
