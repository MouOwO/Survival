# WS4 游戏内商城目录不同步

2026-10-31 实际复现：原游廊包的存档合同为已发布 `d573588b64d2...`，四人 WS4 API 仍为 `47accd81d922...`；用已批准游戏会话执行只读 `commerce_catalog`，后台返回 `archive_config_mismatch`。登录、公开网页目录以及现金商品目录可用，并不代表游戏内钱包目录可用。

修复目标是四账号独立 WS4 实例，不是另一套已更新的原 API。候选从冻结的 `20261029-archive-d573588b64d2` 复制，保留原 WS4 `workshop_test` 鉴权包装、独立库、密钥、端口与访问范围；不修改支付服务、商品价格或玩家数据。SQL 只补齐已发布合同，原有配置分支保留；独立库没有匿名角色，因此仅省略对不存在角色的 REVOKE，实际 PUBLIC/app/service_role 撤权保留，不创建角色。

默认不执行正式切换。准备流程为：

```text
driver.py plan
driver.py upload
driver.py prepare
driver.py clone
```

`clone` 明确使用 `pg_dump --schema-only`，检查恢复清单不含 TABLE DATA 或序列值。副本只加入公开不可变配置和事务内的合成测试账号；不复制真实账号、存档、余额、回执或订单。失败副本、旧工具版本和私有诊断保留，不重复使用失败数据库。

正式阶段必须取得本次明确授权，且需要 `--apply`：

```text
driver.py quiesce --apply
driver.py protect-backup --apply
driver.py activate --apply
```

正式阶段先检查没有未处理存档操作／待处理订单，仅短停 WS4 API，保留支付和认证服务。服务器生成私有完整备份；作者电脑只保存 DPAPI 密文，并校验实际解密摘要，原始备份不写入 Git。修改前检查原文件／数据库基线、候选 hash 与备份时效；迁移前后逐表核对玩家和支付行摘要不变。失败时使用旧合同的安全代码恢复，额外 SQL 合同保留，不用旧备份覆盖后续玩家数据。`resume` 用于备份或确认失败后的安全恢复。

2026-10-31 用户已明确授权上述备份与同步，正式合同已补齐，WS4 正在运行 d573，启动文件与实际进程一致。完整备份为506,916字节；本机DPAPI密文已实际解密核验，原始备份仅留服务器。玩家／支付业务表迁移前后29张一致，受保护的七项服务PID全部未变。用户重新登录后，经内部API只读取得126项钱包／48项现金商品；但用户当前原生客户端仍显示目录未连接，暂停与游戏端分包／传输仍待定位。不能写成商城整体修复完成。

首次切换的健康探针误用了基础 `FISHING_API_TOKEN`，被WS4的Valve凭据pin包装拒绝，触发安全版回退；当时 `systemctl start` 对已运行的新进程没有重启作用，造成启动文件为安全版、实际仍为新版。已修正探针：只复用现有登录侧上游凭据，先核对其pin，再请求配置；不新增pin或绕过鉴权。失败回退先停API再换启动文件。8项本地检查包含已批准身份发送正确凭据、未批准身份在HTTP前被拒绝。

对此次已经存在的精确状态，`driver.py reconcile --apply` 只在实际进程为新版、磁盘启动文件为安全版、合同与已验证副本一致、原始及加密备份匹配、799份候选字节与鉴权包装均一致时，对齐启动文件并重新验证。它不重复SQL、不重启运行API；失败回执和operator v6保留，实际修复使用新封存v7。该恢复入口同样要求明确授权。

## 成本与证据范围

这些是显式运维阶段，不加入游戏帧循环、定时刷新或商品请求热路径。F 为候选文件数（本次 799），T 为数据表数，R 为单表行数，P 为目录商品数。

| 路径 | 执行频率 | 时间／空间成本 | 调用与边界 |
| --- | --- | --- | --- |
| 源码校验／候选复制 | 准备、验证、切换各一次 | O(F＋总字节)，顺序读盘 | 原有活跃玩家请求不做此扫描 |
| 结构副本 | 每次显式验证一次 | O(schema 字节＋公开配置字节) | 0 个真实玩家数据行复制 |
| 行摘要 | 每次迁移前后各一次 | 每表 O(R log R)，聚合文本 O(序列化表字节) | 用于证明原玩家／订单行不变，不加入在线请求 |
| 恢复探针 | 最多20轮 | O(20)，O(1)空间 | 固定回环配置查询；不会循环扫码／支付 |
| 本次启动配置对齐 | 显式恢复一次 | O(F＋总字节＋schema)，O(文件字节)临时空间 | 校验799文件；数据库仅结构/合同读取，无玩家行复制与重复迁移 |
| 商品读取 | 原有实现不改 | 保持原有 O(P) | 不新增游戏轮询或原生桥调用 |

`test_operator.py` 验证本地边界与实际 SQL 转换。远端结构副本运行真实 Python→Lua→PostgreSQL 回执测试。模拟、结构副本和正式 API 启动证据分别记录，不能代替实际玩家重新打开商城的确认，不能称为实机 FPS 优化。私有回执在 `output/shop_online_20261031/`。
