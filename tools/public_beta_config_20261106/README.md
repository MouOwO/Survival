# 公测配置精确授权

仅准备，正式Git绑定入口尚未运行或登记配置。现役函数摘要 `8d2b3fc8…` 没有新 `f8ab7087…` 配置的授权；新API启动会调用 `archive_sync_config`，必须先完成此项。V5完整真实PG探针已通过：2个旧配置、7类伪造拒绝、重复登记、事务回滚及函数规范化摘要均通过，持久化写入0。正式冻结后仍须重新执行绑定源提交和工具提交的prepare/probe/activate/verify，不能以V5排演代替正式发布步骤。

默认 `plan` 不访问远端。正式入口依次为 `prepare` → `probe` → `activate` → `verify`，均需源提交和工具提交：

```text
python -B tools/public_beta_config_20261106/deploy.py prepare --source-revision <40位提交> --operator-revision <40位提交>
```

- `prepare` 只读核验固定WS4数据库和旧函数/owner/ACL/配置摘要，并在挂载树外保留旧函数、元信息和全部精确产物。
- `probe` 读取两条旧配置，运行真实PostgreSQL的两个 `pg_temp` 函数和临时表，验证旧配置兼容、新配置精确登记、重复幂等、7类伪造拒绝、子事务失败回滚和PG函数规范化。最终整个事务回滚，无持久化写入，无玩家数据访问。
- `activate` 在单个事务中锁定配置登记，复核原始摘要，仅增加新hash与对应JSONB摘要的授权分支和一条不可变配置。旧分支、旧配置、函数owner/权限保持不变；不修改玩家、不运行其他DDL。
- `verify` 仅验证函数和配置摘要。`recipe.verify_sql()` 本身不包含提交/回滚，可由联合WS4部署的只读事务调用。

SQL失败不自动重试，未提交事务自动回滚。若已提交后通信中断，先用只读verify核查，不再次activate。API程序回滚时保留已提交的新配置授权及配置行，因为可能已有耐久回执引用，不得自动删除。
每个source/operator/产物绑定使用独立控制目录，目录名包含绑定摘要，旧记录不可覆盖。

此工具不运行游戏、重启服务或操作玩家。真实PG probe尚未运行前，单元测试不得写成数据库验收完成。

构建与校验各为一次性 O(配置及函数字节数)；当前旧配置数2。无新增运行时轮询，新分支仅在新hash启动登记时校验对应配置摘要。
