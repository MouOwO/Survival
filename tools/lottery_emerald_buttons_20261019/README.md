# 幽林翡翠：按钮五轮评审

固定用户选定的幽林翡翠主题，五轮按顺序累积调整按钮。HTML 默认显示 R5；可切换轮次、四个正式奖池，以及正常、悬停、按下、焦点、票券不足、开启中状态。

这是离线设计评审。背景、主按钮和单抽按钮沿用官方素材，奖池名称、费用、奖品与保底文字来自当前项目 CSV。余额、开奖结果与记录均为本地样例，不调用游戏、账户或支付接口，也不修改生产界面。

## 文件

- `rounds.cjs`：每轮累积样式。
- `build.cjs`：使用已选主题和正式奖池数据生成独立 HTML。
- `capture_round.cjs`：单轮画布与按钮截图。
- `verify.cjs`：最终五轮布局、按钮状态和本地交互验证。
- `native_verify.cjs`：使用真实 Panorama 源码和安装包官方纹理做独立离线检查，不连接游戏或账户。
- `compile.ps1`：只备份、编译并校验本轮两份展示层源文件。
- `integration.patch/json`：本轮展示层与测试期望的独立差异，以及基线和验证哈希；工作区已应用，勿重复应用。

评审入口：`design_refs/lottery_emerald_buttons_20261019/幽林翡翠_按钮五轮优化.html`。图片已嵌入，可直接以 `file://` 打开。

## 运行

在项目根目录执行：

```powershell
node tools/lottery_emerald_buttons_20261019/build.cjs
node tools/lottery_emerald_buttons_20261019/verify.cjs
```

输入依赖是五套官方方案构建生成的 `output/lottery_five_official_20261019/data.json`。验证不会重建或修改 HTML、轮次样式和正式 CSV。

当前环境 C 盘空间已满；自动化执行使用 `require_escalated`、`login:false` 的执行通道。浏览器复用现有 `tools/market_filter_20261017/browser.cjs`，隔离 profile 保存在 D 盘项目下。不要为运行本工具清理用户其他文件。

## 最终验证范围

- 五轮 × 四奖池 × 1920/1280，共 40 个布局组合；固定参考画布 1672×941。
- R5 单抽 220×84、十连 244×84，标题 28/32、费用 18/26、券图标 52×36，加号和关闭点击区域 44×44。
- 六种按钮状态的真实样式差异、禁用和忙碌时不扣本地券。
- 单抽、十连、确认、再开、动画完成和跳过、四种弹层关闭及键盘 Enter。
- 真实奖池 CSV 数据、全部嵌入图片解码、五画布对比、390px 无横向溢出、无网络请求。

输出目录：`output/lottery_emerald_buttons_20261019/qa/`。

- `report.json`：自动检查与测量结果。
- `browser/`：每轮完整画布、按钮局部、R5 六状态和交互截图。
- `五轮按钮对比.jpg`：仅由本轮浏览器截图拼合，保留各按钮截图的原始比例，不编辑用户提供的原图。

自动检查通过后，还需目检按钮字色、费用可读性、材质高光和四周留白。浏览器截图不能代替 Panorama 实机验证。

## 本轮结果与生产状态

五轮评审通过 101 项检查、40 个布局组合和四个奖池抽奖链。真实组件检查另覆盖两分辨率、四奖池、八个奖励预览、按钮热区、禁用状态，以及仅发出一次原回调。检查发现原生八奖励下的保底文字会遮住最后一个名称，已移到十连按钮下方，并加入几何检查。

`lottery_gw2.js/css` 已接入主题并成功编译到游戏资源。实机打开了更新后的界面，但当前对局的权威数据返回 `lottery_revision_invalid`，因此不能把本轮离线抽奖结果称为实机抽奖成功。

这两份生产源文件、对应编译资源与主测试开始前已有用户未提交修改。本轮保留其完整工作区状态；独立补丁仅记录本次变更，排除了并发写入的菜单缩放与 tooltip 缩放修正。不要把补丁直接用于旧 HEAD：它明确依赖 `integration.json` 中的既有基线。正式文件待这些既有修改一并归档后，可按正常流程提交；本次提交只包含本目录的工具和独立差异，不会替其他任务提交代码。
