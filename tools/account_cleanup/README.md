# 远程账号清理

根目录双击 `远程清理账号.cmd`。仅在保存了项目既有 SSH 私钥的维护电脑使用；工具通过固定主机密钥连接 WS4，不向游戏、网页或 HTTP API 添加管理入口。

1. 输入 Steam AccountID 或 SteamID64，不接受昵称或局内玩家槽位。首先只读预览，显示目标、各表行数、兑换占用和未结订单。
2. 确认玩家已退出旧对局。只有输入 `DELETE <预览显示的AccountID> STOP WS4` 才实际清理；其他输入退出。
3. 完成后目标玩家重新开局、重新网页授权。不要继续使用旧对局的内存数据。

工具代码必须与当前 Git 提交一致。源码、数据库结构、服务路径或预览之后的账号数据发生变化会拒绝操作，需要重新预览。不存在的账号也会拒绝。

## 范围

清理目标账号的永久属性、存档、库存、权益、排行榜、奖励及幂等记录、每日限额、在线时长记录、对局会话、支付/充值记录、兑换尝试与领取记录、旧网页认证和账号限流记录。清除兑换领取时同步归还该码的限量占用，可重新领取尚有效且仍有名额的码；兑换码定义、期限、奖励定义不变。

保留身份注册行并提高档案版本、恢复初始状态；保留管理员准入白名单及 enabled 值。其他账号、商品/配置、兑换码定义、共享 IP 限流和 Steam 防重放 nonce 保留。外部支付渠道的交易记录不在此工具控制范围，不发起退款。订单必须全部为 delivered/closed，否则阻断，不能跳过。

实际操作会短暂停止 WS4 网页、支付、存档三个服务，影响该环境所有在线玩家的请求。先备份完整 PostgreSQL 与认证 SQLite，校验后才清理。业务删除在单事务内，唯一需要临时解除的奖励不可变触发器会在同事务内恢复；不关闭全局触发器。认证撤销先提交，业务失败时可能需要玩家重新授权，结果会明确记录。

## 回执与失败处理

- 本机：`D:/Survival_本地工具/runs/account_cleanup/run_*`，保存预览、请求号和结果，不保存原始账号行。
- 服务器：`/root/goufayu_upload/account_cleanup/run_<请求号>`，保存 root 私有完整备份、目标行及事务回执。不要转发这些文件。
- 实际执行返回及结果未知时，本机用固定的已提交登记工具运行 `record --receipt`，保存登记回执；登记失败会明确显示并保留原回执，不自动扫描或删除备份。
- 默认不重试。SSH 断开或结果未知时，按输出的请求号只读查询：

```powershell
& '<项目Python>' -B -X utf8 tools/account_cleanup/cli.py status --request-id '<32位请求号>'
```

`ACCOUNT_RESET_COMPLETE` 或 `ACCOUNT_RESET_COMMIT_RECONCILED` 且 `ok=true` 才表示已完成并恢复服务。若 `database_commit_unknown=true`，工具保持写服务停止，需维护者结合提交前后指纹核对，不能再次执行清理。若 `service_restart_failures` 非空，仍须恢复列出的服务。备份保留，不自动回灌覆盖其他玩家数据。

脚本化预览：`cli.py preview --account <ID>`。脚本化执行需要同时提供 `--plan`、该文件 `--sha256` 与完整 `--confirm`，见 `cli.py --help`。不要把真实账号用于回归。

## 成本与验证边界

无游戏循环、轮询或游戏网络新增调用。手工预览对 23 张目标表按身份读取；每表先做行数/字节预算再排序摘要，总上限 10万行/100MiB，SQL 单次30秒。按账号索引的查询成本取决于目标行数 K，排序约 O(K log K)、保存目标行空间 O(K)；兑换定义和计数核对另扫描兑换表/领取表，完整备份 O(全库字节)，仅在明确确认后维护期间执行。维护总期限300秒，单服务命令30秒、备份180秒；不是后台持续任务。

已用线上结构的空白 PostgreSQL 克隆及合成双账号验证清理、完整备份恢复、回滚、触发器恢复、兑换名额、另一账号不变、未结订单/旧计划/结构变更拒绝。未对真实账号执行清理；真实维护时长和服务停止恢复未以合成测试替代。
