## Read-only publication preflight and explicit update

```
python -B tools/arcade_portrait_release_v03_20261101/publish_v03.py
python -B tools/arcade_portrait_release_v03_20261101/publish_v03.py --preflight --report-sha256 PACKAGE_SHA --review PRIVATE_JSON --reviewed-evidence-sha256 ROOT_REVIEW_SHA
```

Preflight performs full local authentication and evidence checks, zero SDK.
In addition to script faults, the actual engine log must contain none of:
`NETWORK_DISCONNECT_SNAPSHOTERROR`, `Failed to serialize CustomGameEvent`, or
`SendData ... reliable data too big` (case insensitive). These are known actual
failure families; root review booleans cannot override them. A failed candidate
requires a new scope/source/plan/signature and new native evidence.

Only after every actual acceptance and authorization can root use the same
arguments with `--apply`. The tool repeats admission before the SDK, preserves
all nineteen historical journal entries and previous_release, uses the original
item and Unlisted four-account listing and writes no backend/player/order data.
Unknown/pending state and duplicate already-submitted updates are refused. No
APPROVED_CLOSURE constant is populated and the old development gate is not used.
Final normal Workshop performance remains a separate post-upload test.

## Isolated verification boundary

The four tests use mocks only for SDK, OS/Win32, input and signing. The build
review-copy regression really writes seventeen synthetic review files to a
private temporary directory but never reads a key or produces an executable
signed package. Network-fatal negative tests append each diagnostic to the
synthetic final engine log, update its SHA, then require whole-preflight refusal
and zero SDK/journal mutation. These tests cannot establish native correctness.
