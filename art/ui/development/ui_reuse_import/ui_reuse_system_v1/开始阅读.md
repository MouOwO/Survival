# 苟发育 · 统一 UI 复用方案 V1

以后以共用组件组装页面。窗口外框、标题栏、关闭入口、背景处理、按钮、页签与卡片尽量共用；商品、奖励、英雄、标题与业务数据从配置传入。仅在现有组件无法表达需求时新增资源。

本次完成的是旧素材盘点、统一资源目录、组件规格和迁移文档，尚未修改游戏工程，也未把所有旧素材精修为可直接发布的透明分层。

## 本次交付

- 盘点6个旧素材包中的601个图片文件。
- 找出21组文件字节完全一致的重复资源，共22份重复副本，占67,615,873字节，约64.5 MiB。这是旧包文件层面的统计，不是游戏运行显存节省量。
- 选出65个稳定资源ID：52个共用资源，13个页面专用资源。新包中的文件与选定旧源逐字节一致，本次没有重新生图。
- 建立100条旧路径→新资源ID映射，区分完全相同文件与需要视觉校准的替换候选。
- 定义22种组件和7类页面组合，所有资源、别名和组件引用已校验。
- 原包不删除。精确裁片继续作为还原基准，生成补绘、估算alpha和程序状态图仍保留来源标记。

## 必须区分的三个层面

1. 组件复用：所有窗口调用同一个ModalShell，即使窗口尺寸和内部布局不同。
2. 资源复用：同一按钮底板、同一关闭图标只维护一个资源ID，可有多个控件实例引用。
3. 业务复用：展示组件复用，购买、抽奖、存档解锁等业务规则仍由各自系统管理，不能合并成错误逻辑。

现有窗口边框没有完备的干净透明九宫格；需选定一个窗口母版后一次性精修，随后所有窗口共用。详情见补齐清单。现在可先做统一结构、资源引用和组件状态页，不能用带背景的边缘裁片硬拼后声称已达到原图效果。
