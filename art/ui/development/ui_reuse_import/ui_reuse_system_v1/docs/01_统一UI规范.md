# 统一 UI 规范

## 美术只维护一个主题

主题为青蓝、玉白、细香槟金边；顶部功能入口使用灰白单色小图标。保留幻想RPG的材质与轻微细节，减少额外装饰。商城五分栏共享外框、标题和页签，内部换普通商品、礼包或VIP条件单元。不得再分别生五张完整框架作为运行资源。

颜色、字号与时长集中在design_tokens.json。该文件是统一化建议，不是从效果图逐像素取样的结果；迁移时在一个组件样例页统一校准，校准后全项目引用同一份。

## 共用层与变化层

|层|共用内容|页面允许变化|
|---|---|---|
|游戏场景|实时游戏画面|相机和游戏内容由游戏决定|
|全屏页面场景|同一主题的背景板、渐暗层|背景ID、主题立绘、少量主题色|
|ModalShell|外围遮罩、细框、标题栏、关闭图标、内容槽、底栏|窗口尺寸、标题、侧栏或顶部页签、内容|
|FullscreenShell|顶部导航、关闭入口、阅读渐暗层、底部操作槽|主题画、标题、活动内容、按钮数据|
|基础组件|IconButton、ActionButton、NavToggle、TabBar、CardShell等|文字、图标ID、状态、事件回调|
|业务组合|ArchiveCard、ProductCard、BundleCard等共同布局规则|条目、价格、条件、数量、概率、奖励图案|

外框“相同”指角部形状、边线粗细、材质与组件实现一致，不强制全部窗口同宽同高。存档窗口可更窄，商城更宽；圆角/削角不随窗口拉长变形。

## 背景策略

局内存档/商城：实时地图 → 半透明黑色遮罩 → ModalShell → 内容。禁止把生成效果图中的地图截图永久盖在真实游戏上。

抽奖等全屏美术页：SceneLayer → 可选主题立绘 → 渐暗层 → FullscreenShell → 内容。同主题页面可以引用完全相同的sceneId；需要不同主题时只换主题资产，继续复用导航与控件。不要把按钮、标题、价格和背景合成一张运行图。

目前scene.treasure是现成宝箱与景观合成板，可继续作为抽奖主题背景共用；它不是“无宝箱纯景观”。现有素材无法无损分出被宝箱遮挡的景观。中性共用纯背景是可选一次性补齐项。

肉鸽三选一可覆盖实时地图，并复用渐暗处理；无须强行放上抽奖宝箱背景。游戏HUD保留独立轻量结构，不套进大弹窗框架。

## 边框、文字、图标与状态

- 干净窗口框定稿后采用九宫格：四角保持原比例，左右边只纵向延展，上下边只横向延展，中部用独立底色/底纹。不能整张窗口图片横向拉伸。
- 标题栏、顶部冠饰（若保留）、关闭按钮、边框、内容背景各自独立。冠饰不能被九宫格拉长。
- 同一功能用同一语义图标ID；不同功能不能为了少几张图都用同一个星形。主界面灰白图标与存档类别符号可以是同主题下不同用途。
- 返回官方退出入口与关闭当前弹窗必须是不同动作。图标近似不代表行为相同。
- 图标PNG画布大小与图形大小分开。64×64画布内只有约28px图形时，不能再把整图缩至28×28。
- 图片不烘焙文字、价格、倒计时、快捷键与current/required。文字由同一字体/排版系统渲染。
- normal、hover、pressed、selected、disabled、busy作为状态，不为每个页面另画一组。selected和hover并存时保留选中状态，禁用态阻止交互。
- 顶部图标悬停只提亮，不放大；肉鸽牌保留103.5%悬停放大。不是所有控件都用同一动效。
- 进度角标显示当前/目标；目标来自配置，不写死10。未提供进度字段时隐藏。
- 检查框的checked与disabled分开，切换两张不同画布素材时按图形范围对齐。
- VIP未达成只禁用购买，条目仍然可以读详情。

## 三种卡片不能粗暴合并

共用CardShell和状态处理，但保留三种布局：方形奖励/存档卡；横向商品/组合礼包卡；竖向翻面肉鸽牌。它们共享配色和边框原则，不通过直接拉伸同一整张PNG完成。肉鸽旧牌面与立绘已合成，本次保留为页面资产；后续扩展时只做一次框与立绘分层。

## 新页面准入规则

先查组件与资源ID → 能复用则直接组合 → 需要新语义图标或新插画时补一份并登记 → 在共用状态页验证 → 接入页面。禁止在页面目录复制common_button、common_close、common_frame后改名。若确实需要新皮肤，以组件variant登记并写清原因。

共用皮肤只维护一处。页面业务只传数据与事件，不直接指定散落在旧包中的图片路径。
