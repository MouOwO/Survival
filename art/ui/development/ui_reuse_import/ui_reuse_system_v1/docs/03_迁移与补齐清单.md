## 一次性补齐项

|事项|现状|完成标准|
|---|---|---|
|干净共用窗口边框|原裁片带背景；整块shell带固定布局|固定四角、四边与中心透明区，有经过验证的切片内距；至少两种尺寸无变形|
|标题栏与正文底纹|只有小样本或合成底板|一套可延展/可平铺的材质，或使用统一纯色/渐变；无接缝|
|中性全屏背景（可选）|已有宝箱合成主题板，未分出纯景观|若多页面需要无主题场景，只补一张共用纯景观；否则继续用同一主题板|
|极简商城/搜索图标|尚无批准的独立源|从现有项目已验收同义资源复用，或各补一份后统一登记|
|完整状态对齐|部分旧hover/on/off边距、轮廓不一致|在共用状态页对齐一次，再迁移所有引用；不按页面分别调|
|旧总览文件损坏|archive_ui_kit_v1/reference/components_generated.png无法严格完整解码|仅为旧总览，不纳入共用运行资源；单独裁片通过本次读取与哈希检查|

上述补齐项不阻止先完成组件结构与资源引用整理，但不应在美术精修前宣称“所有窗口已经无损还原”。不需要为每个窗口重绘整套外框。

## 实施顺序

1. 在当前项目确认真正的UI目录、原始资源和现有框架，保留当前工作；本包没有项目源代码，不能猜工程路径。
2. 导入shared资源及注册表，建立统一路径解析。先做小型状态样例页，集中查看关闭、导航、按钮、卡片、复选框。
3. 实现ModalManager与ModalShell的结构，将遮罩、标题、关闭、内容槽与尺寸参数抽离。所有窗口接同一个共用外框ID；外框精修只做一次。
4. 优先迁移存档与商城这两个窗口，验证同一外框在窄/宽窗口中的布局，然后迁移奖池详情和历史。
5. 接入FullscreenShell；抽奖背景继续引用scene.treasure，导航和底部动作复用。肉鸽复用遮罩与组件机制，保留自身翻牌布局。
6. 将主HUD极简入口统一到IconButton，保留原官方行为与底部操作逻辑。
7. 新旧页面对照验证后，停止新页面引用旧路径。旧包移入归档标记即可，未检查真实工程引用前不删除。

## 验收

- 同一关闭、按钮或页签只在注册表维护一份来源；页面不私自复制改名。
- 存档/商城/奖池详情的外框、标题和关闭视觉一致，窗口尺寸可不同。
- 动态文本、数字、币种、倒计时、解锁进度与状态都从游戏数据显示。
- 窗口内点击不关闭；外部遮罩按策略关闭最上层；游戏底层不被误点击。
- 至少检查1920×1080、2560×1440和一种超宽画面。先检查实际逻辑分辨率，防止重复缩放。
- 深/浅/实时地图背景各检查透明边缘，不能出现黑方块或被拉长的角部。
- 切页、反复打开/关闭、跳过动画不会留下重复计时器、订阅或多次提交。
- 成功迁移后提供资源ID引用表、共用组件状态截图和实际游戏截图。不得只以PNG校验通过代替引擎运行验收。
