## 页面迁移

|页面|共用外层及组件|保留的业务与结构|
|---|---|---|
|存档|ModalShell、NavToggle、CardShell、ProgressBadge、ActionButton、Tooltip|原分类与顺序、解锁条件、真实数量、抽奖余额与操作、悬停属性、筛选|
|商城/挑战/研究|ModalShell、TabBar、CardShell 的 product 内容变体、ActionButton、Tooltip|原商店快照、右键购买、科技条件与冷却、库存、木材/金币、挑战和研究入口|
|奖池详情|ModalShell、TabBar、CardShell|保留当前两排四列和列表内部滚动；详情页奖池与主页面所选奖池独立；悬停读取真实名称和属性|
|抽奖记录及说明弹窗|与详情同一 ModalShell 实例|保留真实结果记录、公告/购买/礼包已有功能；没有服务端功能时继续显示原有说明|
|全屏地图抽奖|FullscreenShell、ActionButton、Checkbox、DrawResultSequence|无左侧栏、四个奖池、原消耗/免费条件/保底、真实服务端结果、单抽/十连、跳过及重复提交保护|
|肉鸽|FullscreenShell 实时游戏遮罩、AugmentChoiceGroup、ActionButton、Checkbox|真实候选、原翻牌节奏、103.5% 悬停、选择/重抽及失败回执；不改服务端发奖|
|主 HUD|HUDShell、IconButton|原生技能、物品槽、地图、血蓝条及其事件；返回继续调用官方 Dashboard，关闭窗口走弹窗栈|

本次按新规范恢复了抽奖的真实物品图片，取消此前“所有奖励统一使用星盘测试图”的试用显示。原测试图片仍保留在注册表的项目变体中。

商城现有代码是商店/挑战/研究，不具有文档示例的五类商城业务配置。`ProductCard`、`BundleCard`、`VipBundleCard` 已提供可复用展示接口；没有创建虚假商品、价格、VIP 条件或额外业务页签。旧商城的右键购买与原生商品图不改造成示例购买流程。

## 资源与组件维护

|用途|源文件|
|---|---|
|65 个稳定 ID 及原始质量标记|`panorama/src/ui/resource_registry.json`|

|候选颜色、字号、动效等|`panorama/src/ui/design_tokens.json`|
|22 种组件原始约定|`panorama/src/ui/component_contracts.json`|

|项目现有素材变体映射|`panorama/src/scripts/custom_game/common/ui_project_resources.json`|
|运行时解析表（生成文件）|`panorama/src/scripts/custom_game/common/ui_registry.js`|
|组件实现|`panorama/src/scripts/custom_game/common/ui_components.js`|
|组件状态和已迁移页面的共用外观|`panorama/src/styles/custom_game/common/ui_components.css`|

注册表包含包内 **65 个 ID（52 共用、13 页面）**，另登记 **236 个项目现有变体**，合计 301 个运行 ID。后者保留原文件和用途，不代表 301 张已经统一精修的新素材。候选替代与字节完全一致的资源保持区别；不会仅凭名字相似就把所有旧图替换为同一图。

CSS/XML 中使用 `ui-resource://button.ivory.normal`；JavaScript 使用 `GameUI.CustomUIConfig().SurvivalUI.Asset("button.ivory.normal")`。`ProjectAsset` 只用于已经登记的现有变体集合。真实物品/技能图片继续使用服务端配置与 Dota 原生图片控件。

22 种接口已建立：ModalShell、FullscreenShell、HUDShell、IconButton、ActionButton、NavToggle、TabBar、CardShell、ArchiveCard、ProductCard、BundleCard、VipBundleCard、ProgressBadge、ProgressBar、PriceLabel、Checkbox、Tooltip、FilterBar、RewardGrid、AugmentChoiceGroup、DrawResultSequence、ModalManager。

既有页面使用 `.Adopt(...)` 接入已有控件，保留原 ID 和事件；新控件使用工厂函数。卡片 `bodyVariant` 支持 square/product/augment/outline。outline 皮肤使用包内状态边框，底板不再叠加自带装饰框；装饰底板皮肤不叠加第二层状态边框。原有肉鸽长牌保持独立比例。

## 构建与回查

在项目根目录运行：

```powershell
node tools/build_ui_reuse.cjs
./tools/deploy_shared_ui.ps1 -CheckOnly
./tools/deploy_shared_ui.ps1
node tools/build_shared_ui_preview.cjs
node tools/verify_shared_ui_preview.cjs
```

部署脚本将资源 ID 转换为引擎路径，检查现有 XML 的 ID/事件未丢失，备份后同步到 `content/dota_addons/Survival/panorama`，再调用 `resourcecompiler.exe`。`lottery_window.xml` 是主 HUD 内的布局片段，通过 `survival_hud.xml` 编译，不作为独立根布局编译。

`ui_assets.css` 只作为编译期动态图片依赖清单，不挂到所有页面，避免为了注册素材而给每个窗口额外加载整套资源。旧主 HUD/肉鸽部署入口已转到共用部署流程，避免把未解析的 `ui-resource://` 直接复制到游戏。

源文件首次迁移前的快照在 `baseline/`；每次部署前备份在 `backups/`，最近一次路径记录在 `last_backup.txt`。不删除旧素材，也没有提交/覆盖此前的服务器修改。

- 共用组件：最上层关闭、窗口内外点击分离、重复打开不叠加计时器、禁用/请求中保护、复选框画布对齐、分母缺失隐藏、VIP 未满足只禁用购买、页签状态独立。
- 页面行为测试：存档、商城、抽奖、肉鸽及主 HUD 六组相关脚本检查通过。抽奖重复点击、跳过、关闭、过期响应、确认不再次抽取；肉鸽选择/重抽/失败重试；商城真实币种及购买路由均保留。
- 65 张原始 PNG 的哈希、尺寸和真实 Alpha 通道检查通过；小型状态图另检查透明角及 Alpha 范围。不修改像素，也不将 Alpha 检查等同于实机无黑边。
- 所有部署源通过资源编译，65 个共用/页面运行纹理存在。

仍需完成：

1. **干净通用九宫格外框 `frame.window`**：包内明确缺失。当前集中使用细线玉白/青蓝程序底板，已停用这些弹窗上带旧背景的外框裁片；没有虚构 slice 内距，也没有宣称原图无损还原。拿到干净四角/四边后只需在 ModalShell 中接一次。

4. **搜索/商城专用图标**：没有批准的独立透明源时不使用 emoji 冒充；对应新增业务视觉待补。
5. **指定字体实机生效**：后续字体接入轮已添加三款原版思源 OTF、OFL 授权及共用字体样式，解决原文件名被 Dota 字体过滤规则忽略的问题。Dota 自带字体库匹配及浏览器真实字体检查通过；原生游戏与游廊下载后的验证仍待完成，见 [字体接入记录](../font_import/接入说明.md)。
6. **Dota 实机截图及验收**：需启动测试局后检查原生排版、深浅地图上的透明边缘、不同 UI 缩放、鼠标穿透、反复打开/关闭、技能/背包及 Alt 输入。浏览器截图和资源编译不代替这一步。
