# 每日奖励 UI 接入

已按 `D:/新建文件夹/daily_rewards_ui_v1/daily_rewards_ui_v1` 包接入并编译。窗口为 1348×758 设计面板，对应 1672×941 参考画布；由现有 ModalShell 根据 Panorama 的实际 UI 缩放统一适配。窗口采用包内 32px 边角九片，未将带地图或烘焙文字的 exact 图片用作运行时背景。

## 复用与新增

- 复用 `SurvivalUI.ModalShell`、`ActionButton.Adopt`、`CardShell`、`Tooltip.Bind`、`State`、`Lifecycle` 和 `SurvivalUILayers`。图标按钮复用 State 的交互规则，并使用本页四态局部皮肤。
- 旧 `button.ivory.*`、`icon.close`、`icon.pool_details` 等共享 ID 保留。补签、购买和返回按钮沿用共享 ActionButton；每日关闭、说明及通行证图标使用包内 local 版本，不覆盖旧图标。
- 新增 `daily.*` 与 `shared.candidate.daily_window.*` 共 64 个资源 ID，文件哈希与 manifest 核对；完整映射见 `reuse_mapping.json`。
- 六张卡片复用 `daily.card.empty`；第七张使用 `daily.card.week_end`，普通及专属槽分开显示。标题、天数、名称、数量和状态均为 Label。
- 当前正式奖品是项目原有宝石及碎片，复用包内水晶圆底作为类别插画，名称、数量、属性是原配置；不是参考图里的金币500、木材300等奖励，也不是每种物品的独立最终美术。

## 业务规则差异：待确认

包要求自然周最后一天的高级装备奖励，但仓库只有“累计签到七次循环”和累计7/14/21次通行证奖励，没有自然周重置规则、高级装备候选池和独立补领政策。已向用户询问，尚未收到规则选择。

因此保持原发奖算法、奖励数量、补签、通行证累计奖励与去重逻辑；自然周专属槽明确显示“待配置”，不会凭客户端日期、计数或样例数据发奖。需要新增经济规则时，必须补齐服务端配置及独立领取记录，当前不宣称该功能已上线。客户端独立槽状态已用预览测试覆盖。

服务端快照新增真实物品 ID、当期卡状态、当前卡、周期标识、说明、补签范围和消息序号；客户端不根据自身时钟判断领取资格。数据及逻辑位于 `archive_daily_rewards.lua` 和 `archive_service.lua`。

## 请求与关闭

取消原先两秒后自动解锁。等待服务端保存期间按钮保持 busy，重复点击不发送新领取；成功由快照确认，失败保留上次已确认状态并可重试，旧序号和旧日期快照被忽略，周期切换清除旧操作状态。原服务端幂等结算继续负责不重复发奖。

每日奖励注册到共享层级栈；窗口外遮罩与右上角关闭走同一个 ModalShell 关闭动作，只关闭最上层窗口，不调用游戏退出。窗口内容与遮罩是兄弟节点。物品悬停通过全局 Tooltip 显示真实名称及属性。
