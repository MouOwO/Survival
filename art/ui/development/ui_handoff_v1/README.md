## 明确的缺项及边界

1. 原工程没有 `SurvivalEquipment`、`SurvivalAppearance` 接口，装备/外观图标暂禁用；不以商店等不相同功能替代。
2. BOSS 图包含固定示例文字的整层预览，不能作为运行组件。当前未发现已确认的 UI 触发契约；本轮未接入自动 BOSS 警告，不按每第 N 波自行猜测规则。
3. 属性图标 Alpha 为交接包估算值；底板遮挡区域为交接包重建值。需要在深/浅地形复核透明边缘，不能宣称与精确参考切片逐像素一致。PNG 的透明中心可能保留不可见参考 RGB，运行时依赖实际 Alpha；未将其作为可见技能图案使用。
4. 还需检查：有实际物品时的内容/角标对齐、冷却、拖放、长姓名、大数值、真实英雄/建筑头像、Alt、单位切换与重建。建造者第三格为空但有 G 快捷键，需继续区分原技能图标资源缺失与显示策略，不用参考素材补图。快捷键标签会被原项目控制器再次设置样式，部分帧仍显得偏小，不能把 25px 的设置值当成完整视觉通过。
5. 模拟覆盖 1024×768、1280×720、1672×941、1920×1080、3440×1440，共 45 种分辨率/格数组合；其他分辨率和 10/12/16+ 格的实机情况尚未验证。大量技能时整体字号也随父级缩小，需要人工确认可读性。
6. 包里顶部与底栏是不同画布，没有一张带实时小地图、现有全部额外入口的统一最终全屏稿；当前整合锚点需要用户以实机截图验收。现有其他窗口未改版。
7. 热重载曾继续使用旧版本 JS，并出现既有控制台命令重复注册日志。正式视觉验收应冷启动测试插件，避免混用缓存中的版本。
