# 思源字体接入记录

本轮按 `字体使用与AI接入说明.md` 接入三款原版静态 OTF，并统一当前存档、商城、地图抽奖、奖池详情、肉鸽卡牌和 HUD 的字体角色。窗口布局尺寸、真实奖励与业务接口保持原状。

## 文件与字重

| 用途 | 字体内部名称 | Panorama 字重 | 随游廊分发的文件 |
| --- | --- | --- | --- |
| 正文、属性、tooltip、进度和数字 | Source Han Sans SC | normal / 400 | `panorama/fonts/Radiance-Survival-SourceHanSansSC-Regular.otf` |
| 按钮、分类、入口、小标题 | Source Han Sans SC | medium / 500 | `panorama/fonts/Radiance-Survival-SourceHanSansSC-Medium.otf` |
| 窗口标题 | Source Han Serif SC | bold / 700 | `panorama/fonts/Radiance-Survival-SourceHanSerifSC-Bold.otf` |

仅分发这三款字体，合计 58,597,892 字节（约 55.9 MiB）。原包附带的 Sans Bold 和 Serif Heavy 未接入。

**兼容前缀的原因：** 当前 Dota 的 `game/core/panorama/fonts/fonts.conf` 使用 `<fontpattern>` 按文件名过滤字体。独立进程加载这份真实配置后，以原始文件名调用 `FcConfigAppFontAddDir` 无法匹配到字体；给文件名添加 `Radiance-Survival-` 前缀后，可以匹配到三款字体的正确文件。这里利用已有 `Radiance` 文件名前缀规则，**没有修改字库字节、内部字体名、字重或格式，也没有替换 Dota 的 Radiance 字体**。

三份 OTF 的 SHA-256 均与附件 manifest 一致。原文件名、版本、版权来源与哈希记录在 [字体清单](../../panorama/src/ui/font_manifest.json)。两份原始 OFL 授权随包放在 `panorama/fonts/licenses/`。

## 加载和共享样式

- 源文件：`panorama/src/fonts/`；编辑器部署目标：`content/dota_addons/Survival/panorama/fonts/`；游戏原始资源：`game/dota_addons/survival/panorama/fonts/`。
- 当前客户端二进制包含 `panorama/fonts/` 与 `IUIEngine::RegisterCustomFontPath`，文字模块使用 Fontconfig/FreeType，并识别 `.otf`。项目使用这个自定义字体目录，未编造 JavaScript 注册 API，未修改全局 `fonts.conf`，未安装系统字体。
- 字体是原始 OTF 文件，不送给 `resourcecompiler` 编译。部署脚本会校验源文件哈希并同步原始文件，旧无前缀副本只在哈希完全相同时备份后清理。
- [统一字体样式](../../panorama/src/styles/custom_game/common/ui_typography.css) 由三个现有根布局最后加载。旧页面中的 `font-family` 和 `font-weight` 已集中迁移，原字号和布局由各页面保留。
- [主题 token](../../panorama/src/ui/design_tokens.json) 同步记录三种角色。共用弹窗标题改用 `UIFontTitle`，不再以内联 SimSun 覆盖。
- 旧 `archive_gothic.css` 是未引用的历史皮肤，本轮没有重新启用它。
- 技能提示通过共享 `ReadableText` 把不在字库内的 `💰`、`🌲` 显示为“金币”“木材”；原配置、数值和业务计算不变。

## 已完成验证

1. 三个文件的哈希、OTF/CFF 标识、静态字库和 OS/2 字重检查通过。
2. 在独立进程调用当前 Dota 随带的 `libfontconfig-1.dll` / `libfreetype-6.dll`，并读取游戏实际 `fonts.conf`：三种 family/weight 分别选中正确的原版文件。规定的样本文字在 14、16、18、20、24、30、38、44 px 均可栅格化。见 [字体库验证结果](verification.json)。这一步不等于游戏客户端已挂载游廊字体。
3. 扫描 UI 源码、实际 content 文案、本地化、144 份 CSV 及 621 份游戏脚本，合计 1,738 个可打印字符。30 个原字体缺字中，28 个来自已存在的乱码/替换字符，另 2 个为上面的 emoji；emoji 的技能说明显示已处理。其余缺字位置与无法可靠解码的文件在验证结果中列出，没有擅自重写这些旧 CSV。
4. [字样预览](preview/index.html) 使用随包 OTF。Chrome 实际渲染字体返回的 PostScript 名分别为 `SourceHanSansSC-Regular`、`SourceHanSansSC-Medium`、`SourceHanSerifSC-Bold`，不是仅检查 `font-family` 或 `document.fonts.check`。
5. 字样预览通过 1280×720、1920×1080、2560×1440、3440×1440 的边界和裁切检查；截图在 `preview/fonts-*.png`，均为**浏览器预览，不是 Dota 实机截图**。
6. 共用组件与 HUD 行为检查通过；共用组件预览同步加载字体，弹窗缩放与关闭检查通过。游戏 UI 源码已经编译部署，现有 XML ID 和事件绑定保留。

Fontconfig 输出的 `41-repl-os-win.conf` 多值警告来自游戏已有配置；三种字体匹配仍通过，本轮未修改该全局文件。

## 游戏内验收入口与剩余验证

当前没有运行中的 Dota 客户端，因此**未声称游戏内字体已经实际生效**，也未交付冒充实机的截图。还需在不安装字体的游廊下载环境中验证挂载与实际排版。

重新启动工具和本地图后，在 Panorama 调试器选择主 HUD 上下文，在 JavaScript 控制台执行：

```js
GameUI.CustomUIConfig().SurvivalTypography.ShowTest()
```

会打开已编译的 [字体测试面板](../../panorama/src/layout/custom_game/font_test.xml)，包含指定测试文案、长名称、数字和深浅底色。用面板底部按钮关闭，或执行：

```js
GameUI.CustomUIConfig().SurvivalTypography.CloseTest()
```

原生面板没有自动弹出，不影响正常对局。请在常用分辨率核对实际窗口中的物品名称、标题和 tooltip 裁切；如果仍回退，需检查游廊发布包是否包含字体及授权文件、当前客户端是否注册了 addon 的字体目录。设置字体名称与资源编译成功不能代替这一步。

发布包必须包含 manifest 列出的 3 个 OTF 和 2 个授权文件；还没有执行游廊发布/下载测试。不要以往全局游戏目录复制字体或开发机安装字体的方式掩盖打包问题。

## 复现命令

```powershell
node tools/import_ui_fonts.cjs
node tools/build_ui_reuse.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File tools/deploy_shared_ui.ps1
& 'art/ui/development/ui_reuse_import/python/python.exe' tools/verify_ui_fonts.py
node tools/build_font_preview.cjs
node tools/verify_font_preview.cjs
```

`migrate_ui_typography.cjs` 是本轮的一次性、可重复迁移工具，平时调整字体请编辑共用样式和 token，避免每个页面重新定义字体。
