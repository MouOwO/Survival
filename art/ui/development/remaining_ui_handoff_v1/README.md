| --- | --- |
| `prepare.cjs` | 从修改前基线生成候选 XML/JS/CSS；映射交接资源；保留现有业务函数 |
| `common.js` / `common.css` | 公共九宫格窗口、页签/高亮、三态关闭、按钮状态、奖励卡、Tooltip 接入与肉鸽时间线 |
| `lottery_dialogs.css` | 奖池详情、记录、结果排列与按钮样式 |
| `daily.css` | 七天奖励与额外奖励区域、Tooltip 样式 |
| `rogue.css` | 最终透明卡牌的设计尺寸、入场/翻面/悬停 |
| `commerce.js` / `commerce.css` | 商城、礼包、订单显示适配器；无预设商品或支付结果 |
| `deploy_test.ps1` | 仅部署隔离测试插件，保存布局备份，编译并保护正式 UI 与已确认模块 |
| `test_*.cjs` / `verify.cjs` | 复用现有测试，验证真实业务函数保持、状态/请求防护、资源哈希 |
| `compare.py` / `gallery.cjs` | 实机截图与确认图同尺寸对照、证据浏览页 |

本轮生成并实际加载的文件见 `build.json` / `delivery_manifest.json`：三个布局包装 `survival_hud.xml`、`archive.xml`、`rogue_reward_ui.xml`，一份预载布局，一份公共样式，以及公共、抽奖、每日、肉鸽、商城五个版本化脚本。运行 PNG 位于 `custom_game/remaining_handoff_ready/`。

继续复用既有 `SurvivalUI` 的 `ModalShell`、`Fit`、`Lifecycle`、`ActionButton`、`TabBar`、`State`、`CardShell`、`ProductCard`、`BundleCard`、`PriceLabel`、`Tooltip` 及 `SurvivalUILayers`；没有为每页重新实现支付、奖励或选择业务。

## 未解决项与下一轮验收

1. **商城业务代码位置缺失**：目前只找到 `shop_ui.js` 的金币/木材局内商店和 `archive_service.lua` 未配置 provider 的通行证订单钩子。需要实际积分/U币商品、礼包、订单/支付服务再映射到 [显示适配器](COMMERCE_ADAPTER.md)。本轮未伪造价格、支付方法或二维码。
2. **每日规则与确认图不同**：`archive_daily_rewards.lua` 返回 `claim_count` 周期及 `premium.status=unconfigured`。自然周末高级装备需要业务方提供已确认配置，不能在 UI 里补造。
3. **精确分层外框缺失**：奖池包说明明确外框、标题和关闭部分仍烘焙在参考图里。当前用同一交接体系的公共九宫格框，颜色/内沿/标题装饰与参考仍有差异；先验收结构和功能，不标成像素级完全还原。
4. **奖品美术与概率**：实际 Dota 小图固有深色背景和低分辨率仍在；没有用星形占位替代真实奖品。缺少可靠概率字段，概率行隐藏。
5. **字体分发**：本机思源黑体/宋体已通过之前的实机字体测量验证，见 `../archive_handoff_v1/client_font_validation.json`。这不证明其他玩家仅下载 addon 就能加载字体，跨客户端分发尚未验证。
6. **第二分辨率**：尝试修改窗口外框后引擎仍保持 1672×941；控制台未返回可验证的 addon 握手，没有发送分辨率命令。第二尺寸仅有适配函数测试，没有实机截图，不标记为通过。
7. **极端内容**：一般真实名称/数量已实机查看；极长商品名称、超大金额、真实商品黑色悬停层、支付所有状态仅组件模拟验证，需真实目录后补图。
8. **正式合入**：本轮沿用隔离测试链，没有覆盖正式 `survival`。下一轮先验收证据页中的详情/记录、每日奖励、肉鸽及单抽十连修复，再按当前正式分支差异合入；不得直接全量覆盖旧 HUD。

## 重现与继续位置

```powershell
node art/ui/development/remaining_ui_handoff_v1/prepare.cjs
node art/ui/development/remaining_ui_handoff_v1/verify.cjs
pwsh -NoProfile -File art/ui/development/remaining_ui_handoff_v1/deploy_test.ps1
```

部署目标固定为测试插件，正式 UI 受保护；不要运行旧的全量部署脚本。`baseline/` 保存修改前版本，`backups/` 保存每次部署前布局。最终包不含自动打开页面的探针。需继续检查时从 `evidence/index.html` 的对照与本节未解决项开始，不重新设计或重做已完成模块。
