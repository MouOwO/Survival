# 建造网格原生批次

只使用 `art/ui/sources/custom_game/survival_grid/reference_edge.png` 和
`reference_corner.png` 已有图像。生成器校验原文件 SHA-256，按原来线段 0.60、
角标 0.75 的透明度合成；不使用带灰色填充的 `reference_cell.png`。
除范围圆细线经过的环带外，所有单元格内部透明；每个 64 世界单位交点都有原角标，
不按视角抽稀角标。

```powershell
node tools/build_construction_grid.cjs
& tools/compile_construction_grid.ps1
```

源文件在本目录 `source`；编译器将源码同步到同一 addon 的 content 工程并生成
`particles/survival_grid/reference_grid_0.vpcf_c` 至 `_3.vpcf_c` 和对应纹理。
编译与资源检查日志写入 `output/construction_grid_compile`。

每次仅显示一个 world-Z sprite。CP0 为网格中心，CP3.x 为整体透明度，
附件使用 `PATTACH_WORLDORIGIN`。四张纹理的局部格相位依次为 `(0,0)`、
`(32,0)`、`(0,32)`、`(32,32)`；选择与中心的世界坐标模 64 相同的相位，
使格线固定在世界 64 倍数处。镜头变焦不需要改控制点。
Source2 的该 world-Z sprite 把纹理 U/V 分别映射到世界 Y/X；生成器内部交换
世界相位轴，纹理实际相位依次为 `(0,0)`、`(0,32)`、`(32,0)`、`(32,32)`。
客户端资源编号仍为 `phaseX + 2*phaseY`。这个对应关系已用 CP0 只移动 32X
的两张非对称相位截图对照核实，生成器与清单都显式保留这项约定。

可见圆半径 1280，前 75% 半径不衰减，外 25% 平滑羽化。
绿色范围边界也画在这一个 sprite 中，圆心及平面与白网格完全一致，
不再另用随地形起伏的 `range_display` 圆产生视觉错位。边界中心半径 1280，
颜色沿用 `.StaticGridRangeLine` 的 `#75e14b99`，线宽 2 世界单位、
抗锯齿宽度 2 世界单位，只覆盖半径 1278–1282 的细环带，没有大面积绿色填充。
环带周围 16 世界单位内仅对完全透明像素填入绿色 RGB（Alpha 仍为 0），
防止 DXT5 块压缩和 mip 过滤把细线混成灰白色。
范围圈不使用格相位偏移，不乘白网格羽化；四个相位的范围圆保持同一个圆心。
这只是建造预览提示，不更改实际技能范围、建造合法性或服务器校验。
由于该 Dota 编译器不支持非 2 次幂纹理，图像填充为 2048×2048，
每像素对应 2 世界单位；sprite 半径 2048，外围完全透明。
保持默认 UV：实机已证实 renderer 的 `.625` UV 缩放会重复图案，不能当作裁切。
线宽 4、角标 16 世界单位保留旧版每格约 32 屏幕像素时线宽 2、角标 8 的比例，
尺寸随世界透视缩放。关闭深度遮挡与雾着色，避免地面、模型和视角遮住网格。

纹理为 DXT5，含 mip，每张约 5.6 MB；四相位约 22.4 MB。
本机 BC7 编码器缺失 `bc7e.dll`，因此不采用 BC7。
四张相位图同时保存准确的圆心；简单共用一张图并平移 UV 会连同羽化圆心一起移动。
原生显示与取消由客户端网格生命周期管理，服务器预加载四个粒子依赖。

生成器内校验源指纹、环带以外格内全透明、四相位在实心区域的世界对齐，
并按度数检查各相位范围边界连续。内侧 75% 半径的白网格逐像素 SHA-256
与加圈前已验证源一致，绿色边界不会改动原线段或角标。
编译通过只证明资源有效；镜头距离、相位与实际帧耗的验收记录由实机测试另行保存。
