============================================================
一、长期代码规范
============================================================

1. 文件即模块
- 每个 Lua 文件是独立模块。
- 普通业务模块采用：
  local M = {}
  ...
  return M
- 单个 Lua 文件原则上不超过 300 行。
- 超过 300 行必须按职责拆分，不能仅压缩代码行规避限制。

2. 组合根
- addon_game_mode.lua 是唯一组合根。
- 只负责 require、初始化、Precache 和引擎入口适配。
- 禁止持续把业务逻辑堆入 addon_game_mode.lua。

3. 事件驱动
- 玩法模块通过 core/event_bus.lua 订阅、分发和请求。
- 禁止玩法模块之间直接调用业务函数。
- 服务端必须是玩法状态的唯一权威来源。

4. 变量与全局
- 业务变量必须使用 local。
- 禁止新增业务全局状态。
- 只允许 Dota 引擎要求的 Precache、Activate、Ability 类和 Modifier 类暴露在引擎适配层。
- keys 只能在当前回调参数作用域使用。

5. 实体操作
- 优先使用实体句柄 API。
- 不要通过单位名称进行不可靠的全局实体操作。
- 优先 EntFireByHandle，而不是按名称 DoEntFire。
- 所有实体必须先检查 nil 和 IsNull。

6. 客户端安全
- 客户端只提交意图和 ID。
- 客户端不能提交价格、等级、奖励、概率、最终属性和伤害结果。
- 资源消耗、VIP、前置条件、配方、技能候选、技能升级和奖励全部由服务端验证。

7. 数据配置
- 策划数据优先存入 CSV。
- CSV 通过 tools/csv_to_lua/build_configs.sh 生成 LuaConfig。
- 禁止直接修改 scripts/vscripts/config/generated 下的 Lua。
- 生成文件必须可重复生成。

8. 编码
- Lua、KV、XML、JS、CSS 使用 UTF-8。
- PowerShell 安装器优先纯 ASCII。
- PowerShell 禁止通过 Get-Content / Set-Content 拼接或重写含中文源码。
- 安装器应使用 Copy-Item 按原始字节复制完整文件。
- 已乱码文件不能通过“转为 UTF-8”修复，必须从干净文件恢复。

9. 交付方式
- 每次修改应给出完整更新包或明确 patch。
- 提供一个可直接执行的 PowerShell 命令。
- 自动备份现有文件。
- 给出日志和状态文件路径。
- 报告修改文件清单。
- 报告 Lua 语法检查、文件行数、require 检查、KV/XML/JS 检查。
- 必须区分：
  【源码确认】
  【静态检查通过】
  【待 Dota 2 实机验证】
- 没有经过 Dota 2 Workshop Tools 实机测试，不得宣称运行成功。

二、当前已经完成和确认的基础系统
============================================================

1. 建造者
- 初始英雄使用 Undying 作为建造者。
- Undying 只承担建造和经营功能。
- Undying 与祭坛召唤出的战斗英雄必须完全隔离。

2. 建造流程
- 初始只有“建造城墙”。
- 城墙完成后替换为“建造主城”。
- 主城完成后获得：
  - 建造箭塔
  - 建造英雄祭坛
- 金矿运行时代码可以保留，但当前默认建造阶段可关闭。
- 城墙整局只能建造一次。
- 城墙可选择、显示血条、有升级技能。
- 除城墙外的建筑默认不显示头顶血条。
- 主城拥有：
  - 升级主城
  - 训练伐木工
- 主城被摧毁时游戏失败。

3. 工人和资源
- 伐木工在主城附近生成，避免与主城碰撞。
- 自动攻击树木并增加木材。
- 木材、金币、人口和主城状态由服务端同步。
- 波次、等待时间、存活怪物等数据由服务端同步。
- 战争迷雾应关闭。

4. 防御塔
- 防御塔升级到 5 级后，从五个相同成本的转职方向中选择。
- 转职后可以继续升级。
- 转职和升级由服务端验证。

四、英雄技能池
============================================================

1. 基本规则
- 每名战斗英雄最多保存 10 个项目技能。
- 所有英雄共享一个公共技能池。
- 技能可以设置为某个英雄专属。
- 普通英雄初始获得 1 个专属技能。
- VIP 英雄初始获得 4 个明确配置的技能。
- VIP 初始技能不要在代码中随机写死，应从 hero_initial_skills.csv 读取。

2. 配置表
- hero_skill_definitions.csv
- hero_skill_pool_members.csv
- hero_exclusive_skills.csv
- hero_initial_skills.csv
- hero_skill_choice_rules.csv

3. 转职随机技能
- 击败二转 Boss 后由服务端生成 3 个随机技能候选。
- 同一轮候选不能重复。
- 满级技能不能进入候选。
- 已拥有技能再次被选择时升级。
- 未拥有技能且技能数小于 10 时新增。
- 已有 10 个技能时，只能提供可升级技能，不能给出无法选择的新技能。
- 服务端保存 choice_token 和 pending_choice。
- 客户端只能提交 choice_token 和 skill_id。
- 服务端必须验证该技能属于当前候选。

4. 推荐模块职责
- systems/hero_skill_system.lua
  保存、增加、升级、恢复和投影英雄技能。
- systems/hero_skill_pool_service.lua
  筛选公共池、专属池、转职范围、VIP 和随机权重。
- systems/hero_skill_choice_service.lua
  生成三选一、保存令牌、验证最终选择。
- ui/hero_skill_ui_service.lua
  只负责网络事件和候选快照。
- 不允许把上述职责重新合并到 addon_game_mode.lua。

5. 当前边界
- 服务端三选一核心已经设计并接入测试指令。
- 最终三选一 Panorama 面板仍属于待完成项。
- 原生 Dota 技能栏不适合稳定显示 10 个可见技能。
- 正式版本需要自定义技能面板；隐藏被动可继续由能力/Modifier 执行。

六、逻辑数值缩放与 UI
============================================================

用户实测：
- 英雄可直接设置的攻击力高值大约在 3200 附近出现限制。
- 英雄和武器总攻击接近 20～30 亿时出现上限或异常。

当前架构推测：
- 3200 附近可能与较窄的底层定点或整数表示有关。
- 20～30 亿接近有符号 32 位整数范围。
- 这是根据实测反推，不是 Valve 源码确认。

当前方案：
逻辑数值 : Dota 引擎数值 = 10 : 1

例如：
- UI 逻辑攻击 +1
- 引擎投影攻击 +0.1
- UI 逻辑攻击 10 亿
- 引擎投影约 1 亿

要求：
- 服务端保存逻辑值。
- 服务端将逻辑值缩放后投影到 Dota 实体。
- 客户端 UI 显示逻辑值。
- 客户端不得用引擎面板值反推权威逻辑值。

大数字格式：
- 9999 → 9999
- 10000 → 1万
- 102000 → 10.2万
- 100000000 → 1亿
- 1020000000 → 10.2亿

UI 策略：
- 不优先直接修改 Valve 官方 HUD 的内部攻击力节点。
- 使用项目自己的权威战斗属性面板覆盖显示。
- 原因是官方节点容易随更新变化，并且显示的是缩放后的引擎值。
- 武器、英雄属性、资源和商店价格共用统一大数字格式化工具。

当前尚未完全迁移到逻辑层的项目：
- 敌人生命
- 建筑生命
- 技能伤害
- 暴击伤害
- 吸血
- 护甲与减伤
- 最终伤害飘字

在继续扩大攻击数值前，应逐步把生命、伤害和减伤也迁入同一逻辑数值系统。

八、已发生过的严重问题，禁止回归
============================================================

1. PowerShell 中文乱码
- Windows PowerShell 5.1 把无 BOM UTF-8 按 ANSI 读取。
- 导致 XML、Lua 和 PowerShell 脚本中的中文变成乱码。
- 严重时破坏字符串引号并产生 unfinished string。
- 禁止用 PowerShell 读写方式修改中文源码。

2. XML 根节点
- Panorama XML 根 Panel 曾错误添加 id，Resource Compiler 不允许。
- 修改 XML 时必须先做严格 XML 解析检查。

3. Modifier 注册
曾出现：
- modifier_building_stationary unknown
- modifier_building_no_health_bar unknown
- modifier_enemy_wall_ai unknown
- modifier_lumberjack_ai unknown

必须在业务系统加载和实体创建前完成 LinkLuaModifier 和 Modifier 注册。

4. require 伪装成 module not found
Lua 文件内部语法损坏时，Dota 可能先显示：
module 'config/xxx' not found
但真正原因是后面的 unfinished string 或语法错误。
诊断时必须读取整条错误链。

5. UI 与服务器不同步
曾出现：
- Unknown custom nettable survival_ui_state
- Unknown custom nettable survival_ability_runtime
- UI Snapshot service nil
- 商店仍打开原生 Dota 商店
- shopshow 不工作
- 服务端没有推送资源和波次数据

新增 NetTable 时必须同步更新 custom_net_tables.txt，并确保服务初始化顺序正确。

# 六、OpenAI API Key 注意事项

QClaw 应使用你自己的 OpenAI API Key。

不要把 API Key 写入：
- 本提示词；
- QClaw 知识库文件；
- Git 仓库；
- Lua、JS、PowerShell 源码；
- 上传给模型的日志；
- zip 更新包；
- README；
- 截图。

推荐在运行 QClaw 的机器上使用环境变量：

```text
OPENAI_API_KEY
```

Windows 可在用户环境变量中设置，或者使用 QClaw 自己的秘密凭据配置。

知识库中只写：

```text
OpenAI provider is enabled.
Read the credential from OPENAI_API_KEY.
Never print or persist the key.
```

不要记录真实 Key。
